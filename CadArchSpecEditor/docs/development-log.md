## 2026-07-29 — AutoCAD 2022/2026 宿主技术验证

完成：

- 建立共享宿主消息协议和运行时信息 DTO；
- 建立 AutoCAD 2022（`.NET Framework 4.8`）宿主；
- 建立 AutoCAD 2026（`.NET 8`）宿主；
- 建立 `JZSM` 命令和可停靠 `PaletteSet`；
- 使用 WinForms `WebView2` 承载同一套 React 静态资源；
- 完成前端 `editor.ready` 与 CAD `host.ready` 双向握手；
- 增加 WebView2 进程异常隔离、用户数据目录和诊断日志；
- 增加 WebView2 原生加载器的显式解析，避免 AutoCAD 插件加载上下文找不到
  `runtimes\win-x64\native\WebView2Loader.dll`。

兼容性结论：

- AutoCAD 2022–2024 使用 `.NET Framework 4.8` 宿主；
- AutoCAD 2025–2026 使用 `.NET 8` 宿主；
- 两套宿主共享 `netstandard2.0` 领域、应用、规则、布局、规范和桥接程序集；
- AutoCAD 托管插件必须使用 `NETLOAD`，不能使用只面向 ARX/LSP 等文件的
  `APPLOAD` 来加载当前 DLL。

实机验证：

- 本机 AutoCAD 2026 SDK：
  `D:\Program Files\Autodesk\AutoCAD 2026`；
- Release 全解决方案构建：0 警告、0 错误；
- `NETLOAD` 成功加载 `CadArchSpec.Host.AutoCAD2026.dll`；
- `JZSM` 成功显示“建筑设计说明助手”；
- React 页面显示“AutoCAD 宿主已连接”；
- 关闭面板后再次运行 `JZSM`，页面和宿主握手仍然正常；
- 测试期间 AutoCAD 2026 未发生崩溃。

验证过程中发现并解决：

1. 最初使用 WPF `WebView2CompositionControl` 配合 `PaletteSet.AddVisual` 时，
   AutoCAD 2026 发生原生崩溃；宿主改为 AutoCAD 更稳定的 WinForms
   `PaletteSet.Add` 容器。
2. 改用 WinForms 后 AutoCAD 不再崩溃，但首次实机加载报
   `WebView2Loader.dll` 找不到；AutoCAD 2026 宿主增加
   `NativeLibrary.SetDllImportResolver`，AutoCAD 2022 宿主在创建控件前显式
   `LoadLibrary`，两者都从插件自己的 `runtimes` 目录加载原生组件。

下一步建议：

开始阶段1编辑器壳层：左侧章节树、中间结构化字段编辑器、右侧规范依据与审查结果，
并先实现项目基本信息与一个示范章节的保存/恢复闭环。
