# 规则与公式

## 规则包

规则包是插件之外的版本化 JSON 文件，必须包含管辖地区、版本、状态、生效日期、规则列表和可选签名。项目以后应锁定已使用的规则包版本，不能在后台静默改变已报审项目结论。

规则引擎允许的受控检查类型：

```text
requiredSection
requiredField
fieldConsistency
standardStatus
tableRequired
formula
dateApplicability
```

不允许脚本、自定义 C#、JavaScript、反射调用或任意 CAD 命令。

`rules/CN/common/package.json` 是国家建筑专业基础完整性规则的第一批试运行包，
状态为 `Draft`。它只检查章节、关键字段是否存在并已确认，不计算防火分类、
无障碍指标或其他专业阈值，也不能代替注册建筑师和审查机构的结论。

规则结果包含规则包版本、核实日期、适用边界、严重程度、字段或章节定位信息。
编辑器可以跳到对应位置，并将本次结果导出为 JSON 报告。项目数据变化后旧结果
立即失效，必须重新运行预审。

每次预审结果都会作为项目审查档案写入工作区，最多保留最近 100 次。档案保存
规则包标识与版本、执行和核实时间、问题证据、定位信息及项目数据指纹。数据指纹
不包含保存时间和审查档案本身，因此新增记录不会使刚生成的报告失效；项目字段、
条件或章节内容变化时，历史报告会明确标记为“基于旧版本数据”。

报告可导出含档案信息的 JSON，也可按 A4 版式调用系统打印功能保存为 PDF。
每条问题可以记录待处理、处理中、已解决、接受风险或不适用状态，并保存责任人、
处理意见、复核人和更新时间。接受风险不计入已解决数量，不适用和接受风险均应
填写原因并完成复核。

报告最少 5 页：封面与结论、项目与审查范围、问题明细、问题处理记录、规则索引
与使用声明。问题明细每页最多 4 条并自动续页，详细页面定义见
`docs/review-report-pages.md`。

预审历史允许选择任意两次记录进行对比。问题使用规则编号与目标字段/章节组成的
稳定键匹配，不使用每次运行随机生成的 IssueId。对比结果分为新增、持续和本次
不再检出三类；“本次不再检出”不自动等同于人工已解决或专业审查通过。

项目可以保存设计单位、项目负责人、编制人、校对人、审核人和默认报告编号。
运行预审时把当时的签发信息复制到审查档案，之后修改项目默认人员不会改写旧报告。
报告编号留空时自动生成 `BPP-JZYS-日期-短编号`。签发信息不参与设计数据指纹，
因此只修改人员不会错误地把预审结论标记成基于旧版设计数据。

广西、四川目录仍只是“未加载地方规则”的占位提示，不含地方审查结论。

## 公式

公式解析器允许：

- 四则运算和括号；
- 字段引用；
- 比较运算；
- `SUM`、`MIN`、`MAX`、`ROUND`、`IF`、`ABS`、`COUNT`。

未知字段、未知函数、非法字符和除零都会显式失败。公式不执行任意代码。
