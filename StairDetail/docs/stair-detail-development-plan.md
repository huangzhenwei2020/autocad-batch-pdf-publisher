# 万落建筑“一键楼梯大样”开发计划

> 文档版本：V0.1  
> 编制日期：2026-07-31  
> 目标平台：AutoCAD + 天正建筑  
> 首版目标：从楼梯对象、已有平面图或参数输入，快速生成可编辑、可更新、符合项目制图标准的楼梯平面大样和剖面大样。

当前首测环境已确定为 AutoCAD 2022 + 天正建筑 T20 V9。AutoCAD 2024 暂不作为首轮联调环境。

## 1. 产品目标

“一键楼梯大样”不是简单的线条复制工具，而是一套“识别输入 -> 参数校核 -> 大样生成 -> 标注出图 -> 后续更新”的参数化制图工具。

首版重点解决以下问题：

1. 重复绘制梯段、踏步、平台、栏杆、尺寸和标高效率低。
2. 平面图、剖面图之间的数据容易不一致。
3. 不同设计人员的图层、文字、尺寸和索引表达不统一。
4. 修改层高、踏步数或梯段宽度后，需要大量手工重画。
5. 天正对象、普通 CAD 线条和外部参照等输入来源不统一。

## 2. 首版范围

### 2.1 MVP 支持内容

- 楼梯类型：双跑平行楼梯（含有梯井、无梯井两种）。
- 输入方式：
  - 选择天正楼梯对象，自动读取可获取的参数。
  - 选择普通 CAD 楼梯平面线条，辅助识别轮廓和踏步。
  - 无法识别时，通过参数面板快速录入。
- 输出图样：
  - 底层、中间层、顶层楼梯平面大样。
  - 一个纵向楼梯剖面大样。
  - 踏步、平台、梯梁、楼板、栏杆扶手和梯井表达。
  - 尺寸、标高、步数、上下方向、剖切符号和必要文字说明。
- 编辑能力：双击或执行“编辑楼梯大样”命令，修改参数并整体重生成。
- 样式能力：图层、颜色、线型、文字、尺寸、比例和精度可按项目模板配置。
- 结果兼容：默认输出原生 AutoCAD 图元和块，不依赖天正也能显示、打印和编辑。

### 2.2 首版暂不支持

- 剪刀梯、三跑楼梯、弧形楼梯、旋转楼梯和室外复杂台阶。
- 自动完成所有节点详图、防水构造和钢筋构造。
- 从任意质量的二维图纸完全无交互地识别楼梯。
- 自动替代建筑师进行规范判定或消防审查。
- Revit、国产 CAD 和非 Windows 平台。

这些内容在核心数据模型稳定后分期扩展。

## 3. 核心用户流程

### 3.1 智能生成

1. 用户执行命令 `WLSTAIR`。
2. 选择天正楼梯对象或框选已有楼梯平面图。
3. 插件识别楼梯方向、轮廓、梯段宽度、平台、踏步数和层高等信息。
4. 无法确定的字段在参数面板中高亮，用户补充或确认。
5. 系统实时校核参数，并预览平面和剖面结果。
6. 用户指定插入点、出图比例和样式模板。
7. 系统一次生成整组大样，并记录关联参数。

### 3.2 参数生成

当原图不存在或无法可靠识别时，用户直接输入：楼层标高、层高、梯段宽度、梯井宽度、平台深度、踏步数量、踏步宽高、梯板厚度和栏杆参数，系统生成大样。

### 3.3 修改更新

1. 用户选中已生成的大样，执行 `WLSTAIREDIT`。
2. 修改层高、步数、宽度或样式。
3. 系统保留插入位置和人工允许保留的附加标注，重生成受控图元。
4. 更新平面、剖面、尺寸、标高和说明，避免图样间数据不一致。

## 4. 功能模块

### 4.1 输入识别模块

- 天正对象识别：根据对象运行时类型、扩展数据和可访问属性读取参数。
- 普通图元识别：识别直线、多段线、块、文字、尺寸和踏步重复线。
- 几何推断：通过平行线、等间距线、封闭轮廓和上下箭头推断楼梯结构。
- 识别置信度：每个参数标记为“已读取、已推断、需确认”。
- 安全降级：不修改或炸开源对象；必要时在内存或临时数据库中对副本分析。

天正兼容不能只依赖某一个私有接口。建议采用三级策略：

1. 优先读取天正对象可公开访问的属性。
2. 无法读取时，从对象显示几何或副本分解结果提取信息。
3. 仍无法确认时进入参数录入，不阻断用户出图。

### 4.2 楼梯参数模型

核心模型 `StairDefinition` 至少包含：

- 楼梯类型、楼梯方向和基准点。
- 起止楼层、楼层标高、结构层高和建筑完成面高差。
- 梯段净宽、梯井宽、平台宽度和平台深度。
- 每跑踏步数、总步数、踏步宽度和踏步高度。
- 梯板、平台板、楼板、梯梁的厚度和相对位置。
- 面层厚度、栏杆高度、扶手偏移和临空侧设置。
- 平面比例、剖面比例、标注精度和样式模板编号。
- 输入来源、识别置信度、数据版本和唯一 ID。

模型必须与 CAD API 解耦，以便独立进行单元测试，并支持后续增加其他楼梯类型和 CAD 平台。

### 4.3 参数计算与规则校核

- 根据层高和候选踏步高度推荐整数步数。
- 自动分配两跑步数，并处理奇偶步数差异。
- 计算踏步宽度、梯段水平长度、平台位置和剖面控制点。
- 检查净宽、平台尺寸、踏步宽高、栏杆和净空等规则。
- 区分“无法生成”的几何错误和“允许生成但需提示”的规范风险。
- 所有规则使用可配置规则表，并显示规则来源、版本和适用条件。

规范条文不能直接散落硬编码在绘图逻辑中。正式发布前应由建筑专业负责人确认适用的国家、地方、住宅、公共建筑及消防规则；软件提供辅助校核，不代替专业审查。

### 4.4 几何生成模块

- 在独立二维坐标系中计算楼梯平面和剖面几何。
- 生成楼梯轮廓、踏步、平台、楼板、梯梁、栏杆和折断线。
- 正确处理底层、中间层、顶层以及剖切线上下的可见性。
- 统一处理线宽、遮挡、虚实线、图形比例和注释比例。
- 先生成平台无关的几何描述，再由 CAD 渲染层创建图元。

### 4.5 标注与出图模块

- 自动布置总尺寸、分段尺寸、梯段宽度、平台尺寸和梯井尺寸。
- 自动生成楼层标高、平台标高、踏步宽高和步数说明。
- 自动绘制上下方向箭头、剖切索引和图名比例。
- 支持文字避让、尺寸线分层和左右镜像。
- 支持按项目模板映射图层、文字样式、尺寸样式、线型和打印颜色。
- 缺少模板资源时自动创建带 `WL_` 前缀的安全默认样式，避免污染或覆盖用户同名样式。

### 4.6 关联与更新模块

- 每组大样分配唯一 ID。
- 使用扩展字典或 XData 保存参数版本、图元角色和关联 ID。
- 参数主体建议保存为版本化 JSON，同时保留必要的快速索引字段。
- 所有生成图元归属于同一逻辑对象，可整体选中、检查和更新。
- 更新采用事务：新结果成功生成后再替换旧结果，失败时完整回滚。
- MVP 先提供手动更新；源平面自动联动可在稳定后增加。

## 5. 技术架构建议

### 5.1 开发技术

- 语言：C#。
- CAD 接口：AutoCAD .NET API；只有遇到 .NET API 无法解决的问题时再引入 ObjectARX/C++。
- UI：WPF 参数面板，界面与计算核心隔离。
- 配置：JSON，包含制图模板、规则集和用户默认值。
- 日志：本地结构化日志，默认不记录完整图纸内容和项目敏感信息。
- 测试：纯 C# 单元测试 + AutoCAD 内集成测试 + 典型 DWG 回归样本。

### 5.2 分层结构

```text
WL.Stair.Core
  参数模型 / 计算 / 规则校核 / 几何描述

WL.Stair.Cad
  AutoCAD 命令 / 事务 / 图元读写 / 选择与预览

WL.Stair.TArch
  天正对象识别 / 属性映射 / 降级提取

WL.Stair.Rendering
  平面与剖面渲染 / 标注排布 / 样式映射

WL.Stair.UI
  WPF 参数面板 / 模板设置 / 错误与风险提示

WL.Stair.Tests
  计算测试 / 几何快照 / DWG 回归 / 版本兼容测试
```

### 5.3 版本兼容策略

AutoCAD 不同大版本可能使用不同的 .NET 运行时和程序集，因此不建议用一个未经区分的 DLL 覆盖全部版本。

- 核心计算库尽量不引用 AutoCAD 程序集。
- 按 AutoCAD 大版本或运行时家族构建宿主适配 DLL。
- 天正适配器按“天正版本 + AutoCAD 版本”建立测试矩阵。
- 使用 `.bundle` 结构安装，通过 `PackageContents.xml` 选择正确组件。
- 启动时检测实际版本；未验证组合只启用安全功能并提示兼容状态。
- 第一阶段开始时冻结首发版本矩阵，不在开发中无限追逐所有历史版本。

当前第一阶段先支持 AutoCAD 2022 + 天正建筑 T20 V9，完成稳定闭环后再扩展第二个 AutoCAD 大版本。后续版本仍应通过目标用户调研和真实安装环境确认后写入兼容清单。

## 6. 分阶段开发计划

以下排期按“2 名开发 + 1 名兼职建筑专业负责人/测试”的小团队估算，共 10 周。

### 阶段 0：需求和样图冻结（第 1 周）

- 收集 20至30 份真实双跑楼梯大样和对应楼梯平面图。
- 确认底层、中间层、顶层、剖面及标注的标准画法。
- 确定首发 AutoCAD/天正版本、图框比例和项目模板。
- 建立参数字典、输出清单和 5 组验收基准样图。
- 明确哪些规范问题阻止生成，哪些只给出风险提示。

交付物：需求规格 V1、兼容矩阵 V1、标准样图、验收用例。

### 阶段 1：计算核心与原型（第 2至3 周）

- 建立 `StairDefinition` 数据模型。
- 完成层高、步数、踏步宽高、平台和剖面控制点计算。
- 完成双跑楼梯的平面、剖面几何描述。
- 建立规则校核框架和首批单元测试。
- 用命令行或简单测试界面输出验证数据，不急于完善 UI。

交付物：可测试的纯计算核心、计算测试报告、几何原型。

### 阶段 2：CAD 出图 MVP（第 4至5 周）

- 建立 AutoCAD 插件工程、命令入口和事务管理。
- 参数输入生成底层、中间层、顶层平面及剖面。
- 创建图层、线型、文字、尺寸、标高和方向箭头。
- 完成插入点、比例、镜像、撤销和失败回滚。
- 完成 `.bundle` 调试安装包。

交付物：仅靠参数即可稳定生成大样的内部试用版。

### 阶段 3：天正兼容与图形识别（第 6至7 周）

- 采集首发版本中的天正楼梯对象样本。
- 实现天正属性读取和对象类型映射。
- 实现对普通 CAD 轮廓、踏步线和文字的辅助识别。
- 增加识别置信度、待确认字段和参数录入兜底。
- 验证源图不被修改，代理对象和外部参照场景能安全退出。

交付物：可从目标天正版本及标准二维平面获取大部分参数的 Beta 版。

### 阶段 4：关联编辑与模板化（第 8 周）

- 保存楼梯参数和生成图元的关联关系。
- 完成编辑、重生成、复制后重新编号和数据升级。
- 完成项目制图模板、默认值和规则集配置。
- 处理人工补充图元的保留边界，避免更新时误删用户内容。

交付物：可反复修改更新、可适配不同项目标准的 Beta 2。

### 阶段 5：兼容测试与交付（第 9至10 周）

- 在兼容矩阵所有组合中执行安装、生成、编辑、保存和重开测试。
- 使用验收 DWG 做图形快照和人工审图对比。
- 测试中文路径、大坐标、毫米单位、不同绘图比例和缺失字体/线型。
- 测试撤销、重做、崩溃恢复、只读图纸和异常对象。
- 优化生成速度、错误提示、日志和安装升级流程。
- 编写用户手册、已知限制和问题反馈模板。

交付物：V1.0 安装包、兼容清单、测试报告、使用说明和演示样图。

## 7. 验收标准

### 7.1 功能验收

- 5 组标准双跑楼梯均能生成底层、中间层、顶层平面和剖面。
- 层高、踏步数、梯段宽度和平台深度修改后，相关图形和标注同步更新。
- 天正对象读取失败时能进入参数补录，不崩溃、不破坏源对象。
- 生成结果在未安装天正的目标 AutoCAD 中仍能显示和打印。
- 一次 `UNDO` 能撤销一次完整生成或更新操作。

### 7.2 准确性验收

- 总高度、水平长度、踏步数量及主要标注与输入参数一致。
- 图元端点闭合和尺寸误差控制在 CAD 建模容差内。
- 平面、剖面中的步数、方向、平台标高和楼层标高互相一致。
- 规则提示与建筑专业负责人确认的验收表一致。

### 7.3 性能与稳定性验收

- 常规楼梯大样从确认参数到生成完成目标不超过 2 秒。
- 连续生成或更新 100 次无明显资源泄漏和性能恶化。
- 无效选择、锁定图层、缺失样式和不支持对象均有明确提示并安全退出。
- 在所有首发兼容组合中完成不少于 30 份真实图纸的回归测试。

## 8. 主要风险及对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 天正对象接口随版本变化 | 自动读取失败 | 独立适配层、样本库、三级降级和参数兜底 |
| “一键”输入信息不足 | 自动结果不可靠 | 置信度机制，只要求用户确认不确定参数 |
| 楼梯画法和项目标准差异大 | 输出难以直接交付 | 制图模板化，首版冻结一种标准表达 |
| 规范条文适用条件复杂 | 错误提示或错误拦截 | 规则配置化、标注来源版本、专业负责人审核 |
| 自动标注碰撞 | 图面质量不稳定 | 先做固定布局规则，再增加碰撞检测和拖拽修正 |
| 更新时删除人工内容 | 用户数据损失 | 只管理带自身 ID 的图元，替换前事务校验和回滚 |
| AutoCAD 版本运行时差异 | DLL 无法加载 | 核心解耦、分版本构建、安装时匹配宿主 |

## 9. V1.0 之后的路线

### V1.1

- 单跑、L 形和三跑楼梯。
- 更完善的标注碰撞检测和局部拖拽。
- 批量生成标准层楼梯大样。
- 从项目已有样图提取图层和标注风格。

### V1.5

- 剪刀梯及复杂防烟楼梯间。
- 平面源图变化检测和一键同步。
- 楼梯详图、栏杆节点和材料做法库。
- 多地区、多建筑类型规则包。

### V2.0

- 支持更多 CAD 平台。
- 图纸级楼梯批量识别和一致性检查。
- 与 BIM 模型或项目参数表进行数据交换。

## 10. 立即启动清单

1. 确定首发支持的 AutoCAD 与天正版本组合。
2. 选定一套公司标准楼梯大样作为唯一 MVP 输出基准。
3. 收集 20至30 份脱敏 DWG，并按楼梯类型和版本分类。
4. 由建筑专业负责人整理必检参数、提示语和规则来源。
5. 先完成“参数输入 -> 双跑楼梯平面和剖面”的技术原型。
6. 原型稳定后再接入天正对象识别，避免识别问题阻塞出图主链路。

## 11. 首个迭代建议

第一个两周迭代只验证一件事：输入层高、梯段宽度、平台深度、梯井宽度和每跑步数后，能否生成一套与基准样图一致的双跑楼梯平面与剖面。

首迭代演示应包含：

- 一组正常参数生成。
- 修改层高后自动重新计算并更新。
- 不合理踏步参数的风险提示。
- 左右镜像和插入点选择。
- 一次撤销完整删除本次生成结果。

如果这个闭环稳定，再进入天正识别、复杂楼梯和更多规范规则，整体开发风险最低。
