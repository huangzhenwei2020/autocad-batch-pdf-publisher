# 建筑模型与三维软件互通开发计划

## 已实现的基础

- 平面 CAD 表达由参数化墙、门窗和现有投影器生成；三维体量由同一语义模型生成。
- 正交墙角的三维顶面与底面使用一致的斜接归属；平面预览补齐带门窗墙及复制墙的相交角。
- 三维视口提供线框、实体、按构件着色、定向光照四种实时显示模式。这些是视口模式，不是材质；当前光照没有投影阴影、环境光遮蔽或 PBR。
- 2026-09-30 第一阶段已实现：整栋/当前楼层 GLB 导出，保留楼层和构件身份、标准层实例、米制坐标、法线及基础色；通过 Blender 5.2.1 导入/重新导出验证。测试与限制见[第一阶段验收记录](reviews/建筑模型GLB导出验收-2026-09-30.md)。下一阶段为门窗视觉资产导入。

## 数据边界

保留 `model.json` 中墙、门窗、楼板、楼层等语义与尺寸为唯一可编辑建筑数据。外部三维模型只作为可替换的视觉资产，不反向覆盖墙洞尺寸、门窗位置或二维制图线。每个门窗类型可以引用一份视觉资产与一个放置规则；同类型实例共享网格，逐实例只存变换。若资产缺失或损坏，回退到当前程序化门窗体量，平面图及 CAD 出图照常工作。

平面视图始终从语义墙和洞口生成 CAD 线条、门扇弧线、窗线及定位信息，不把三维网格投影成二维图纸。三维视图优先使用匹配的视觉资产；没有资产时使用程序化门窗。三维资产允许与平面符号细节不同，但洞口宽高、窗台高、朝向与宿主墙必须一致。

## 分阶段实施

1. **网格导出**：从已验证的三维体量导出整栋或选中楼层的 `.glb`。按楼层和构件保留节点层级及稳定 ID；将内部毫米、Z 向上坐标统一换算为 glTF 的米、Y 向上。导出只读快照，不改 `model.json`。用 Blender 导入检查层高、门窗洞、法线和斜接底面，做往返几何测试。
2. **外部构件资产导入**：先支持单个门/窗 `.glb` 资源。导入时校验文件、网格尺寸、外部纹理路径及三角形数量；提供轴向、单位、原点、正反面、宽高适配和预览。资产复制到项目内受控目录并用哈希关联门窗类型；替换资产不改变平面图。
3. **材质系统**：在语义构件和导入资产上引入独立的材质引用。先实现基础色、金属度、粗糙度及贴图，再接法线、透明、双面等需要的选项。视口模式扩展为材质预览；其 GPU 着色器、纹理缓存与现有实体/线框模式分开，不能把当前“着色”冒充真实材质。
4. **渲染与其他格式**：有稳定材质和灯光后再提供带阴影的渲染预览。评估其他软件格式时先做格式适配器，不让导入器直接修改参数化墙或二维投影逻辑。

## SketchUp 与 3ds Max 互通扩展

- 当前已实现的格式仍为 GLB；下面是待实施的适配器，不代表已支持原生 SKP/MAX 文件。
- SketchUp：优先增加 COLLADA `.dae` 导出，使用软件自带导入器。保留楼层分组和构件短编号，明确单位与轴向；完成目标版本实机导入后再开放入口。
- 3ds Max：优先增加 `.obj + .mtl` 导出，覆盖几何、构件分组、法线和基础材质；OBJ 没有可靠的单位与楼层场景层级，需要明确导入单位并附带元数据。后续评估 FBX 对层级和材质的支持，不用改扩展名伪造 FBX。
- 各格式复用优化后的同一份网格：只合并同一构件、同一法线、同一平面的墙面切片，保留门窗洞口和墙角归属，不保留其他墙洞口产生的全局网格线。
- GLB 必须使用三角网格，因此少量三角剖分对角线是格式表达，不等于墙体破损。不能为了减少线条跨过洞口封面，或把不同墙合成一个不可追溯的对象。
- 先验收手动导入，再增加“导出后打开”目标软件选项。检测安装路径、导入脚本与软件版本，不关闭用户已有场景、不覆盖未保存工程。
- 验收：原尺寸、楼层及标准层完整、门窗洞口贯通、法线正确、无无关墙切分、编号一致、材质对应；每种格式必须在对应软件独立验证。

参考：[SketchUp 支持的交换格式](https://help.sketchup.com/en/sketchup/using-sketchup-data-other-modeling-programs-or-tools)、[3ds Max 几何交换格式](https://help.autodesk.com/cloudhelp/2025/ENU/3DSMax-Interoperability/files/GUID-566E59EE-8221-4AC6-824B-5062C5AE0B32.htm)。

## Blender 式视口分层（显示规则）

视口入口保持紧凑、位置固定，切换模式不改变建筑模型。当前线框、实体、构件着色、定向光照都属于工作视口；后续在同一入口增加设置弹层，提供统一色/构件色、轮廓、背景及光照强度等选项。只有实现 PBR 材质与纹理缓存后才开放“材质预览”；只有加入场景灯光、阴影和相应渲染管线后才开放“渲染预览”。材质预览与渲染预览不能仅换按钮名称或复用当前定向光着色器。各模式共享选择、相机、裁剪和构件可见性状态。

## 验收与性能

- 导出后在 Blender 打开，楼层数量、标高、洞口和构件身份对应原模型；毫米到米的换算误差在既定几何容差内。
- 导入同一门窗资产的多个实例时共享 GPU 网格和纹理；改变类型资产后实例更新，撤销与保存重开仍正确。
- 删除/移动门窗或切换标准层来源时，三维实例、二维符号和 CAD 出图各自更新，不出现悬空引用。
- 大模型异步解析、网格构建和纹理上传；切换视口模式不重新计算建筑语义几何。以实测帧率、内存和首次显示时间作为放行条件。
- 外部文件设路径、体积、三角形数量和纹理尺寸上限；失败应清晰提示并保持原模型可用。

格式选择依据：[Khronos glTF 2.0 规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html)定义米和 Y 向上坐标及金属/粗糙度材质，[Blender 官方手册](https://docs.blender.org/manual/en/5.3/addons/scene_gltf2.html)说明 `.glb` / `.gltf` 导入导出。导入导出实现时需按规范处理坐标、法线、材质及外部资源，而不能只改文件扩展名。
