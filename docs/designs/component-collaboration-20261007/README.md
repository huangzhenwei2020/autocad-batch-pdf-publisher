## 2. 样例数据与图面一致性

- 图库选中 M1525，整体洞口 1500 × 2500 mm，带固定上亮、两侧外框合页、左右两扇。此图的外部来源/可变能力是未来设计状态，不代表当前资源已经可放置。
- 配对编辑选中 **左门扇**，二维组和三维节点均为 `leaf_L`，实际左侧部件在模型中高亮。已纠正旧稿“右门扇”误写。
- 配对图门扇示例净宽 700、净高 2100；整体 1500 × 2500 保持不变。固定面宽 50 与门扇厚度 40 是不同方向的尺寸，不混用。净尺寸仅是本设计样例；实现必须由实际型材、缝隙、上亮和分格解算，不能硬编码 700/2100。
- 柜体 F-G01 示例宽/深/高为 1200/600/2200，左柜门开启 45°，右柜门及抽屉关闭。实际应用来自作者声明的有效范围，不默认所有柜体都可伸缩。
- 家具稿当前“开闭”页的宽/深/高作为只读摘要，因此显示锁；切换“尺寸”页后，可变资源在作者允许范围内编辑，固定规格资源才保持锁。不要把图中的锁理解成所有家具永久不可改尺寸。
- 门窗卡片造型、家具场景及部件小图是设计示意，不是 CAD/Max 实机导出资产，也不用于几何或性能验收。

## 3. 图库选型窗口

结构：左分类，中缩略图，右预览/参数，固定底栏。门、窗分开，家具等类别共用入口；未实装类别不发布空列表。

| 区域 | 控件/字段 | 行为 |
|---|---|---|
| 顶栏 | 搜索；来源；网格/列表图标；导入；新建 | 搜索按编号/名称/型号；来源有项目/内置/公共；管理命令可按权限收起 |
| 分类 | 门/窗及类型；家具；洁具/设备 | MM 默认门窗范围；CAD 功能区只有“图库”一个入口 |
| 资源项 | 实际缩略图、编号/名称/尺寸、参数/外部来源、固定/可变 | 悬停预览；单击选择；双击按已校验参数进入放置，不绕过错误 |
| 预览 | 平面/立面/三维页签 | 二维使用 CAD/参数真实符号；三维使用真实几何，不投影三角网格代替平面 |
| 部件条 | 固定框、左右扇、上亮、门槛/五金实际形状 | 普通用户悬停/点击看对应高亮；底层绑定只在配对编辑修改 |
| 门窗字段 | 编号、洞口宽高、窗台、门槛、平面角度、三维开启 | 合法值显示范围；不适用字段隐藏；参数门窗保留原行为 |
| 家具字段 | 型号/规格、宽深高、安装高、前向 | 没有门槛/窗台字段；固定资源选规格，可变资源按规则编辑 |
| 来源/能力 | 参数门窗/外部构件、支持开闭、固定/可变、缺失状态 | 展示能力，不靠颜色猜；普通用户不填文件路径和矩阵 |
| 底栏 | 取消；放置 | 固定位置；校验失败内联提示，保留输入；Esc 取消当前预览 |

图面没有展开全部字段：实现须保留窗台、资源范围/状态、收藏/最近和来源过滤，不能为了机械照图删除已有功能。字段补全时使用可滚动右栏，不压扁控件。

“编辑配对”进入作者工作区；“另存为外部构件”保留原参数资源。给项目换外形另用“替换三维”操作，预览影响范围，不修改宿主墙/编号/尺寸。

## 4. 配对编辑工作区

顶部步骤为基本信息、二维符号、三维模型、部件与尺寸、校验，底部取消/保存草稿/发布。步骤只是导航，未通过验证不开放发布。

### 部件必须画出真实样子

- 列表小图来自同一 PartId 的实际关闭基准几何：框是框，门扇是有框/玻璃/把手的一扇，抽屉是盒体，不用通用小方块代替。
- 选中后在二维组、三维部件、左侧放大和右侧规则图同步标出；不依赖用户识别英文节点名。
- “只看此部件”使用统一隔离图标；眼睛控制可见性；悬停图标提供名称。多选动作组可以包含扇框、玻璃和五金多个网格。
- 图形化规则图来自当前几何，固定边灰色、可伸长区青色，同时加边界线/固定尺寸标签；合页轴黄色并标文字，轨道画箭头与行程。不能只靠色彩表达。
- 部件图无几何时显示明确空状态和选择来源操作，不显示一个假门扇缩略图。

### 参数与交互

| 页面 | 字段/动作 | 约束 |
|---|---|---|
| 二维符号 | 基点、宽高、X/Y 前向、编号锚点、图元分组 | CAD 按 mm、1:1；无符号可先保存草稿，不能发布成完整配对 |
| 三维模型 | 来源、单位/轴向、前后面、闭合姿态 | 导入校验，禁止自动运行附带脚本；只有真实节点可选 |
| 部件绑定 | 名称、角色、二维组、三维选取、运动组 | 内部稳定 PartId；重导入有差异/失联提示，不只按名字猜 |
| 尺寸 | 跟随/锚定、固定端、可变区、厚度、净分格、最小/最大 | 拖动区间显示实际形状；可直接输入 mm；尺寸未声明则固定 |
| 开闭 | 固定/转动/平移、合页边/轴点、内外方向、角度/行程 | 先改关闭尺寸再求轴；平开两侧外框合页；玻璃/把手刚体跟扇 |
| 测试 | 闭合/15/30/45/90、自定义输入；宽高边界测试 | 作者测试姿态不自动变成新放置默认姿态；回到闭合无累积误差 |
| 校验 | 尺寸/单位/来源/部件/缺失/动作/二维状态 | 分项列问题和定位按钮；错误阻止发布但不阻止保存草稿 |

右栏主要使用“尺寸/开闭”分段控件，每页显示对应设置。视觉稿同时露出精简的开角测试，用于与模型核对；不要展开整套高级规则而挤掉预览。

开闭合页拾取在模型上反馈轴点和方向；局部坐标收在高级区域。选择固定边/伸长区时能点几何，不要求用户算矩阵。活动扇随鼠标测试只变换缓存，完整尺寸解算在规则改变后执行。

## 5. 家具实例编辑

在现有模型窗口使用右侧位置/尺寸/开闭页签，不给每次改柜门都弹一个复杂作者窗口。项目浏览器家具独立分类，左侧可展开部件形状；单选一扇可只调整该扇。

- 位置：落点、安装高、旋转、离墙、靠墙/居中；家具不切墙。鼠标放置预览有基点/正面，左键提交，Esc 取消未提交动作。
- 尺寸：只显示作者允许的参数和规格，板厚/五金等固定约束保持；各字段有范围与具体错误。
- 开闭：平开角度或推拉/抽屉行程，关闭全部，独立/联动；三维开关与二维表达分离。
- 夹点沿用较大屏幕尺寸和命中热区，拖动松开提交；数值输入用应用提交，避免用户刚输入第一位就意外保存。
- 应用范围默认当前这一件，同类型需明确；标准层另明确仅本层/共用楼层。一次应用一次撤销；Esc 不替代 Ctrl+Z。
- 开闭与尺寸只更新相关实例/部件；动态操作不解码整份 GLB 或重算整栋。

首期对象：固定椅和规则柜体，后续桌/床/沙发、洁具、设备。柜门转动和抽屉平移复用部件运动，软包沙发不整体任意拉伸。

## 6. 布局、大小窗口和状态规格

图是约 1600 × 1000 的栅格示意，**不是通过测试的响应式界面**。实现应保持原稿层级、分隔线、图标和部件图，同时按下列布局适配，不等比缩放整个窗口字体。

| 项目 | 实现规格 |
|---|---|
| 常规输入/按钮 | 36 DIP；图标工具 32–36；表单行至少 42；正文 14，字段标题 14，紧凑段标题 16 |
| 形状与留白 | 普通半径 4、上限 8；外边距 12、区内间距 8；分隔线保留，工作区不装饰卡片化 |
| 图库常规 | 分类 200–220；右栏 360–430；中间剩余；卡片最小 180，列数随剩余宽度改变 |
| 作者常规 | 部件 200–230；右属性 320–380；中间二维/三维平分，允许拖动分隔条但有限定最小宽度 |
| 小窗口 | 约 960×680 采用收起分类/部件栏；二维/三维页签切换替代并排；右栏可收起，底栏固定；所有字段通过滚动可达 |
| 滚动条 | 沿用现有细轨道、胶囊滑块，不恢复箭头；列表和属性独立滚动，固定底栏不滚走 |
| 高 DPI | 按 DIP/逻辑坐标实现；字体不按视口宽度缩放；缩略图保留长宽比，文字不截断关键编号 |
| 图标 | 复用现有统一图标；拾取/视图/撤销/可见性用熟悉符号，陌生符号加悬停提示 |
| 缺失/忙碌 | 明确文字状态；较长处理反馈；只禁用相关动作，不白屏或丢选中项 |
| 错误/取消 | 错误靠对应字段或部件，保留输入；关闭有未保存草稿时给保存/放弃/返回 |

实际实现必须验证 960×680、1280×800、1600×1000 和目标机器 DPI，分别检查文字、底栏、滚动、热区和拾取。设计图目视核对不能替代这些测试。

## 7. 视觉核对记录与实现注意

本轮目视检查了三个最终生成结果；未运行新的原生 UI 或性能测试。

- 图库：三栏、来源类型、参数字段、实际部件预览及固定底栏可见；右侧门窗与所选 M1525 一致。
- 配对：左列表/放大/右标题/leaf_L 一致，二维为俯视、三维左扇高亮，轴在外侧；固定边和可变区具象显示。
- 第一版配对误把部件标为 750×2500。已用 imagegen 定向修正为 700×2100，并把“边框厚度”修正为“门扇厚度”，补上竖向伸长区边界。只保存修正结果作为配套稿。
- 家具：柜体完整可见，左门/右门/抽屉形状清晰，墙体未切洞，型号/尺寸/开角一致。顶栏是简化的家具上下文，不要求删除现有完整 Ribbon 工具。
- 仍为示意：图库各卡片外观不作为所有门窗类型的精确 CAD 画法；选中 M1525 的实际型材截面、边框/上亮尺寸、透视开角须由实际作者样例生成后核对。固定框小图需从真实组合部件生成，不能沿用近似截图轮廓。
- 家具图中的位移/旋转热区和透视不是可用拾取证据；锁图标按第 2 节的只读摘要解释，尺寸页必须真正支持允许的编辑。
- 卡片/控件截图中可见的青色状态不等于已经支持 PBR。背景场景不纳入功能资产，也不用于开闭/尺寸/碰撞测试。

用户强调“一个线条都不能少”：实施时以最终确认稿的分隔、层级、图标、部件图和字段规格建立逐项比对，不擅自省略。栅格稿的近似几何、文字误差不能反向覆盖真实尺寸规则；有差异需记录并确认，而不是声称生成图已经逐像素实现。

## 8. 旧门窗兼容结论

现有代码具备参数类型、实例和分格分层，适合保留原后端并行接入外部资源。门窗不会被强制转成固定网格；旧项目/模板/v1 包继续走参数构造。详细字段、可空三维状态、模型内做法优先、另存转换、缺失回退和新旧程序版本边界见规划第 19 节。

本轮用仓库 SDK 执行 ComponentAssets 和 BuildingModel 现有测试套件，均成功；包括参数包往返、旧类型/MLC、分格/门槛/开启/编号/标准层/保存撤销。仅证明现有兼容基线，不能宣称尚未实现的外部后端已通过兼容测试。
