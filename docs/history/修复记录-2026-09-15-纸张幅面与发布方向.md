## 一、问题现象

用户报告：**发布 PDF 时纵向图纸和加长图纸看起来被"挤压"了**。

实际测量的旧输出（`桂林·山水湾四期_28#.pdf`，23 页）：**9 页被非等比拉伸**。

| 页 | 图号 | 纸张 | 内容流变换矩阵 | 形变 |
|---|---|---|---|---|
| 2 | — | 210×297 纵 | `0.707 0 0 1.4149` | 横向压扁 2.0013× |
| 10–11 | 建施8-9 | 891×420 加长 | `2.1206 0 0 0.4034` | 竖向压成 19.0% 高 |
| 12–14 | 建施10-12 | 743×420 加长 | `1.7684 0 0 0.5653` | 竖向压成 32.0% 高 |
| 15–17 | 建施13-15 | 594×841 纵 | `0.7063 0 0 1.4156` | 横向压扁 2.0042× |

## 二、根因

### 2.1 直接原因：PdfSharp 的 `DrawImage(dest, src)` 语义

`NormalizeTemporaryPage` 用 `XGraphics.DrawImage(form, destRect, srcRect, Point)` 做矢量裁切。
实测（离线探针，`src=841×594 不旋转`，`target=594×841`）：

```
cm=[0.7063 1.4158]   ← sx ≠ sy，非等比
```

**PdfSharp 只把 `srcRect` 当作裁剪框，缩放矩阵是按整张 form 铺满 `destRect` 计算的。**
所以只要源页与目标页比例不同（例如纵向图框落到横向介质上），整页就会被非等比塞进去。

旧代码用 `source.Width.Point / source.Height.Point` 算裁切，但缩放却由 form 尺寸决定，
两者不是同一个坐标空间，裁切框再准也救不回来。

### 2.2 触发条件：介质方向与登记方向不一致

发布日志（`%APPDATA%\WanluoArchitectureTools\用户配置文件\Logs\BatchPdfPublisher.publish.log`）：

```
15 建施13 目标=594×841 介质=ISO_full_bleed_A1_(841.00_x_594.00_MM) 驱动纸张毫米=841×594
10 建施8  目标=891×420 介质=UserDefinedMetric (420.00 x 1041.00毫米)
```

`ChooseMedia` 原本用 `Math.Min(direct, rotated)` 打分，**尺寸对得上就认、方向反了也照样选中**，
于是纵向图框被配到横向介质上 → 进入"后备介质 + 矢量裁切"路径 → 命中 2.1 的缺陷。

## 三、修复内容

### 3.1 修复非等比压缩（核心）

**文件**: `BatchPdfPublisher/Features/Publishing/Services/PdfPublisherService.cs` → `NormalizeTemporaryPage`

按 form 自身坐标算裁切，并用**单一系数**覆盖两个轴，结构上不可能再非等比：

```csharp
var formWidth  = form.PointWidth;
var formHeight = form.PointHeight;
var crop   = CenterCrop(formWidth, formHeight, target[0] / target[1]);
var scaleX = page.Width.Point  / crop[2];
var scaleY = page.Height.Point / crop[3];
var scale  = Math.Min(scaleX, scaleY);
graphics.DrawImage(form,
    new XRect(-crop[0] * scale, -crop[1] * scale, formWidth * scale, formHeight * scale),
    new XRect(crop[0], crop[1], crop[2], crop[3]), XGraphicsUnit.Point);
```

离线验证：4 种真实场景全部由 `SQUEEZED` 变为 `UNIFORM`，且内容包围盒**正好等于整页**
（含垂直居中的裁切，位置正确）。

### 3.2 介质方向不符时自动 90° 旋转，1:1 出图（通用，不针对具体项目）

**文件**: 同上 → `CreateSettings` / `PlotSinglePage` / 新增 `TemporaryPageIsUsable`

```csharp
var needRotation = allowRotation && mediaSize != null
    && (mediaSize[0] > mediaSize[1]) != (target[0] > target[1]);   // 介质与登记方向不一致
var rotation = needRotation ? PlotRotation.Degrees090 : PlotRotation.Degrees000;
```

`PlotSinglePage` 改为**两轮**：

1. 第 1 轮允许旋转。打完后用 `TemporaryPageIsUsable` 验收：必须是**登记方向的整页**且
   **确有图面内容**（`MeasurePageContentBytes` 统计页内 Form XObject 字节）。
2. 验收不过（打出空白页 / 方向仍不对 / 直接抛异常）→ 自动用第 2 轮 **0° + 矢量裁切**重试。

第 2 轮是已验证可用的路径，**所以新路径不会比原来更差**。
判据只比较"介质真实长短边方向 vs 登记纸张长短边方向"，没有写死任何纸张规格。

> 历史上代码强制 `Degrees000`，注释记录过 "AutoCAD 2022/TArch 用 90/270 会出空白页"。
> 本轮实测该问题未复现，且已有自动退回兜底，故放开。

### 3.3 用绘图仪真实纸张判断是否需要裁切

原代码从介质名解析尺寸（`UserDefinedMetric (420.00 x 743.00毫米)`），会被 PIA 的
`landscape_mode` 旋转误导。改为读 `settings.PlotPaperSize`（驱动真实回报值），名字只作兜底。

### 3.4 修正 `BPP_` 关键字死代码

AutoCAD 返回的 canonical media name 取自 PIA 的 `name` 字段
（`UserDefinedMetric (…)`），不是 `localized_name`（`BPP_…_FULL_BLEED`）。
原判断 `media.IndexOf("BPP_")` 永远不成立，导致：

- 打包介质的 -0.05 优先加分失效；
- "无白边（满幅）"模式下，自带满幅介质反而吃到 +0.2 惩罚，被排到最后。

新增 `IsBundledMedia()`，两种名字都认。

### 3.5 GB/T 50001-2017 幅面合规校验（新增）

**文件**: `PaperSizeCatalog.cs`、`PdfPublisherService.cs` → 新增 `ValidateStandardPaper`

第 3.1.3 条：图纸短边不应加长，A0～A3 长边可加长，但**应符合表 3.1.3**。
原 `GetSize` 对表外比例会用 `L + 分数×L` 自行推算，能造出 `2376×594` 这类标准里不存在的规格。

新增 `IsStandardExtension` / `TryGetStandardSize` / `DescribeStandardExtensions`，
发布前校验并给出该幅面允许的全部比例；表外加长比例直接报错。

### 3.6 同方向介质优先

`ChooseMedia` 拆成两轮：第 1 轮只接受与目标同方向的介质，确实没有再退到旋转介质。
避免"尺寸吻合但方向差 90°"的介质被优先选中而多走一次裁切。

### 3.7 其他修正

| 问题 | 处理 |
|---|---|
| 裁切路径上"空白页"判据失效（裁切后 content stream 仅 63 字节，内容在 Form XObject 里，`contentBytes < 512` 恒成立） | 新增 `MeasurePageContentBytes`，把页内 Form XObject 字节一并统计 |
| "保留 3 mm 白边"分支两轴缩放差 0.3%（inset 造成） | 改用单一等比系数 |
| 旋转页的最终尺寸日志读的是未换算 `/Rotate` 的 MediaBox，把横向页记成竖向 | 直接导入时改用临时页的显示尺寸 |
| **只读 PC3 导致启动器整个起不来**（`UnauthorizedAccessException`，2024 那份被标了只读） | `InstallPlotterProfiles` 与 `RewriteCompressedPlotterFile` 写回前调用 `ClearReadOnly()` |

## 七、遗留与说明

1. **特殊幅面 841×891 / 1189×1261** 已入纸张库（手工打印可用），但插件的
   「幅面 + 加长比例」登记模型表达不了，**在图框登记里选不到**。要用需先增加"特殊幅面"选项。
2. **`description{}` 里有 2 个孤立块**（idx 14、33），是编辑/删除纸张时留下的残留，
   没有纸张条目引用，不影响出图。
3. `Test-PlotterMedia.ps1` 曾按**块序号**配对 `size{}` 与 `description{}` 两个列表，
   导致一次误报（19 条假"不一致"）。两个列表**互相独立、编号不对齐**，
   真正的连接键是描述名字符串（`size.media_description_name` ↔ `description.name`），已改正。
4. 自动旋转的 `Degrees090` 方向已在真实输出上目视确认正确；若某版本 AutoCAD 表现相反，
   改为 `Degrees270` 即可（单点修改）。
