# 建筑模型程序修复：拖构件时选中项被清空 → NullReferenceException

**日期**: 2026-09-26
**仓库/分支**: `huangzhenwei2020/autocad-batch-pdf-publisher` → `main`（**仅本地提交，未推送**）
**现象来源**: 用户在程序里操作后弹出中文错误框（我们自己加的兜底提示）：

```
System.NullReferenceException: Object reference not set to an instance of an object.
   at Wanluo.BuildingModelStudio.PlanCanvas.<OnMouseMove>b__86_1(ColumnModel c) in ...\PlanCanvas.cs:line 584
   at System.Linq.Enumerable.TryGetFirst[...]
   at Wanluo.BuildingModelStudio.PlanCanvas.OnMouseMove(MouseEventArgs e) in ...\PlanCanvas.cs:line 584
日志：C:\Users\34505\AppData\Local\万落建筑模型\错误日志\建筑模型-错误-20260926-135419.log
```

## 一、根因

`PlanCanvas.OnMouseMove` 的拖动分支**每次都用 `_selection` 反查被拖的构件**：

```csharp
var column = (_model.Columns ?? new List<ColumnModel>())
    .FirstOrDefault(c => c != null && Same(c.Id, _selection.Id));   // ← _selection 可能是 null
```

而 `_selection` 会被这些操作清掉：**Delete 删除、Ctrl+Z 撤销、Ctrl+Y 重做、切楼层、Esc 取消、换模型**。
于是出现这样的真实序列（任一种都能触发）：

1. 按住柱子拖动（`_drag = MoveColumn`）；
2. 拖动还没结束，选中项被清空（例如拖动中按了 Delete / Ctrl+Z，或鼠标在窗口外松开导致 `OnMouseUp` 没跑到、随后又切了楼层）；
3. 鼠标再动一下 → 拖动分支解引用 `_selection.Id` → **NullReferenceException**。

顺带说明：这次崩溃**没有把程序带走** —— 上一轮加的界面兜底把异常接住了，弹的是中文提示（含类型、堆栈、日志路径），
日志也确实写到了 `%LOCALAPPDATA%\万落建筑模型\错误日志\`。兜底到位，但根因必须修。

## 二、修法（不是加个 `if`，而是让这种状态不可能存在）

1. **拖动期间只认"开始时抓到的构件引用"**：新增 `_dragWall / _dragOpening / _dragColumn / _dragGrip`，
   在 `OnMouseDown` 命中时就抓住对象；拖动分支不再看 `_selection`。
2. **任何会让目标失效的动作都取消拖动**：新增 `CancelDrag()`，在
   删除、撤销、重做、`StoreyId` 变更、`Tool` 变更、`Model` 变更、`Esc`、**鼠标捕获丢失**（`OnMouseCaptureChanged`）时调用。
3. **再加一道保险**：`DragTargetAlive()` 检查抓着的构件是否仍在模型里（撤销会把模型换成快照，
   引用自然不在里面）；拖动洞口时它的**宿主墙**没了也会取消拖动并提示。
4. **自检留证**：新增 `PlanInteractionSelfTest`（把鼠标消息直接送进画布，不需要窗口消息循环），
   固定住"拖动中目标被删 / 被撤销 / 换楼层 / 宿主墙消失"四条路径。

## 三、核实过的事实

```
PASS 拖柱：跟手移动 800mm，松手记一步撤销
PASS 拖柱中删除：拖动已取消，鼠标继续移动不再抛 NullReferenceException
PASS 拖墙夹点中撤销：拖动已取消，鼠标继续移动不再改动模型
PASS 拖柱中换楼层：拖动已取消，鼠标继续移动不再拖动旧构件
PASS 拖洞口时宿主墙消失：拖动已取消，不再改洞口定位
PASS 平面交互自检：拖柱 / 拖墙夹点 / 拖洞口 —— 目标被删、被撤销、换楼层、宿主墙消失都只取消拖动，不抛异常
```

（这些断言是"修好之前会挂"的：把 `_dragColumn` 换回 `_selection` 就会在第二条上抛 NRE。）

回归检查也一并跑过：画布自检 18 项、立面预览自检 5 张视图 + 极端变换 + 坏数据、主窗口真实绘制一次，全过：

```
PASS 画布自检全部通过（正常/极端/坏数据/坏 Graphics）
PASS 主窗口构造与画布装载：楼层 2、墙 8、洞口 7（已真实绘制一次，无异常）
PASS 立面预览：已真实绘制一次，样例-两层小房子 南立面图 画了 66 条线 / 3 个文字（无异常）
```

## 四、顺手做的可发现性改进（同一次提交）

- 顶部新增一键入口按钮 **「预览立面」**：切到预览页并按当前模型重算一张；
- 修掉"切到预览页可能一片空白"的隐患：视图可能在控件还没拿到尺寸时装进来，那一刻"缩放适应"算不了，
  原点会留在左上角外侧 —— 现在控件一拿到尺寸、以及每次绘制前都会自动适应一次；
- 新增 `--snapshot-ui [<png>]`：把主窗口（预览页）渲染成 PNG，用于核对界面。

## 五、教训（写进代码约定）

**凡是"跨事件保存的 UI 状态"，都要在拖动/操作期间只认自己抓住的对象引用；共享的 `_selection` 只用于显示。**
需要清空选中项的每一个入口，都要顺带取消正在进行的拖动 —— 这两条现在都由 `CancelDrag()` 与
`DragTargetAlive()` 兜住，并由 `PlanInteractionSelfTest` 钉住。
