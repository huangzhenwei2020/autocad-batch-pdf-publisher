# 新增功能：启动器里的项目管理（改名不影响 CAD、云同步与扫描结果）

**日期**: 2026-09-19
**仓库/分支**: `huangzhenwei2020/autocad-batch-pdf-publisher` → `main`
**起始提交**: `dd83cfc`（文档同步）
**需求原话**: “我感觉还得加一个项目管理的功能，可以删除/新建项目/修改名字及项目里文件的名字，
这个功能不在 CAD 里，在启动器上加一个按钮，然后对项目进行管理，修改完成之后，CAD 里面能正常识别
并能正常上传下载（对于云同步功能）就是说不会影响项目的正常使用，比如批量打印功能不用重新扫描。”

---

## 一、为什么“改个名字”不是改一个字符串

项目名不是显示用的一行文字，它被写进了六处不同性质的状态里。先按代码把账算清楚
（下面的行号是本次改动前的状态）：

| 状态 | 位置 | 键是什么 | 只改 `Name` 的后果 |
|---|---|---|---|
| 项目注册表 | `通用设置\项目列表.json`（`PublishPlanStore.cs:321`） | 项目名 + 绝对路径 | CAD 里项目名变了，但 `CadFiles`/`SavedSheets[].SourceFile` 还指向旧文件夹 |
| 当前项目指针 | `通用设置\当前项目.txt`（`PublishPlanStore.cs:322`） | 项目名 | `GetActiveProject()` 静默回退到 `projects[0]`（`PublishPlanStore.cs:89-94`） |
| 云同步身份 | `ProjectSyncProjectionStore.StableProjectId(名)` = `名-<sha5>` | 项目名 | **CloudId 变了**：`项目文件/<CloudId>/…` 整条同步路径作废 |
| 云同步映射 | `cloud-sync.settings.json` → `ProjectMappings[]` | 项目名 + CloudId + 本地目录 | 新旧两条映射并存，旧的继续同步旧目录 |
| 同步状态库 | `.cloud-sync\state.json` → `Files[].LogicalPath` | `项目文件/<CloudId>/相对路径` | 新前缀全部 `baseHash=null` → **整项目全量重传** |
| 批量打印扫描结果 | `项目列表.json` → `ProjectProfile.SavedSheets[].SourceFile` | **绝对文件路径** | CAD 侧按 `File.Exists` 判定，找不到就丢行；不重扫直接发布报“发布所需的 CAD 文件不存在” |
| 图框模板 | `用户配置文件\图框模板\<项目名>\*.dwg`（`FrameTemplateStore.cs:89`） | 项目名目录 | CAD 下次加载时自动搬到新名字目录（`MakePathsReadable`），云端旧副本留下 |
| 楼梯方案 / 平面缓存 | `楼梯大样\项目\<项目名>`、`楼梯平面缓存\<项目名>` | 项目名目录 | 按新名字从零重建 |

结论：“改名”本质上是一次跨多个存储的**引用迁移**，而不是一次 `string` 替换。

## 二、关键设计决定：项目身份与项目名解耦

云同步的身份 `CloudId` 原本每次都从项目名现算：

```csharp
CloudId = StableProjectId(project.Name)   // 项目名一变，身份就变
```

一旦身份变了，同步引擎（`LocalFolderSyncEngine`）只认 `LogicalPath`，没有任何“同哈希换路径=改名”的识别
（`ProcessFile` `LocalFolderSyncEngine.cs:172-263`），结果是：新 CloudId 前缀下全部当新文件上传、旧前缀条目
永久残留，云端还会多一份同名目录。对几个 GB 的工程目录来说不可接受。

因此给 `ProjectProfile` 增加一个**持久化的 `CloudId`**：

- 首次仍由项目名派生（与旧算法逐字节一致，老配置升级后取值不变，因此不影响任何老用户）；
- 之后**改名不再重算**，身份跟着项目走；
- 旧配置没有这个字段时，按 ① 已记住的 → ② 旧映射同名 → ③ 旧映射同目录 → ④ 按名派生 四级回退补齐
  （`ProjectSyncProjectionStore.AssignIdentities`），并且必须在写 `项目列表.json` **之前**补齐，
  否则改名当次写盘的还是旧值。

改名的实际后果因此收敛成：

- `项目文件/<CloudId>/…` 一个字节都不用动 → **不会重新上传工程目录**；
- 只需重写一份很小的“项目描述”投影（`项目配置\同步项目\<CloudId>\项目.json`，内容是项目名与相对路径）；
- 云同步映射只更新 `ProjectName`/`LocalFolder`，`CloudId` 保持 → 同步中心的“已同步/待上传”状态不变。

`ProjectSyncProjectionStore` 的三处配套改动：

1. `Export` 按 `ProjectId(project)`（即持久化 CloudId）写投影，而不是按名字现算；
2. `MergeInto` 把**投影目录名**当作权威身份写回项目（其他设备改名后本机也能对上）；
3. `BuildMappings` 先 `AssignIdentities`，再按 CloudId/名字双查旧映射，`Enabled`/`SelectionConfirmed`
   与“已归档”判定都改用最终 CloudId。

## 三、实现：一份逻辑，两个宿主

项目管理要在**没有 CAD** 的启动器里跑，但它改的是 CAD 的项目文件。如果启动器另写一套读写，
两边对 `项目列表.json`、CloudId、云同步映射的理解迟早会漂移。所以：

- 新增 `Features\Projects\Services\ProjectManagementService.cs`（纯 `System.*`，不引用 AutoCAD）：
  负责方案（`PlanCreateProject/PlanRenameProject/PlanRenameFile/PlanDeleteProject`）与执行
  （`Execute`），执行前后写操作记录、备份配置、失败即回滚；
- 启动器**以源码链接方式**编译同一份实现
  （`BatchPdfPublisherLauncher.csproj` 里 14 个 `<Compile Include="..\BatchPdfPublisher\…">`），
  于是**没有新增任何 DLL**——发布脚本对 `CadApi` 目录有“只允许 `BatchPdfPublisher.dll`”的白名单校验，
  启动器的安装/自动加载清单也是逐文件硬编码的，新增独立 DLL 会连带改安装器与卸载逻辑；
- 启动器侧缺的只有 `CloudSyncCoordinator`（依赖 AutoCAD），用 `CloudSyncCoordinatorStub.cs` 顶替成空操作：
  启动器本来就不能同步，下次进 CAD 时同步引擎自然会跑；
- 为了让这套链接成立，顺手把两处“纯函数”抽成共享文件，避免两套实现：
  - `FrameTemplatePaths.cs`（图框模板目录约定，原在 `FrameTemplateStore` 里，`FrameTemplateStore` 改为委托）；
  - `FileHash.cs`（SHA256 大写十六进制，原在 `LocalFolderSyncEngine` 里，`CloudSyncTransaction` 也改用它）。

## 四、改名时到底改了什么

`ProjectManagementService` 的一项改名 = 以下动作，全部先出方案给用户看、确认后才执行：

1. **搬移**（必需项失败即整体回滚；楼梯缓存等非必需项失败只记警告）
   - 项目文件夹 → 同级目录下改成新名字（默认，可在界面上关掉）
   - `图框模板\<旧名>\*.dwg` → `图框模板\<新名>\`，逐个文件搬，目标已存在则跳过并告警
   - `楼梯大样\项目\<旧名>`、`楼梯平面缓存\<旧名>`（存在才搬）
2. **改写引用**：项目名、`ProjectFolder`、`OutputDirectory`、`CadFiles`、`SelectedCadFiles`、
   `SavedSheets[].SourceFile`、`Frames[].TemplateRelativePath`；`CloudId` **保持不变**。
   外部登记的图纸（例如 `D:\华为云盘\…`）原样保留，不参与搬移。
3. **落盘**：经 `PublishPlanStore.SaveProjects` 写入（原子写 + `.bak`），同时刷新投影与云同步映射；
   若改的是当前项目，同步更新 `当前项目.txt`。
4. **记录**：`项目配置\项目管理\<时间>-<操作>.json` 写下正向/反向映射，执行前另存
   `项目列表.json.项目管理备份-<时间>` 与 `cloud-sync.settings.json.项目管理备份-<时间>`。

改名之外：

- **重命名项目内文件**：只允许项目文件夹内的文件；物理改名后改写 `CadFiles`/`SelectedCadFiles`/
  `SavedSheets[].SourceFile`，所以下次进 CAD **不需要重新扫描**。若有 `pending` 待应用更新会提前告警。
- **新建项目**：默认目录 = 工作区根目录下的同名文件夹；同时解除同名 CloudId 的归档并恢复同步登记，
  避免“同名重建后同步默认是关的”。
- **删除项目**：从列表移除 + 关闭该项目的云同步登记 + 标记归档（防止被云端投影重新导回）+ 删除投影目录；
  勾选“移到回收站”时才把项目文件夹、图框模板、楼梯缓存移到回收站。云端已上传的文件**不会**被删除。

## 五、界面与安全前提

启动器主窗口底部新增“项目管理”按钮（与“手动选择程序/卸载插件”同一行），打开独立窗口：

- 左侧项目列表（含项目数、配置路径）；右侧项目信息、云同步状态、新建/删除、项目文件列表
  （文件名/大小/是否已登记、已扫描/修改时间，双击即可改名）。
- 窗口打开时与每次执行前都检测 **AutoCAD 是否在运行**（`ProjectManagementService.IsCadRunning`）：
  正在运行则禁用全部写操作并提示先关闭 CAD——CAD 内存里有一份项目列表，会在保存时把磁盘改动覆盖回去。
- 执行前弹出方案预览（搬移项、引用改写条数、注意事项），默认按钮是“否”。

## 七、已知边界（本次有意不做）

1. **门窗立面的“按工程记忆”设置**按项目名存在 `door-window-elevation-settings.json` 的 `ProjectName`
   字段里，改名后需要重新设置；旧数据不会被删除（界面上会提示）。原因是该模型文件依赖 AutoCAD，
   启动器无法链接，硬做只能在启动器里复制一份 DTO —— 与“一份逻辑”的原则冲突，故留待后续用共享字段的方案处理。
2. **云端旧名字的副本不会被删除**：同步引擎从不传播删除（`DeleteLocal/DeleteRemote` 无调用点，
   `StageDelete` 无调用点）。改名后旧路径只留一条 warning，云端旧副本会作为孤儿保留，
   需要在云同步中心或网盘侧自行清理。跨设备也会看到“新旧两份”，这是引擎既有语义，不是本次引入。
3. **不做撤销按钮**：改名前写操作记录与配置备份，失败时自动回滚；成功后如需还原，按记录里的正反向映射手工处理。
4. 重命名后的**自动保存快照**（`项目文件夹\自动保存\原名_路径指纹_自动保存.dwg`）不跟着改名：
   文件仍可直接打开，只是名字里的路径指纹过期；下次自动保存会生成新名字的快照。
