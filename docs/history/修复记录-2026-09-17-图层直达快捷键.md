# 图层直达快捷键失效：目标图层没传到位

**日期**: 2026-09-17
**仓库/分支**: `huangzhenwei2020/autocad-batch-pdf-publisher` → `codex/detail-layout-frame-ranges`
**起始提交**: `46bed46`

---

## 一、现象

用户在"制图标准 → 图层快捷键"里给门窗（门）图层填了快捷键 `DOO`，实测：

> 输入自己设置的图层快捷键后得到的是对象归层 GL 的效果，并没有得到应该对应图层的效果。

也就是**别名执行了、GL 也起来了，但目标图层丢了**——弹的是普通 GL 的选层对话框。

现场数据（用户机器）：

```
%APPDATA%\WanluoArchitectureTools\用户配置文件\通用设置\layer-shortcuts.ini
DoorWindowDoor=DOO
```

---

## 二、根因

原来的做法是"AutoLISP 写环境变量 → .NET 读环境变量"：

```lisp
(defun c:DOO () (setenv "WANLUO_TARGET_LAYER" "WL-门窗-门") (command "GL") (princ))
```

```csharp
Environment.GetEnvironmentVariable(FeatureRegistry.LayerEnvironmentVariable);
```

**AutoLISP 的 `setenv` 写的是 AutoCAD 自己的环境表，并不保证同步进 Windows 进程
环境块**；而 .NET 的 `Environment.GetEnvironmentVariable` 读的正是进程环境块。
两边看起来"读写同一个名字"，实际是两个存储。别名、命令、图层名全都是对的，
唯独这一个值到不了 .NET 侧。

佐证：用户执行过 `DOO` 之后，注册表里既没有 `HKCU\Environment` 项，也搜不到
`WANLUO_TARGET_LAYER`——说明 `setenv` 连持久化都没做，只在 AutoCAD 进程内自己的
表里。`(getenv ...)` 在 LISP 里读得到，.NET 读不到。

---

## 三、修法：改成 LispFunction 同进程传值

`[LispFunction]` 是 AutoCAD .NET 的官方互操作入口：AutoLISP 直接调用 .NET 方法，
同一个进程、直接传参，不存在任何环境变量同步问题。

`BatchPdfPublisher\Commands.cs`：

```csharp
[LispFunction("WLSETLAYER")]
public object SetPendingLayer(ResultBuffer args)
{
    var values = args == null ? null : args.AsArray();
    _pendingLayerName = values != null && values.Length > 0 ? Convert.ToString(values[0].Value) : null;
    return null;
}
```

生成的调用文本（新增纯逻辑类 `Features\Shortcuts\LayerCommandLisp.cs`）：

```lisp
(progn
  (if WLSETLAYER (WLSETLAYER "WL-门窗-门"))      ; 主通道
  (setenv "WANLUO_TARGET_LAYER" "WL-门窗-门")     ; 兼容通道
  (command "GL"))
```

三个细节：

1. **主通道是 `WLSETLAYER`**，`setenv` 只作为兼容通道保留（万一某个 CAD 版本确实
   会同步进程环境块，两条路都能用）。
2. **`(if WLSETLAYER ...)` 是防御**。万一函数名被同名 LISP 函数占了导致没注册，
   裸调用会让整条别名报错中断，连 `setenv` 回退和 `(command "GL")` 都跑不到——
   那快捷键就彻底没反应了。AutoLISP 里未绑定的符号求值为 `nil`，所以 `if` 守卫
   本身是安全的。
3. **整段包成一个 `(progn ...)`**。这一段文字有两个消费方：快捷键别名
   `(defun c:DOO () (progn ...) (princ))` 和 CUIx 菜单宏 `^C^C(progn ...)`。
   菜单宏里多个散装 LISP 形式会被命令行拆开执行。

`Commands.ReadAndClearPresetLayer` 按"LispFunction 暂存值 → 环境变量 → 无"的顺序取值，
取到就清空，保证同一次会话里后面的手动 `GL` 照旧弹对话框。

## 四、顺带修掉的两个隐患

### 4.1 一个图层出错会吞掉所有图层命令

`FeatureRegistry.All` 原来是**在循环外** `catch { return FixedItems; }`：
任何一个图层读不出名字，就会把**所有**图层直达命令一起丢掉，用户只看到
"图层快捷键没反应"，且没有任何提示。改成逐个图层兜异常。
同时复用一次 `LoadProfile()`——`LayerNameFor` 每次调用都会重读标准文件，
逐个调用等于每个图层重读一遍盘。

### 4.2 快捷键别名生成结果不可见

`ShortcutAliasService` 现在会把本会话生成的图层直达命令写进 UI 日志：

```
图层直达快捷键：DOO→WL-门窗-门
图层直达快捷键：无（图层快捷键表为空）
```

"按下去弹的是 GL 对话框"这类问题，光看界面分不清是**别名没生成**还是
**目标图层没传进去**；日志里有一行"快捷键→图层名"就能一眼定位。

另外直达归层成功后命令行会留一句回执，否则用户只能靠"图层有没有变"猜命令走了哪条路：

```
万落建筑工具：直达归层 → WL-门窗-门（不弹对话框）
```

## 五、测试与构建期校验

新增 `BatchPdfPublisher.Tests\LayerCommandLispTests.cs`（5 项，`LayerCommandLisp` 是
纯逻辑、不依赖 AutoCAD，所以能离线断言）：

| 断言 | 防的是什么 |
|---|---|
| 整段是一个 `progn`、单行、括号配平 | 菜单宏被拆开执行 |
| 目标图层通过 `WLSETLAYER` 传递 | **本次的 bug 本身** |
| 传值排在 `(command "GL")` 之前 | GL 已经弹完对话框了 |
| `setenv` 兼容通道还在 | 回退通道被误删 |
| `(if WLSETLAYER ...)` 守卫存在 | 函数没注册时整条别名中断 |
| 图层名里的引号/反斜杠被转义 | 图层名带特殊字符时 LISP 语法崩掉 |

`CuixPackageBuilderTests.CuixLayerEntriesUseLispInvocation` 同步更新，
锁住 CUIx 菜单宏里也是同一个 `progn` 形式。

`build\Build-Release.ps1` 增加构建期校验：`LayerCommandLisp.SetFunctionName` 必须能在
`Commands.cs` 里找到对应的 `[LispFunction("...")]`。两边改名不同步会静默失效，
表现只是"图层快捷键弹 GL 对话框"，很难查，所以在构建期卡住。

```
图层直达命令校验通过：WLSETLAYER LispFunction 已注册
```

### 在 CAD 里怎么确认修好了

查 `%APPDATA%\WanluoArchitectureTools\用户配置文件\Logs\BatchPdfPublisher.ui.log`，
启动后应有：

```
图层直达快捷键：DOO→WL-门窗-门
```

选中对象按 `DOO`，命令行应出现：

```
万落建筑工具：直达归层 → WL-门窗-门（不弹对话框）
```

- 没有第一行 → 别名没生成（图层快捷键表为空或保存失败）
- 有第一行但仍弹对话框 → LISP 侧传值仍失败，看是不是 `WLSETLAYER` 被同名函数占了
- 出现第二行 → 已修好

## 七、遗留

- 用户的 `drafting-standard.ini` 是 17 个图层的旧版本，不含 `DoorWindowDoor` 等
  门窗/大样图层。此时 `LayerNameFor` 会回退到内置默认名（`WL-门窗-门`），
  快捷键仍然可用；要改名字请在"制图标准"里把这几层补回来。
