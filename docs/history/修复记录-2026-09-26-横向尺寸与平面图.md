## 一、横向尺寸链（把立面标注补全）

在已有两条竖向链之外，建筑下方加了**两道横向链**：

| 位置 | 内容 |
|---|---|
| **内层**（建筑底边下 1200） | **洞口定位链**：立面左右两端 + 这个立面上所有洞口的左右边线，排序后连成连续尺寸 |
| **外层**（建筑底边下 2000） | **总长** |

样例（干净模型）南立面实测读数：内层 `200｜1450｜950｜550｜650｜1350｜900｜1350｜200`（一层窗、一层门、二层窗），
外层 `7600`。竖向链在左侧、横向链在下方，两者在左下角对齐 —— 常规立面图的排法。

**顺带查出一个真 bug**：算立面范围时把**标高符号线**也算进去了（它比轮廓多伸出去 1400），
总长会算成 8840 而不是 7440。现在取范围只用"建筑几何"那一批图层，标注类图层（标高/图名/尺寸/门窗表）排除在外。
测试里加了这条断言，避免以后又滑回去。

## 二、平面图：平面也由模型投影生成

新增 `ViewKind.Plan` 与 `OrthographicProjector.ProjectPlan(model, view, library)`（用 `StoreyIds[0]` 指定画哪一层），
v1 内容：

| 元素 | 画法 |
|---|---|
| **墙** | 两条面线（±墙厚/2）在**洞口处断开**，洞口两端补封口；墙用"剖到"图层（平面是水平剖切，墙柱断面最粗） |
| **窗** | 两条玻璃线（墙厚内侧偏移，取 `min(墙厚×0.35, 60)`） |
| **门** | 一条扇线（从门垛沿墙法线出去，长度 = 洞口宽）+ **90° 开启弧**（8 段折线拟合，弧端点落在另一侧门垛上） |
| **柱** | 断面矩形（同"剖到"图层） |
| **编号** | 每个洞口下方标 `C1518`/`M0921`… |
| **尺寸** | 下方横向定位链 + 总长、左侧竖向定位链 + 总宽（都由墙端点与洞口边线取值） |
| **可点选** | 每个洞口都有锚点（框住洞口 + 墙厚），所以**平面图里也能点选门窗、换做法** |

干净样例一层平面：线 59（门窗图例 15）、尺寸 16、总长 7600 / 总宽 5800、可点选门窗 4 个；
二层平面：线 24、尺寸 10、可点选 1 个。程序里「生成全部视图」会**每层**写一份 `plan-<楼层>.json`，
预览下拉里多出「一层 平面图 / 二层 平面图」，`--snapshot` 也会出 PNG。

同时修了一处排版：**图名原来会压在尺寸链上**，现在图名落到最外一道尺寸线之外。

## 三、核实过的事实

**单元测试**（新增第 9 组"平面图"，坐标手算核对）：

```
平面图：墙面线在洞口断开、窗 2 条玻璃线、门扇线 + 弧、柱断面，总长 7600 / 总宽 5800，锚点 4 个
PASS 立面门窗：… / 尺寸与门窗表 / 平面图
```

断言包括：南墙面线在 1450–2950（窗）与 4950–5850（门）处**断开**（并显式断言洞内不该有线）、
窗左门垛封口存在、窗的两条玻璃线在 ±42、门扇线 4950,0→4950,900、开启弧扫到 5850,0、
门窗图例共 15 条（3 窗×2 + 1 门×9）、柱断面矩形、总长 7600 / 总宽 5800、
横向定位链含洞口边线且各段之和 = 总长、锚点框盖住洞口与墙厚。

**尺寸归零的一致性修复**：`Normalize` 原来只平移线/填充/文字，**没平移尺寸** ——
落图后尺寸会整体偏掉一个视图原点。现在按"竖直尺寸量 Z、水平尺寸量 U"分别平移，
测试也统一改成"换算回模型坐标"来核对（原来那几条断言其实是在验证未平移的行为）。

**预览自检**：9 张视图（4 立面 + 剖面 + 2 平面 + 门窗表）逐张离屏真画，线/文字/尺寸条数与视图数据**完全一致**。

**发布**：`Build-Release.ps1 -Bands R24,R25`（R24/R25 都过）。**人眼核对**：干净样例的
`一层 平面图.png` 上墙线断开、窗双玻璃线、门弧、柱断面、编号与两道尺寸链都正常，图名在下方不压尺寸。

## 四、已知边界（下一步）

1. 平面 v1 **不画**：楼板/房间填充、房间名与面积、轴网与轴号、剖切符号与索引号（P5）；
2. 门扇开启方向固定取洞口起点一侧（模型里还没有"开启方向"字段）；
3. 平面的尺寸链是"墙端点 + 洞口边线"的整体定位链，**还不是分道轴线尺寸**（要等轴网进模型）；
4. 立面/平面都还没有**图框排版**（选图框、按纸张分页、图纸目录）—— 这是 P5 的最后一块。
