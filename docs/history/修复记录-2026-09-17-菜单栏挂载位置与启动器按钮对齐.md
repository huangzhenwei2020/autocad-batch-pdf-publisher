**基线提交**: `fc15056`

## 一、经典菜单没出现在菜单栏

### 现象

功能区（Ribbon）正常显示 5 个面板 18 个按钮，但经典菜单栏上看不到「万落建筑工具」。
`BatchPdfPublisher.ui.log` 里却写着：

```
菜单已请求加载并挂到菜单栏 P16：...\Temp\BPP_万落建筑工具.cuix（第 1 次尝试）
```

### 根因

**`P16` 在菜单栏上根本不存在**，`menucmd` 静默失败。那行日志是在
`SendStringToExecute` **之后**就写的，只代表"请求已发出"，不代表挂载成功。

对照本机 `acad.CUIX`（AutoCAD 2022，`%APPDATA%\Autodesk\AutoCAD 2022\R24.1\chs\Support\`）
里 `<Alias>` 的真实取值：

| 槽位 | 用途 |
|---|---|
| `POP0` | 光标（右键）菜单 |
| `POP1`–`POP12` | 菜单栏的 12 个主菜单（FILE…HELP） |
| `POP5xx` | 对象 / 夹点上下文菜单 |

没有 `POP16`。`menucmd` 的 `"Pn"` 是**菜单栏绝对位置**，默认布局只有 12 格。

### 对照 Express Tools

同一个方案原本声称"结构照抄 `acetmain.cuix`"。实测该文件的真实做法是：

- 顶层弹菜单别名取的是**菜单栏槽位名** `POP1`（在它自己的菜单组命名空间内）；
- **完全没有调用 `menucmd`**；
- 它出现在菜单栏靠的是 workspace 里的一条引用：
  `<WSPop MenuGroup="EXPRESS" pUID="ID_MNEXPRESS" Display="1" />`（见 `acad.CUIX` 的 `WorkspaceRoot.cui`）。

即：局部菜单上菜单栏的路径是"别名落在 POP1–POP12 内 + workspace 引用"，
而不是"`menucmd` 挂某个高位槽位"。本插件是运行时生成局部菜单、不便改 workspace，
因此仍走 `menucmd`，但**位置必须取菜单栏上真实存在的那一格**。

### 处理

`CuixPackageBuilder`：

1. 别名与位置**解耦**。`PopupAlias` 改为组内标识 `BPP_MAIN`（原来直接叫 `POP16`，
   把"槽位名"和"位置"混成了一个概念）；新增 `MenuBarPosition = 13`。
2. 取 13 而不是 1：`P1` 会插到"文件"之前、把既有菜单顶开；13 是默认 12 个菜单之后的
   第一格。本机另装有天正等第三方菜单（合计约 15 个），`+` 是追加语义，
   即便该格已被占用也只是插入，不会顶掉任何现有菜单。
3. `MountExpressionChain()` 生成 `(or menucmd "P13=+..." menucmd "P14=+..." ... )`：
   从期望位置往后逐个尝试。`menucmd` 挂不上时返回 nil，`or` 会继续试下一个，
   全都失败也不会报错中断——避免某一格在特定菜单栏布局下不存在就整个挂不上。

测试 `CuixPackageBuilderTests` 同步调整：断言改为"用配置的位置挂载"、
"必须是追加语义"、以及"位置必须在 1–16 且不得用 16"。
注意**回退链里仍会出现 P16**，这是无害的（在不存在的位置挂载只是失败），
真正要防的是把它当成**首选**位置——这一点已在测试注释里写明。

### 待验证

`menucmd` 对**运行时生成的局部菜单**是否稳定生效，无法在本机离线断言
（需要真实 AutoCAD 交互）。若改后菜单仍不出现，下一步应改走 Express Tools 那条路：
把弹菜单别名设为 `POP1`，并往 workspace 里加 `WSPop` 引用。

## 二、启动器底部按钮不在同一水平线

### 根因

不是锚点问题，是**纵向空间本来就不够**，且 DPI 基准缺失。

启动器窗体设了 `AutoScaleMode = AutoScaleMode.Dpi`，但**没有设 `AutoScaleDimensions`**，
于是沿用字体基准 `(6,13)`，与 Dpi 模式不匹配，行高与控件高度的缩放比例不一致。

按 GDI+ 实际排版算一遍：

| 项 | 值 |
|---|---|
| 底部行高 | 72 |
| `Padding(28,14,28,14)` 后内容区 | 44 |
| 按钮高 | 40 |
| Button 默认 `Margin` 上下各 3 → 需要 | 46 |

**已经超出 2px**，字体或 DPI 稍微放大就明显错位。

### 处理

`BatchPdfPublisherLauncher/Program.cs`：

1. 补 `AutoScaleDimensions = new SizeF(96F, 96F)`。
2. 底部行高 72 → **84**，`Padding` 改为 `16/16`（内容区 52，容纳 46 有余）。
3. 四个按钮显式 `Anchor = AnchorStyles.Left`：`TableLayoutPanel` 默认 `Top|Left`，
   单元格高度不整除时各列各自贴顶；列是 `AutoSize`（宽度恰等于按钮），
   横向 anchor 不起作用，因此只设 `Left` 表达"垂直居中"。
4. 窗体高度 488 → **500**，补回底部加高的 12px，中部卡片区不被压缩。
