## 一、这一轮做了什么

建筑模型程序加了第二个页签**「立面 / 剖面预览」**：选一张视图点「重算当前视图」，
立刻按**当前内存里的模型**（不是磁盘上的旧 JSON）算出来并画出来 —— 不用生成视图、更不用开 CAD。

| 能力 | 说明 |
|---|---|
| **实时重算** | 下拉框选视图（南/北/东/西立面 + 剖面）→「重算当前视图」直接用当前模型 + 当前门窗类型库投影；改完平面不保存也能先看效果 |
| **所见即所得** | 预览画的 `ViewDocument` 就是 CAD 的 `LTTZ` 落图读的那份数据，所以预览等于落图结果的预演 |
| **图层图例** | 左上角列出各图层的**颜色、线宽、这一张图上的条数**（如"WL-模型-门窗（43 条）"），并列出投影提示（如"门窗「M1500」不在类型库里"） |
| **剖面填充** | 按视图里的 `Spacing`/`Angle` 画 45° 细线（用 `GraphicsPath` 裁剪到断面形状内），1:50 的 75mm 间距就是图上 1.5mm |
| **标高与图名** | 标高符号线与文字（±0.000 / 3.600）、图名与比例 |
| **操作** | 中键/右键拖动平移、滚轮以光标为锚点缩放、Ctrl+A 缩放适应；状态栏显示光标坐标、线/文字/填充条数、当前比例 |
| **PNG 快照** | 命令行 `--snapshot` 把 5 张默认视图渲染成 PNG（与预览同一条绘制路径），写到模型目录下的 `预览\` 子目录，方便留档或发给别人 |

## 二、顺手补上的两处地基

1. **绘制护栏统一到 `DrawGuard`**：屏幕坐标夹取、非有限值判断、视口可用性判断原本散在平面画布里
   （`PlanCanvas` 私有方法 + `PlanGrid` 常量），现在集中一处，平面画布、轴网、立面预览共用。
   理由很直接：上一轮画布崩溃就是"把 ∞ 交给 GDI+ 抛 `OverflowException`"，
   与其在每个画布各写一遍，不如让**"非有限值不许出这个类"**成为一条代码规则（实测边界也写在注释里：1e9 可以、2e9 就抛）。
2. **预览也和平面画布一样有兜底**：`SafeRender` 包住整次绘制，出错只在画布上写一行提示 + 状态栏报错，
   绝不把 `OverflowException` 抛给 WinForms（上一轮那种"未经处理的异常"对话框不会再出现）。

## 三、已经核实过的事实（都可以重跑）

**预览自检**（`--selftest-canvas` 里的第 2 段，把视图真正画到离屏位图上，走 OnPaint 同一条路）：

```
PASS 预览 样例-两层小房子 南立面图：线 63（门窗 43）、文字 3、填充 0，非背景像素 98136
PASS 预览 样例-两层小房子 北立面图：线 29（门窗 10）、文字 3、填充 0，非背景像素 95357
PASS 预览 样例-两层小房子 东立面图：线 29（门窗 10）、文字 3、填充 0，非背景像素 91678
PASS 预览 样例-两层小房子 西立面图：线 19（门窗 0）、文字 3、填充 0，非背景像素 89893
PASS 预览 1-1 剖面图：线 28（门窗 2）、文字 3、填充 7，非背景像素 122065
PASS 预览极端视图变换 10 种：不挂、不抛
PASS 立面预览自检全部通过（5 张视图 / 极端变换 / 坏数据 / 坏 Graphics）。
```

断言不是"画出来就行"：每一张视图都要求 **画出的线数/文字数与视图数据完全一致**
（`LastLineCount == view.Lines.Count`），否则说明有线条被静默跳过；再加上像素数下限。
另外还测了：坏视图数据（NaN/∞ 坐标、`1e300` 超长线、`1e12` 超大文字、越界与 NaN 填充、null 元素）只跳过自己、
已释放的 `Graphics` 必须被兜底拦下。

**主窗口真实绘制**（`--selftest`，走窗口 WM_PAINT）：

```
PASS 主窗口构造与画布装载：楼层 2、墙 8、洞口 6（已真实绘制一次，无异常）
PASS 立面预览：已真实绘制一次，样例-两层小房子 南立面图 画了 63 条线 / 3 个文字（无异常）
```

**人眼核对**：`--snapshot` 生成的 5 张 PNG 已逐张看过（模型目录 `预览\` 下），南立面图上：

- 外轮廓 7440 宽、两层、中间一条 3.600 的分层线；
- 两樘 `C1518`（双扇等分）中挺在洞口正中，两支**反向**推拉箭头（"双向推拉"）；
- 一樘 `M0921`（单扇左平开）外框内边 + 门扇内框 + 两条开启线（左下→右中→左上）；
- 右侧标 `3.600`、右下角标 `±0.000`；左上图例写"门窗（43 条）"；
- 图例里还出现一条真实提示：**「M1500」不在类型库里** —— 那是你在样例工程里手画的一樘门，
  程序按规则只画了洞口轮廓并提示"用 TQLX 导出类型库后可补上分格与开启线"。

剖面上能直接看到：被剖到的两道墙与两块楼板断面**带 45° 填充**、洞口处断面断开（窗台/窗顶线）、
远处背景构件用浅色投影线。

## 四、已知边界（下一步）

1. 预览是**只读**的：还不能在预览里点门窗改做法（要改就去改类型库或模型，然后重算）；
2. 立面上的**门窗编号标注**、竖向尺寸标注还没做（P5 的标注部分）；
3. 剖面里的门窗仍按 P0 规则简化（只画窗台/窗顶线），没有窗框分格；
4. 快照只能出 PNG，**没有直接出 PDF/出图**（出图仍走 CAD 的 `LTTZ` 落图 + 现有打印模块）。
