## 一、经典菜单没能自动出现

### 现象

功能区（Ribbon）正常显示 5 个面板 18 个按钮，但经典菜单栏上看不到「万落建筑工具」。
`BatchPdfPublisher.ui.log` 却写着：

```
菜单已请求加载并挂到菜单栏 P16：...\Temp\BPP_万落建筑工具.cuix（第 1 次尝试）
```

**这行日志不可信**：它写在 `SendStringToExecute` 之后，只表示"请求已发出"，
不表示加载或挂载成功。排查时不要把它当成成功证据。

### 核实过的事实

1. **菜单栏是可见的**。注册表里所有配置的 `MENUBAR` 均为 1，用户界面上也确实能看到
   `文件/编辑/…/帮助` 等 11 个中文主菜单，以及第三方菜单。
   所以问题不在 "菜单栏被隐藏"。
2. **生成的 CUIx 文件是有效的**。同一份结构（顶层 `Alias`、子菜单、宏定义齐全）由用户
   在 CUI 对话框里**手工加载**后，能在「草图与注释」工作空间的菜单栏正常显示。
   说明文件本身与挂载机制都没有问题。
3. **插件没有注册任何"加载菜单"的命令**。代码里只有 `[CommandMethod("WLMENUBAR")]`
   （切换菜单栏显隐），没有任何命令去执行菜单加载；加载只发生在启动时的
   `MenuService` 内部。因此"手工能加载、自动不能"这个差异，**只能出在启动时那段
   加载表达式上**。
4. **经典菜单栏由工作空间控制**。本机 `acad.CUIX` 的 `WorkspaceRoot.cui` 里，每个
   `<Workspace>` 用一组 `<WSPop MenuGroup="…" pUID="…" Display="1" />` 逐条声明
   "哪些菜单组的哪个弹菜单出现在菜单栏"。Express Tools 正是靠
   `<WSPop MenuGroup="EXPRESS" pUID="ID_MNEXPRESS" Display="1" />` 出现的。
   **运行时加载的局部菜单不会自动获得这条引用**，必须自己挂。
   实测后果：菜单可能只在某些工作空间显示。

### 未证实 / 待办

加载表达式里的两条命令都没能在真实环境里验证通过：

- `(command "_.-MENULOAD" …)` —— `_.` 是"国际版命令"前缀，加在已带横线的命令行版本
  命令上会拼成 `_.-MENULOAD`。**用户实测**：在命令行直接输入
  `(command "_.-MENULOAD" …)` 报 **"未知命令"**。
- 去掉 `_.` 后的 `(command "-MENULOAD" …)` —— **同样报 "未知命令"**。

但这两次实测都是**通过 `.scr` 脚本或命令行求值**进行的，而这台机器上 `.scr` 的
`_.NETLOAD` 那几行本身就没有正常执行（用户在命令行看到的是 `程序集文件名: BPPSTARTUP`
这种把参数当输入吃掉的表现）。**因此上述"未知命令"不能确定代表正常加载路径下的行为。**

**下次排查的正确第一步**：不要先分析 `acad.CUIX` 或猜测槽位号，而是在 AutoCAD 命令行
里逐条验证真实命令：

```
(command "-MENULOAD" "<cuix 路径>" "BPP")
(menucmd "P16=+BPP.POP16")
```

先把"命令是否存在、能否执行"确认下来，再去调参数。这次在槽位号（P16/P13）上来回改了好几轮，
方向从一开始就是错的。

### 已做的清理

排查期间为做隔离测试，手工加载过一个最小诊断菜单组 `BPPTEST`。它卸载后在工作空间里
留下了 3 条悬空 `<WSPop MenuGroup="BPPTEST" …>`。已从用户配置中移除：

```
%APPDATA%\Autodesk\AutoCAD 2024\R24.3\chs\Support\acad.CUIX

备份：acad.CUIX.bak-bpptest-cleanup
```

## 二、启动器底部按钮不在同一水平线（已修）

### 根因

不是锚点问题，是**纵向空间本来就不够**，且 DPI 基准缺失。

启动器窗体设了 `AutoScaleMode = AutoScaleMode.Dpi`，但**没有设 `AutoScaleDimensions`**，
于是沿用字体基准 `(6,13)`，与 Dpi 模式不匹配。

按 GDI+ 实际排版算一遍：

| 项 | 值 |
|---|---|
| 底部行高 | 72 |
| `Padding(28,14,28,14)` 后内容区 | 44 |
| 按钮高 | 40 |
| Button 默认 `Margin` 上下各 3 → 需要 | 46 |

**已经超出 2px**，字体或 DPI 稍微放大就明显错位。

### 处理（`BatchPdfPublisherLauncher/Program.cs`）

1. 补 `AutoScaleDimensions = new SizeF(96F, 96F)`。
2. 底部行高 72 → **84**，`Padding` 改为 `16/16`（内容区 52，容纳 46 有余）。
3. 四个按钮显式 `Anchor = AnchorStyles.Left`：`TableLayoutPanel` 默认 `Top|Left`，
   单元格高度不整除时各列各自贴顶；列是 `AutoSize`（宽度恰等于按钮），
   横向 anchor 不起作用，因此只设 `Left` 表达"垂直居中"。
4. 窗体高度 488 → **500**，补回底部加高的 12px，中部卡片区不被压缩。
