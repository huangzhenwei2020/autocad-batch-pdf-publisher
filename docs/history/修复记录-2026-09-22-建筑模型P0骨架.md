## 一、这一轮做了什么（P0 的骨架）

按 v3 架构（**模型与投影在独立程序，CAD 只做"提取 / 落图"两个搬运工**）搭出最小可运行的链路：

| 部分 | 位置 | 说明 |
|---|---|---|
| 模型与视图的数据约定 | `Shared/BuildingModel/ModelTypes.cs` | 楼层 / 墙 / 洞口 / 楼板 / 柱；视图（线/文字/填充）；视图图层表；"提取图纸"的中间格式 |
| 中间格式读写 | `Shared/BuildingModel/BuildingModelJson.cs` | `DataContractJsonSerializer`（与本仓库其它配置一致），原子写 + `.bak`，带 `SchemaVersion` 校验 |
| **自研正交投影** | `Shared/BuildingModel/OrthographicProjector.cs` | 矩形化投影 + 洞口挖空 + **近处矩形裁掉远处边**（隐藏线消除）+ 剖切断面与填充 + 标高/图名 |
| 样例模型 | `Shared/BuildingModel/SampleModelFactory.cs` | 两层小房子（7200×5400、外墙 240、层高 3600/3300）+ 默认 5 张视图 |
| 建模程序（骨架） | `BuildingModelStudio/` | WinForms：新建样例 / 生成全部视图 / 打开目录；另有命令行 `--generate` 便于自动化 |
| CAD 侧两个桥 | `Features/BuildingModel/Services/BuildingModelCadBridge.cs` | `TQTZ` 提取图纸（线条/块/文字/图层 → JSON）、`LTTZ` 落图（视图 JSON → 实体） |
| 命令与登记 | `Commands.cs`、`FeatureRegistry.cs` | `[CommandMethod("TQTZ")]`/`[CommandMethod("LTTZ")]` + 四字简称「提取图纸」「视图落图」 |

**共享方式**：`Shared/BuildingModel` 下的纯逻辑源码被**三方共用**（建模程序、主插件、测试工程），
用源码链接编进各自工程，**不新增 DLL**——避免触发 `CadApi` 的 DLL 白名单校验与启动器安装清单改动。

## 三、还没验证的（要你在 CAD 里跑一次）

`LTTZ` 落图与 `TQTZ` 提取**只做过编译与代码审查，没有在真实 AutoCAD 里跑过**——
运行时行为（图层创建、线型、填充图案、坐标系与插入点）需要你实测。

## 四、P0 的已知边界（有意不做，不是缺陷）

1. **只保证正交墙的立面轮廓精确**；斜墙按投影包围盒近似，并在视图的 `Warnings` 里提示；
2. 立面**不表达"透过窗看到室内"**：洞口作为独立矩形画在门窗图层，墙矩形不挖洞；
3. 剖切只支持**轴对齐的直线剖面**（X=常数 / Y=常数），任意方向剖切是后续阶段；
4. 视图图层目前**硬编码**在 `ViewLayers`（颜色/线宽/线型），P5 才接到制图标准；
5. 不做 DXF（已定的决定）：程序只产出视图 JSON，一切成品经 `LTTZ` 进 DWG；
6. 平面草图编辑器（P1.5）、三维视口（P4）、老图识别（P3）都还没开始。
