## 一、背景

插件功能从最初的几个涨到 **18 个固定功能**（外加按图层动态生成的 `GL` 直达命令），
入口却没跟着整理，用户提了三条意见：

1. **"功能越来越多了，希望它有自己的菜单栏。但新版本 CAD 没有菜单了。"**
2. **"面板上的功能排成一条过去很占空间，你得重新设计规划一下。"**
3. **"每个按钮都改成四个字，工整一点（意思不变）；图标重新设计一下，现在看不明显。"**
   **"菜单也统一一样的名字，还要写上快捷键。"**

三条意见对应三处改动：菜单栏（CUIx）、功能区面板规划、按钮/菜单的文字与图标。

## 二、经典菜单栏：只能靠生成 CUIx

### 2.1 为什么不是 MNU

AutoCAD 的 `MENU` 命令是 R12 时代的遗留接口，`MNU/MNS/CUI` 早已被 **CUIx** 取代。
实测：`-MENULOAD` 加载一个手写的 `.mnu` **不报错也不生效**——因为不会生成配套的
`.mnc`/`.cui`。所以第一条路直接判死。

### 2.2 CUIx 的真实结构

拆开本机的 `acetmain.cuix`、`custom.cuix`、`acad.CUIX` 逆向出来的结构：

| 部分 | 编码 | 作用 |
|---|---|---|
| `[Content_Types].xml` | UTF-8 **带 BOM** | OPC 内容类型声明 |
| `_rels/.rels` | UTF-8 **带 BOM** | 包根关系 |
| `Header.cui` | UTF-8 无 BOM | 版本头 |
| `MenuGroup.cui` | UTF-8 无 BOM | 菜单组 + 宏定义 + 子菜单 |
| `PopMenuRoot.cui` | UTF-8 无 BOM | 顶层弹出菜单（挂菜单栏的那个） |
| `Menu_Package_Info.xml` | UTF-8 **带 BOM** | 包信息 |

关键引用关系：

- `<MenuMacro UID="ID_X">` 由 `<MacroRef MenuMacroID="ID_X">` 引用，**不是**按名字找；
- 子菜单是独立的 `<PopMenu UID=...>`，由 `<PopMenuRef pUID=...>` 引用；
- 顶层弹菜单的 `<Alias>POP16</Alias>` 必须与挂载命令里的
  `menucmd "P16=+BPP.POP16"` 对上；
- UID 在整个包内必须唯一（子菜单之间的 `PMI_BPP_00x` 曾重复，改成全局计数器）。

生成逻辑集中在新增的 `BatchPdfPublisher\Shell\CuixPackageBuilder.cs`，**不依赖 AutoCAD**，
离线就能断言，所以配了 11 项测试锁死结构。

### 2.3 挂载：一个 AutoLISP 形式，先卸再装

`MenuService.LoadPartialMenu` 写包之后，把下面这一整段作为一个字符串
`SendStringToExecute` 发出去：

```lisp
(progn
  (if (menugroup "BPP") (command "_.-MENUUNLOAD" "BPP"))
  (command "_.-MENULOAD" "…/BPP_万落建筑工具.cuix" "BPP")
  (menucmd "P16=+BPP.POP16")
  (princ))
```

两个坑都是踩出来的，注释写在 `CuixPackageBuilder.BuildLoadExpression` 上：

1. **必须先卸载**。`-MENULOAD` 作用在**已加载**的菜单组上是空操作，会继续用旧定义。
   表现就是"CUIx 明明改了，CAD 里菜单还是老样子"——这次用户报的正是这个问题。
2. **绝不按行裸发**。按行发时，一旦 `-MENULOAD` 没吃干净输入，残留的 `BPP`
   会掉到命令行上被当作命令执行——而 `BPP` 正是打开批量打印面板的命令
   （之前"加载菜单会顺带弹出 BPP 面板"就是这个原因）。

`MENUBAR` 这个系统变量在新版 CAD 里依然存在（2022–2025 均可），出厂值为 `0`（隐藏）。
`Shell\MenuService.cs` 用 `Application.SetSystemVariable("MENUBAR", …)` 控制，
并新增 `WLMENUBAR` 命令 / "菜单开关" 功能一键切换。

## 三、功能区重排

原来**一个分组一个面板、每个面板只排一行**，18 个功能一字排开，横向占满整条功能区，
超出的还被折进下拉。

新增 `Shell\RibbonPanelPlanner.cs`（同样纯逻辑、可离线断言）：

- `ButtonsPerRow = 2`、`MaxRows = 3` → 单面板上限 `6` 个按钮；
- `DefaultPlan` 把相关分组合并成 4 个逻辑面板；
- 超过上限时**均分**拆分，而不是前面塞满、最后一个只剩一两个
  （`AppendChunked`：7 项、上限 6 → 4 + 3，不是 6 + 1）；
- 没写进规划的新分组**各自单独成面板**，保证新登记的功能不会漏掉。

18 个功能实际落成 **5 个面板**：

| 面板 | 内容 | 按钮数 |
|---|---|---|
| 图纸与发布 | 图纸与发布(3) + 图块与属性(2) | 5 |
| 建筑工具 | 建筑工具(前 4) | 4 |
| 建筑工具 (2) | 建筑工具(后 4) | 4 |
| 制图与图层 | 制图与标注(2) + 图层工具(1) | 3 |
| 系统设置 | 系统设置(3) | 3 |

按图层动态生成的 `GL` 直达命令**不进功能区**（只进菜单栏和快捷键），
这样面板宽度不会随图纸图层数量增长。

## 四、统一成四个字 + 快捷键 + 新图标

### 4.1 四字简称

`FeatureDefinition` 从 `FeatureRegistry` 里独立出来（`Features\Shortcuts\FeatureDefinition.cs`），
新增 `ShortName` 字段：

- **菜单**：`四字简称（快捷键）`；
- **功能区按钮**：`四字简称（快捷键）`；
- **CUIx 宏的 `<Name>`**：保留完整功能名（不受简称影响）；
- **鼠标悬停提示**：完整功能名 + 说明。

18 个简称：批量打印、创建图框、插入目录、批改属性、属性定义、建筑说明、表格编辑、
楼梯大样、制图标准、对象归层、比例管理、门窗立面、大样排版、图像转绘、房间改名、
快捷设置、菜单开关、云端同步。

`build\Build-Release.ps1` 里加了**构建期校验**：正则抓取 `FeatureRegistry` 里每条
`F("…")` 的最后一个字符串参数，不是 4 个字符就直接让构建失败，
避免以后新加功能忘了起简称：

```
功能简称校验通过：18 个功能均为四字简称
```

### 4.2 图标

原来 18 个功能共用同一种方块图标，放在一起分不清。新增
`Shell\RibbonIconTheme.cs`（纯逻辑）：

- 按**分组**着色：图纸与发布 `#2D70BE`、图块与属性 `#6A4FBF`、建筑工具 `#0E8A7D`、
  制图与标注 `#B8730F`、图层工具 `#1F7A3D`、系统设置 `#5A6472`；
- 圆角底色块 + 白色加粗单字（打/框/目/属/定/说/表/梯/标/层/比/窗/排/绘/房/键/菜/云），
  字体 Microsoft YaHei，16×16 用 `FormattedText` + `BuildGeometry` 现画。

同一分组颜色一致，所以一眼能看出"这一片是图纸与发布"；单字区分到具体功能。

## 七、遗留

- `MENUBAR` 出厂为隐藏，首次安装需要点一次"菜单开关"（或 `WLMENUBAR`）才会出现菜单栏；
  这项设置存在注册表里，之后一直保留。
- 经典菜单栏官方已标记为 legacy，功能区仍是主入口；菜单栏主要是给习惯老界面的用户和
  按图层动态生成的 `GL` 直达命令留的入口。
