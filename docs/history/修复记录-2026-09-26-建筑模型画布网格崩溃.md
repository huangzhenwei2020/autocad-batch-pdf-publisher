# 建筑模型程序崩溃修复：平面草图画布网格死循环 → GDI+ OverflowException

**日期**: 2026-09-26
**仓库/分支**: `huangzhenwei2020/autocad-batch-pdf-publisher` → `main`（**仅本地提交，未推送**）
**现象来源**: 用户运行 `万落建筑模型.exe` 后的截图 —— 画布区域整块变成红叉，桌面弹
"应用程序的组件中发生了未经处理的异常"，异常文本 `System.OverflowException: Overflow error.`
at `Wanluo.BuildingModelStudio.PlanCanvas.DrawGrid(Graphics g)`。

---

## 一、根因（已用真实栈复现，不是推测）

`PlanCanvas.DrawGrid` 里画横网格线的两个循环条件写反了：

```csharp
// 屏幕 Y = offsetY - 模型Y * scale，模型 Y 越大屏幕 Y 越小
for (var y = 0d;  ToScreen(0, y).Y <  Height + 200; y += step)   // 条件恒为真 → y 无限增大
for (var y = -step; ToScreen(0, y).Y > -200;        y -= step)   // 条件恒为真 → y 无限减小
```

- 循环永不结束，屏幕坐标不断远离视口，程序先卡住几十秒 ——
  这正是窗口变成"未响应"、画布区域被画成红叉的原因；
- 屏幕坐标越过 GDI+ 能接受的范围后，`Graphics.DrawLine` 直接抛
  `System.OverflowException: Overflow error.`，于是弹出 .NET 的未处理异常对话框。

GDI+ 的边界是实测出来的（`net8.0-windows`，`Graphics.DrawLine`）：

| 坐标 | 结果 |
|---|---|
| 1e6 / 1e7 / 1e8 / 1e9 | OK |
| 2e9 / 2.1e9 / 4e9 / 1e10 / 1e12 / 1e30 / float.MaxValue | **OverflowException: Overflow error.** |
| ±∞、NaN | **OverflowException: Overflow error.** |

即 GDI+ 把坐标折算成 int32：超过约 2.1e9 或不是有限值就抛。原来的循环把 `y` 加到
天文数字只需要"几十秒"，所以现象是"先卡住、再报错"。

## 二、复现（修复前）

新增 `--selftest-canvas`（把画布真正画到离屏位图上，走的就是 `OnPaint` 那条路），
**未修复前**在默认视图的第一次绘制就复现出同一个异常：

```
FAIL System.OverflowException: Overflow error.
   at Wanluo.BuildingModelStudio.PlanCanvas.DrawGrid(Graphics g) in ...\PlanCanvas.cs:line 244
   at Wanluo.BuildingModelStudio.PlanCanvas.Render(Graphics g) in ...\PlanCanvas.cs:line 196
   at Wanluo.BuildingModelStudio.CanvasSelfTest.RenderOnce(...)
```

与用户截图里的栈完全一致（同一个方法、同一个异常）。

## 三、修复内容

| 位置 | 改动 |
|---|---|
| `BuildingModelStudio/PlanGrid.cs`（新增） | 网格计算独立成**纯逻辑**：先把可见区域反算成模型坐标，再按步长取整点；单轴网格线硬上限 400 条、步长最多放大 64 次；比例/偏移非有限、为 0 或为负一律返回空表；屏幕坐标超过 1e8 的线直接丢弃 |
| `PlanCanvas.DrawGrid` | 不再自己循环，只画 `PlanGrid.Compute` 算好的线 |
| `PlanCanvas.ToScreen` | 所有屏幕坐标统一夹进 ±1e8（NaN → 0）：**任何路径都不可能再把 ∞ / NaN / 2e9 交给 GDI+** |
| `PlanCanvas.Render` | 视图变换坏掉（比例/偏移非有限）时不硬画，提示一行并 `ZoomExtents()` 自愈 |
| `PlanCanvas.ZoomExtents` | 取范围前过滤掉 NaN / ∞ 坐标，坏数据不会把整份视图的比例带成 NaN |
| `PlanCanvas` 各绘制方法 | 墙/柱/洞口/楼板逐个 `Sane(x, y)` 过滤（有限且 ≤1e9），坏构件只跳过自己 |
| `PlanCanvas.OnPaint` | 拆成 `OnPaint → SafeRender`：绘制抛异常只提示、不再把程序带走（`LastPaintError` 供自检断言） |
| `Program.CrashLog`（新增） | 界面线程兜底：任何未处理异常写日志到 `%LOCALAPPDATA%\万落建筑模型\错误日志\` 并弹中文提示，不再弹 .NET 英文堆栈 |
| `Program --selftest` 增强 | 显示主窗口后**强制真实绘制一次**并断言无绘制错误（以前只是构造窗口，可能根本没画到画布） |
| `build/Test-BuildingModelStudio.ps1`（新增） | 一条命令：编译建筑模型程序 + 跑两个自检 |

## 五、这份自检以后管什么

1. 正常比例（含崩溃当时的 1px≈26.7mm）必须画满网格、条数合理、坐标都在屏幕内；
2. 12 种极端视图（缩到最小/放到最大/平移到天边/比例 NaN/偏移 ∞/比例 0 或负）不挂、不抛、网格有界；
3. NaN / ∞ 坐标的坏模型只能被跳过，不许影响整块画布，也不许把比例带成 NaN；
4. 连 `Graphics` 都是坏的（已释放）时，兜底必须拦下而不是抛给 WinForms。
