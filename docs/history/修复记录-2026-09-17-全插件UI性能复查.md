# 全插件 UI 重绘性能复查

**日期**: 2026-09-17
**仓库/分支**: `huangzhenwei2020/autocad-batch-pdf-publisher` → `codex/detail-layout-frame-ranges`
**上一轮**: `docs/history/修复记录-2026-09-17-窗口重绘性能.md`（制图标准窗口）

用户确认制图标准窗口不卡了之后，要求把**同一类问题**在其余 UI 里一并排查修掉。
下面按"痛点"分四类，逐类给出排查结果。

---

## 一、双缓冲：从"一个窗口"扩到"全部窗口"

上一轮只给 `DpiAwareForm` 在 `Load` 时遍历控件树开双缓冲。复查发现这个时机对
**原生控件不够**：

| 控件 | 双缓冲怎么生效 | 时机要求 |
|---|---|---|
| `DataGridView`、`Panel`、`TabPage`… | WinForms 自绘，读 `ControlStyles.OptimizedDoubleBuffer` | 任何时候设都行 |
| **`ListView` / `TreeView`** | 靠 WinForms 在 `OnHandleCreated` 里给原生控件设 `LVS_EX_DOUBLEBUFFER` / `TVS_EX_DOUBLEBUFFER` | **必须在句柄创建之前设**，建完再设不生效 |

修法：`DpiAwareForm` 增加

```csharp
protected override void CreateHandle()
{
    UiPerformance.BufferedTree(this);   // 句柄创建之前先开，原生控件才会带上双缓冲样式
    base.CreateHandle();
}
```

`Load` 时那遍保留，兜住运行时才加进来的控件。

### 插件的 27 个窗口都继承 `DpiAwareForm`，但有两个例外

`CloudSyncCenterForm`、`CloudSyncSettingsForm` 直接继承 `Form`。
**没有改它们的基类**——换成 `DpiAwareForm` 会把 `AutoScaleMode` 从 `Font` 改成 `Dpi`，
那是缩放行为的改变，没法在这里验证，风险不值得冒。改成在构造函数末尾显式：

```csharp
DoubleBuffered = true;
UiPerformance.BufferedTree(this);   // 构造函数里还没建句柄，正好是 ListView 需要的时机
```

### 涉及的 ListView

- `CloudSyncCenterForm` 有 **5 张** `ListView`（待应用/冲突/历史/项目/工作文件）；
- `LineVisionForm` 有 **5 张** `ListView`（线/圆/圆弧/多段线/墙）。

两者现在都在句柄创建前开好了双缓冲。插件里没有 `TreeView`。

## 二、逐帧分配 GDI+ 对象：找到一处真正严重的

### 2.1 `LineVisionPreviewControl`（图像转 CAD 预览）—— 按实体数量分配

这是复查里**唯一一处会随数据量线性放大**的：结果视图的绘制循环里，**每个实体**
`new Pen`，墙体和文字还各要 `new SolidBrush` / `new GraphicsPath`，然后 `Dispose`：

| 循环 | 每个实体原来分配 |
|---|---|
| 线段 | 1 个 Pen |
| 圆 / 圆弧 | 1 个 Pen |
| 多段线 | 1 个 Pen |
| 墙体 | 1 个 GraphicsPath + 1 个 SolidBrush + 1 个 Pen |
| 文字 | 1 个 SolidBrush + 1 个 Pen（低置信度再加 1 刷 2 笔） |

一张扫描图识别出成百上千条线段是常态，而平移、缩放、鼠标划过都会触发重绘——
一次重绘上千个 GDI+ 对象。改成**复用一个 Pen / SolidBrush / GraphicsPath**，
每次只改 `Color` / `Width` / `DashStyle`（墙体路径用 `Reset()` 复用）。
`DrawLowConfidenceMarker` 同理，标记三角形也从每次 `new[]` 改成复用数组。

循环里剩下的 `new PointF[]` 是托管数组，代价比 GDI+ 对象小几个数量级，
不值得为它引入缓冲区尺寸管理，保持原样。

### 2.2 其它预览控件：常量对象提到字段

这几个控件都已经把渲染缓存在位图里（只在脏了才重画），不是滚动热路径，
但每次重画仍会 `new` 十几到二十个对象，顺手清掉：

| 控件 | 处理 |
|---|---|
| `DoorWindowLayoutPreviewControl` | 12 个画笔/笔刷/字体提为静态字段；**并修掉每次重绘 `new Bitmap(Width, Height)`**（1000×700 就是 2.8 MB），改成复用缓存位图、只在尺寸变化时重建 |
| `DetailLayoutPreviewControl` | 8 个提为静态字段；`DrawCentered` 原来每次 `new Font + SolidBrush + StringFormat`，改成按字号缓存的字体表 + 复用笔刷/格式 |
| `DoorWindowElevationPreviewControl` | 14 个提为静态字段；`DrawCentered` 同样改缓存字体 |
| `DoorWindowLayoutEditorControl` | 8 个改为**实例**只读字段（其中 3 支笔在绘制中会改虚线样式再改回来，实例作用域避免跨实例残留），并补上 `Dispose` |

### 2.3 `PublisherForm` 的三处

- `PaintProgressTrack`：进度每更新一次重绘一次（扫描/发布时一秒几十次），
  原来每次 `new` 两个笔刷加一支画笔 → 提为静态字段；
- `SheetsRowPostPaint`：拖动图框列表时的插入指示线，拖动过程反复重绘 → 提为静态字段；
- `AddHeightDragIndicator`：分隔条在鼠标划过/拖动/缩放时重绘，两个画笔 → 提为静态字段。

### 2.4 查过但**不需要改**的

- `AttributeBatchForm.GridCellFormatting`：只是按状态给 `CellStyle.BackColor` 赋一个
  静态 `Color`，很便宜；
- 各表格都已经把 `AutoSizeColumnsMode` / `AutoSizeRowsMode` 设成 `None` 再配一个
  `Fill` 末列，没有 `AllCells` 那种"每次绘制都重新测量"的昂贵模式。

## 三、空闲时的无效工作

`Application.Idle` 一秒触发几十上百次，挂在它上面的活儿都要有便宜的前置判断。
复查了全部 8 处 `Application.Idle +=`：

| 位置 | 结论 |
|---|---|
| `RibbonService` | 上一轮加了 1.2 秒节流 |
| `ShortcutAliasService` | 上一轮加了 1 秒节流 |
| `MenuService` | 挂上菜单后自己 `Detach` |
| `Commands.ShowPublisher` / `FrameRegistrationService` | 一次性处理器，第一行就 `-=` |
| `ProjectAutoSaveService` | 有 `_nextSaveUtc` 早退，间隔以分钟计 |
| `CloudSyncCadNotificationService` | 加锁取一个引用，本来就是空的 |
| **`CadSaveCloudSyncService`** | **改**：原来每次都先问一遍 `CMDNAMES` 系统变量、再建两个空集合才判断"没有待处理项"；改成先看队列是否为空，空就直接返回 |

## 五、验证

- ProjectStore 测试：**44 项全过**
- 楼梯套件：**92 项全过**
- `Build-Release.ps1 -Bands R24` 通过，构建期三项校验全绿，0 警告 0 错误

同样的说明：这些都是重绘与分配行为，**没有离线断言可加**，只能在 CAD 里体感确认。
建议重点看这几处（原来是逐帧分配的）：

1. 图像转 CAD：识别出较多线段后，在结果视图里**缩放和拖动**；
2. 门窗立面：拖动分隔线、切换行；
3. 批量打印面板：扫描/发布过程中进度条与拖动图框排序；
4. 云同步中心 / 云同步设置：拖动窗口、滚动列表。
