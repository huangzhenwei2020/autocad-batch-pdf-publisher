## 一、关掉设置窗口后 BPP 自己打开了（含首次安装）

### 现象

> 改完快捷键，关闭窗口的时候会自己打开 BPP；第一次安装插件的时候也不应该打开 BPP。

### 根因：`MenuService.RefreshNow()` 里按行裸发了 `BPP`

```csharp
// 修复前
document.SendStringToExecute("_.-MENUUNLOAD\n" + MenuGroup + "\n", true, false, false);
//                                     ↑ 常量就是 "BPP"
```

这一行把**菜单组名**当成命令行输入单独发了一行。只要 `-MENUUNLOAD` 没把 `BPP`
这一行吃掉（菜单组当时没加载、或命令的输入消耗与预期不一致），残留的 `BPP`
就落到命令行上——而 `BPP` 正是打开批量打印面板的命令。

**这正是上一轮已经在 `CuixPackageBuilder.BuildLoadExpression` 里修过的同一个坑**
（当时的注释写着"绝不按行裸发……残留的 BPP 会掉到命令行上被当成命令执行"），
但 `RefreshNow()` 里这份按行实现被漏掉了。

日志对得上：

```
01:46:13  图层直达快捷键:GL→归层,DOO→WL-门窗-门      ← 保存快捷键，触发 RefreshNow
01:46:16  BPPUBLISH entered                          ← 3 秒后 BPP 面板自己开了
```

### 修法：直接删掉那一行

`BuildLoadExpression` 生成的是一个 AutoLISP 形式，里面**本来就有**先卸载再加载的守卫：

```lisp
(progn
  (if (menugroup "BPP") (command "_.-MENUUNLOAD" "BPP"))
  (command "_.-MENULOAD" "…cuix" "BPP")
  (menucmd "P16=+BPP.POP16")
  (princ))
```

所以 `RefreshNow()` 里那次单独的卸载**既是多余的、又是危险的**：删掉它，
卸载+加载变成一个形式的原子操作，命令行上再也不会出现裸的 `BPP`。
另外加了一行日志 `菜单已请求重新加载（快捷键或图层表变更）`，下次出问题能直接对上时间。

## 二、图层快捷键：已有选择就直接执行

> 应该是用户如果选择了对象就直接执行命令，如果没有选择对象就让用户选择。

GL 里原本已经会尝试用预选集（`Editor.SelectImplied`），但图层直达命令是由 AutoLISP 的
`(command "GL")` 发起的，**不能假定预选集（pickfirst）在 LISP 发起的命令调用里还留着**。

修法：让 LISP 在调 GL **之前**自己把预选集抓下来交给 .NET。

```lisp
(progn
  (if WLSETSELECTION (WLSETSELECTION (ssget "_I")))   ; 先抓预选集
  (if WLSETLAYER (WLSETLAYER "WL-门窗-门"))            ; 再传目标图层
  (setenv "WANLUO_TARGET_LAYER" "WL-门窗-门")          ; 兼容通道
  (command "GL"))
```

- `(ssget "_I")` 没有预选时返回 `nil` → GL 照常提示用户选择；
- 新增 `[LispFunction("WLSETSELECTION")]` 接收选择集（`LispDataType.SelectionSet`）；
- GL 里优先用这份预选集，用完顺手 `SetImpliedSelection(空)` 清掉，免得后续命令又拿它干活；
- 直达归层成功后命令行留一句回执：`万落建筑工具：直达归层 → WL-门窗-门（不弹对话框）`。

## 三、"图层快捷键"页签去掉，改成图层标准表里的一列

原来 `制图标准` 窗口有 5 个页签，其中"图层快捷键"是独立一页，内容是
`分组 / 系统标签 / 图层名称 / 快捷键 / 使用方`——和"图层标准"页的图层列表**是同一批图层**，
分成两页反而要来回切。

现在：

- 页签从 5 个减到 4 个：图层标准 / 文字样式 / 标注样式 / 引线样式；
- "图层标准"表在"当前图纸"和"备注"之间加了一列 **快捷键**；
- 快捷键跟着图层表一起保存（"创建勾选图层""更新当前图纸图层"和底部两个保存按钮
  都会存），改动过才重新生成别名 + 刷新功能区/菜单（没改就什么都不做）；
- 去掉了独立页签的"使用方"列，但这条信息没丢——**悬停图层名即可看到该图层被哪些功能使用**；
- 页脚加了一行说明：规则、留空含义、以及"悬停图层名看使用方"。

## 四、制图标准窗口发滞

查下来是两处"每次都要重做一遍的重活"。

### 4.1 空闲时一直在读盘 + 重算功能区标签

`RibbonService` 把 `TryInstallRibbon(false)` 挂在 `Application.Idle` 上，
**没有任何节流**。`Application.Idle` 在消息队列一空就触发（空闲时一秒几十上百次），
而这次检查要：

1. `ComponentManager.Ribbon.FindTab()` 走一遍 WPF 功能区树；
2. `ShortcutSettingsService.Load()`；
3. → `FeatureRegistry.All` → `LayerShortcutStore.Load()` + `DraftingStandardService.LoadProfile()`
   → **`File.ReadAllLines(制图标准)` + `CreateDefault()` + 上百次字典查找**；
4. → 再 `File.ReadAllLines(快捷键)`；
5. 然后 18 × N 次字符串比较。

模态窗口打开时这个泵照样在跑，于是界面就"发滞"。

修法三条：

- `RibbonService` 的 Idle 检查加 **1.2 秒节流**（显式刷新不走节流，立即生效；
  工作空间重建后最多晚 1.2 秒把标签补回来，察觉不到）；
- `DraftingStandardService.LoadProfile()` 按**文件时间戳**缓存解析结果；
- `ShortcutSettingsService.Load()` 同样按时间戳缓存；保存时主动失效。

缓存的是**解析结果（`Dictionary<string,string>`）而不是 profile 对象**——
`LoadProfile` 的调用方会就地改返回的对象（制图标准窗口就是先取一份再编辑），
如果发同一个实例出去，窗口里没保存的编辑就会污染"已保存"的缓存。
所以每次仍然新建 profile，只是不再读盘。

`ShortcutAliasService` 挂在 Idle 上的轮询同样加了 1 秒节流（它每次都要问一次文件时间戳）。

### 4.2 每次打开窗口都要开一次 DWG、枚举一次字体

- `ReloadArrowChoices()` → `GetArrowStyleChoices()` 会 `ReadDwgFile` 打开箭头图块库
  （几十到几百毫秒，库放在网络盘或云同步目录时更久）；
- `MakeTextTab()` → `GetAvailableFontFiles()` 要 `InstalledFontCollection`（建 GDI 上下文）
  并扫描 `ACADPREFIX` 里的所有支持路径。

两者都在**构造函数里同步执行**，也就是说窗口要等它们做完才显示出来。
各自按文件时间戳 / 进程内缓存一次即可：库文件换了会自动重读，字体在 CAD 运行期间不会变。

## 五、顺带修掉的 id 撞车

读代码时发现：图层命令的功能 id 前缀是 `layer_`，而固定功能里有一个 id 就叫
**`layer_assignment`（归层 GL）**。于是它被 `TryGetLayerKey` 认成"图层命令 assignment"：

- `ShortcutSettingsService.FixedFeatures` 把它当图层命令**过滤掉** →
  **归层的快捷键在"快捷键设置"窗口里根本改不了**；
- `DescribeLayerCommands` 把它当图层命令统计 → 日志里多出一条莫名其妙的 `GL→归层`。

前缀改成 `layerrole_`（id 只在本进程内用，图层快捷键本身是按图层键存在
`layer-shortcuts.ini` 里的，所以格式可以自由调整），并加了两道防线：

- 测试 `LayerLispTests.LayerFeatureIdsDoNotCollideWithFixedIds`：18 个固定 id 都不得被判成图层命令，
  且图层键本身叫 `assignment` 时也不能与固定功能混起来；
- `Build-Release.ps1` 构建期校验：从 `LayerFeatureIds.cs` 读出前缀，逐一检查 `FeatureRegistry`
  里每个 `F("id", …)` 都不以该前缀开头。

|---|---|
| `Shell/MenuService.cs` | 删掉按行裸发 `BPP` 的卸载；加一行刷新日志 |
| `Features/Shortcuts/LayerCommandLisp.cs` | 调用文本先抓预选集再传图层；新增 `SelectionFunctionName` |
| `Commands.cs` | 新增 `[LispFunction("WLSETSELECTION")]`；GL 优先用预选集；直达归层回执 |

| `Features/Shortcuts/FeatureRegistry.cs` | id 约定改为委托 `LayerFeatureIds` |
| `Features/Drafting/Views/DraftingStandardForm.cs` | 删掉"图层快捷键"页签；图层表加"快捷键"列；使用方移到行提示；字体清单缓存；禁用表头排序 |
| `Features/Drafting/Services/DraftingStandardService.cs` | 设置文件解析结果按时间戳缓存；箭头列表缓存 |
| `Features/Shortcuts/ShortcutSettingsService.cs` | 快捷键文件解析结果按时间戳缓存 |
| `Shell/RibbonService.cs` | Idle 检查 1.2 秒节流 |
| `Features/Shortcuts/ShortcutAliasService.cs` | Idle 轮询 1 秒节流 |
| `build/Build-Release.ps1` | 两个 LispFunction 注册校验 + 图层 id 前缀校验 |

顺带修掉一个潜在的数据错位：两个表格原来假设"行号 == `_profile` 列表下标"，
而 `DataGridView` 的文本列默认**可以点表头排序**——排一次序，保存时就会把 A 图层的参数
写到 B 图层上。现在统一禁止排序，快捷键的收集也改成按行上挂的图层对象取键，不再依赖行号。
