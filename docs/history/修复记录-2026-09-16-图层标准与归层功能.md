## 一、背景

用户提出的两条原则：

1. **每个图层都要真正有作用**；
2. **场景中同名图层的参数要按标准覆盖**。

排查后发现这两条当时**都没有做到**：制图标准里 17 个图层中有 9 个从未被任何代码使用；
图像转 CAD、门窗立面、大样排版、楼梯大样四个模块各自写死图层名，完全绕过标准。

## 二、新增功能

### 2.1 归层（`GL`，别名 `WLLAYER`）

把所选对象归到指定图层。

| 能力 | 说明 |
|---|---|
| 对话框选层 | 默认**只显示制图标准里定义的图层**，可切换为当前图纸全部图层；支持关键字筛选、双击确认 |
| 设为随层 | 默认勾选。只改 `LayerId` 时，对象上显式指定过的颜色不会跟着变 |
| 块属性归层 | 默认勾选。块参照的属性位于宿主空间，需单独归层 |
| 整层合并 | 把所选对象所在旧图层上的**所有**对象并入目标层，并清理**确实清空**的旧图层 |
| 自动建层 | 目标图层不存在时按标准创建，无需先手工建层 |
| 锁定保护 | 目标层锁定/关闭/冻结时执行前拦下；对象所在层锁定时跳过并计数 |

整层合并只删除确实清空的图层；仍有对象或被 Xref 引用而无法删除时保留并在提示中说明。
执行前弹确认框列出将合并的图层，操作可用 AutoCAD 撤销。

### 2.2 每图层独立命令

在 `BZS` 面板新增的“图层快捷键”页为每个图层登记直达命令。

关键实现：**任意数量的图层共用一个 `GL` 命令**。

```lisp
(defun c:GC () (setenv "WANLUO_TARGET_LAYER" "WL_楼梯_轮廓") (command "GL") (princ))
```

目标图层经环境变量传入，`GL` 读到即归层、不弹对话框，读完立即清空
（所以同一次会话里后续的手动 `GL` 照常弹窗）。这样无需为每个图层注册
`[CommandMethod]`，`Build-Release.ps1` 的“登记表命令必须已注册”校验依然通过。

- **留空的图层不生成命令**，从根上不与现有功能抢快捷键。
- 图层快捷键与固定功能快捷键**分开校验唯一性**，两套命名空间互不干扰。
- 快捷键存储：`%APPDATA%\...\通用设置\layer-shortcuts.ini`。

### 2.3 图层角色表

`DraftingLayerRoles.cs` 为 23 个图层登记分组与**使用方**：

- 界面上可见每个图层被谁使用（“图层快捷键”页的“使用方”列）；
- 测试上把“无人使用”变成**断言失败**，避免再次出现装饰图层。

## 三、图层标准真正生效

原先各处写死图层名，现全部改为按标准取层：

| 模块 | 原状 | 现状 |
|---|---|---|
| 图像转 CAD | 7 个 `LV-*` 及颜色写死，文字用图形默认样式 | 按标准取层；文字改用标准“标注”样式 |
| 门窗立面 | `WL-门窗-窗/门/开启洞口`，标准里没有 | 3 个键已加入标准并按标准取层 |
| 大样排版 | `WL-大样-分隔/索引`，标准里没有 | 2 个键已加入标准并按标准取层 |
| 楼梯大样 | 14 个图层名 + 文字样式 + 标注前缀写死 | 经 `DraftingStandardBridge` 只读读取标准 |

楼梯是独立程序集且不保证主插件已加载，因此桥接**直接读文件**而非反射调用。
**读不到 / 格式不认识 / 缺项一律回退内置常量**，行为与改造前一致，不会因标准不可用而出不了图。
同时识别新格式（`LayerItem.N.Key`、`Text.N.Key`）与旧格式（`Layer.<Key>.Name`）。

`EnsureLayerFor` 默认 `updateExisting:false`：只补齐缺失图层，不改动用户图纸里
**已存在**的同名图层；需要覆盖时走 `BZS` 面板的显式路径。

## 四、修复的既有问题

| 问题 | 原因 | 处理 |
|---|---|---|
| `-Bands R24,R25` 被拒绝 | `[string[]]` 把 `R24,R25` 按单个元素绑定，脚本只 trim 未拆分 | 按逗号拆分（`Build-Release.ps1` 与 `Build-CadArchSpecPayload.ps1`） |
| “同步更新同名图层”不生效 | `ApplyConfiguredLayers` 以 `CreateOnApply` 整体过滤 | 改为创建/覆盖分别判断；新增 `SyncExisting`（默认 `true`，旧配置行为不变） |
| 快捷键不能含连字符 | 正则只允许字母/数字/下划线 | 放开 `-`，提示文案补全 |
| 楼梯 R24 工程无法独立编译 | `WL.Stair.Cad2024` 漏 include `WanluoDataPaths.cs` | 补上（该工程未进解决方案，缺陷长期未暴露） |
| 新增图层键老用户拿不到 | `EnsureRequiredStairLayers` 只按 `Stair` 前缀补齐 | 抽为通用 `RefreshRequiredLayers`，并对 `DoorWindow`/`Detail` 补齐 |
| 发布清单含本机明文路径 | `ApiPath` 写入构建机安装目录 | 改为只记 `ApiSource`，路径仅打印在控制台 |
| 两个测试工程编译不过 | 依赖未随代码更新纳入工程 | 按既有 stub 模式补齐 |

## 七、已知限制

1. **楼梯的标准缓存**：图层名与文字样式在类型初始化时解析一次，
   在 `BZS` 中改名后需重载插件或重启 CAD 才对楼梯生效（主插件自身是每次实时读取）。
2. **载荷 zip 非确定性**：即使源码未改动，`StairDetail.R24/R25.zip` 与
   `CadArchSpecEditor.bundle.zip` 每次重建都有少量字节差异（已排除时间戳），
   因此跑完发布脚本工作区总会显示这三个文件被修改。根因（疑与程序集签名密钥容器有关）未查。
3. **版本号两套并存**：`Shared/ProductVersion.cs` 为 `1.5.6`，
   而 GitHub Release 走 `v9.x`（上一版发布时源码为 `1.4.5` / tag 为 `v9.1.0`），二者尚未统一。
4. **图层面板未按参考截图重做**：数据层（系统标签、使用方、每图层快捷键）已就位，
   但图层表的视觉形态与“智能匹配/批量绑定/解析图层”三个按钮尚未实现。
