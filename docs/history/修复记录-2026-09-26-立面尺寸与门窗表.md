## 一、这一轮做了什么

立面上多了**尺寸**，还多了一张**门窗表** —— 两者都是现算的，不是画上去的死图。

### 1. 竖向尺寸：两条链 + 总高

| 位置 | 内容 |
|---|---|
| **左侧（贴建筑）** | 每层一条**洞口定位链**：从该层楼面起，把这一立面上所有洞口的**窗台高/洞口顶**排序后连成一条连续尺寸（样例一层：900 / 1200 / 600 → 0-900-2100-2700；二层：900 / 1800） |
| **右侧** | **层高链**（每层一条：3600 / 3300）+ **总高**（0 → 6900） |

两条硬规则：

1. **只标这个立面上的门窗**：先把"朝观察者的那一道最近外墙"找出来（墙轴与视线垂直 + 该层深度最大），
   背面的窗绝不混进南立面的尺寸链（这条在测试里钉住了）；
2. **数值不写死**：`ViewDimension.Text` 留空，落图时由 CAD 按实际距离**自己量**——
   模型改了、视图重算，数值自动跟着对，不会有"改了模型忘了改尺寸"的问题。

CAD 侧这些是**真的标注对象**（`RotatedDimension`，可拉伸、可改数值位置），
标注样式走插件统一的 `DraftingStandardService.EnsureDimensionStyleForScale(1:N)`
（与门窗立面、楼梯大样用的是同一套"万落建筑工具 1:N 标注样式"）；样式创建失败时退回当前样式并提示。
预览里按"界线 + 尺寸线 + 建筑标记 45° 斜短线 + 数值（竖直尺寸文字竖排）"画出来。

### 2. 门窗表：按编号汇总，做法来自类型库

新增一种视图类型 `ViewKind.Schedule`（表格也是"视图产物 = 线 + 文字"，所以 `LTTZ` 落图不用特殊处理），
`OrthographicProjector.ProjectSchedule(model, library, title)` 现算：

```
编号   类型   洞口尺寸     窗台/落地   樘数   做法（分格 / 开启）
C1215  窗     1200×1500   900        2     单扇 / 右平开，铝合金
C1518  窗     1500×1800   900        2     双扇等分 / 双向推拉，铝合金
M0921  门     900×2100    落地        1     单扇 / 左平开，木质
M1500  门     1500×1800   落地        1     类型库里没有这一条
M1524  门     1500×2400   落地        1     双扇等分 / 双扇平开，玻璃
```

（上面这张是**你现在样例工程里的真实内容** —— 那樘 `M1500` 是你在程序里画的，库里没有，表里如实写出来。）

程序里「生成全部视图」会一并写出 `views/schedule.json`；预览页签的下拉框里也多了「门窗表」这一张，
可以点开直接看，`--snapshot` 也会出 `门窗表.png`。

## 二、核实过的事实

**单元测试**（新增第 8 组，数值全部手算核对）：

```
尺寸与门窗表：层高 2 段 + 总高 6900、一层定位链 3 段（0-900-2100-2700）、门窗表 3 行（宽 14800）
PASS 立面门窗：… / 可点选锚点与编号 / 尺寸与门窗表
```

断言包括：层高尺寸 0→3600 与 3600→6900 且都画在 `maxU+2000`、总高 0→6900 在 `maxU+3000`、
一层定位链三段的位置与 `minU-1200`、**尺寸文字必须留空**（交给 CAD 量）、
门窗表表头齐全、`C1215/C1518` 各 2 樘 `M0921` 1 樘、做法列来自类型库、表宽 14800（各列之和）；
中间格式往返也加了"尺寸不丢"。

**预览自检**（离屏真画，要求画出的线/文字/尺寸数与视图数据完全一致）：

```
PASS 预览 南立面图：线 63（门窗 43）、文字 7、尺寸 8、填充 0
PASS 预览 北立面图：线 29、文字 7、尺寸 7        PASS 预览 东/西立面图：尺寸 5
PASS 预览 1-1 剖面图：线 28、文字 3、尺寸 3、填充 7
PASS 预览 门窗表：线 12、文字 25、尺寸 0
PASS 立面预览自检全部通过（5 张视图 / 极端变换 / 坏数据 / 坏 Graphics）
```

另外修了一处预览取景：**尺寸线比建筑轮廓还靠外**（左 −1200/−2000、右 +2000/+3000），
原来不算进取景范围，会被裁掉；现在尺寸也算进去，两条链与总高完整可见。

**人眼核对**：临时干净样例（`%TEMP%\WanluoCleanSample`）的南立面快照上，
左侧 1F 读到 `900 / 1200 / 600`、2F 读到 `900 / 1800`，右侧 `3600 / 3300 / 6900`，
标高 `±0.000` 与 `3.600`、门窗编号 `C1518`×2 / `C1215` / `M0921`、图名齐全；
门窗表快照与你工程里的 5 种编号逐行对上。

**发布**：`Build-Release.ps1 -Bands R24,R25`（R24/R25 都通过；尺寸用的 `RotatedDimension` 与
`DraftingStandardService` 在两个版本都能编）。

## 三、已知边界（下一步）

1. **水平尺寸**（洞口定位的横向尺寸链）已有数据模型（`ViewDimension.Vertical=false`）但立面还没生成，
   下一步随"平面出图"一起做；
2. 门窗表目前是**整栋汇总**，还没做"分楼层统计/门窗表页"与图框排版（P5 的图框分页）；
3. 尺寸链是"每层一条"，同层多个不同窗台的洞口会合成一条连续链（这是常规做法），
   但如果一层里洞口标高很碎，链条会很长 —— 需要"按窗台分组"时再加策略（P5）。
