# 修改门高闪退修复

## 证据与原因

- Windows Application 日志记录 2026-10-05 19:28:23，原安装目录的 `万落建筑模型.exe` 因未处理的 `InvalidOperationException` 退出。
- 原始消息为“存在超出窗框或尺寸过小的分格”。调用链为 `ValidateCellLayout -> CreateCells -> Build -> OpeningPlanGeometry.DirectionHandle -> LocalDirectionHandle -> DrawOpeningGrips -> Render`，发生于 Avalonia 渲染更新。
- 属性栏按输入值延时预览。原 `TrySetOpeningGeometry` 仅验证洞口和宿主墙，未验证缩放后的门窗构造；例如 2500 改为 2100 时可能先产生 2、21 等输入状态。测试已复现这些值被原事务接受。尚未收到用户对当时所在窗口和输入数值的确认，不能认定该输入序列就是原事故的唯一来源。
- 同一构造异常也可能在平面符号和预选区域更新时出现。`SetModel` 先替换画布模型再生成符号；异步预览外层捕获不能保护之后独立执行的渲染回调。

## 修改范围

1. 洞口参数事务在提交和预览前调用共享构造校验，拒绝安装缝、分格和框料不相容的尺寸；拒绝后不修改模型和撤销历史。
2. 实例尺寸仍由既有适配器缩放分格，不覆盖共享类型的原尺寸和分格定义。
3. 平面符号、预选区域、方向夹点和拖动预览分别捕获预期几何异常。坏分格不再进入未处理渲染异常；不伪造门扇，保留洞口区域选择，并写 Trace 诊断。该保护不是自动修复已有损坏类型，也不等同于整个应用的全局异常恢复。
4. 新增纯逻辑和真实 Avalonia 属性输入回归。无新依赖；版本保持 1.5.6。

## 验证

- 核心模型测试通过：自定义双扇加上亮、安装缝、无效高度回滚、2100 有效高度、类型隔离、平面/方向夹点/预选区域/三维构造、一次撤销与重做。
- 构件参数资源包测试与 CAD 逐层登记测试通过。
- 900x650 属性窗口检查：逐次输入空值、0、2、21、2100；预览不改原模型，应用一次撤销，取消恢复；主动构造超界分格并检查真实组合渲染和移动预览保护。
- 1440x920 原门窗操作检查通过，包含移动、左右内外方向、右键居中、距离输入、编号夹点、预选和 25 个 MM 模板。
- 测试必须分别运行。`--opening-plan-check` 会替换样例为无楼板的门窗图库，不能把依赖原房屋楼板/同编号实例的 `--parameter-check` 与 `--opening-editor-check` 紧接着并入同一进程；本次组合运行出现测试夹具不相容，随后改为独立运行。
- 模型程序、R24 和 R25 编译通过。现有 Avalonia 分析器版本及 Bitmap.Save 过时警告未改动。CAD 内实机复测和原事故输入复现仍待用户测试。
