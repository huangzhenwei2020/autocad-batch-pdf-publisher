# 建筑模型三维预览替代方案与图标清晰度检查（2026-09-27）

## 当前问题与已做的低风险修复

- Ribbon 图标原来无论屏幕缩放都按 32×32 像素、96 DPI 输出，Windows 150%/200% 缩放时必须放大该位图。本次改为物理 64×64 像素、192 DPI，逻辑尺寸仍为 32 DIP；小图标 32×32 像素、192 DPI，仍为 16 DIP。新建模图标和旧图集同样处理。原图集本身带柔光，清晰度不会等同于纯线条图标。实际 CAD/T20 多显示器检查仍需用户界面验收。
- `VolumeCanvas` 在一次鼠标移动中计算投影、随后的绘制中再计算相同投影。现改为按三维体量引用、方位角、仰角、透视和剖切参数缓存结果；缩放和窗口重绘复用结果，视角变化重算一次。自检验证同角度连续两次绘制投影次数不增加，相机变化只增加一次。
- 当前三维不是显卡场景：`BuildingVolumeBuilder` 产出多边形，`VolumeRenderer.Project` 在 CPU 上做投影、近面判断、逐段消隐，`VolumeCanvas` 用 GDI+ 画每块面。临时基准（本机、Release、只计 Project、每组 5 次取中位数）：276 面约 7 ms、552 面 17 ms、1104 面 47 ms、2208 面 86 ms。场景是样例建筑沿 X 平移复制而成，不能外推为所有实际工程；屏幕绘制和模型构建不在这些数字中。数千面时单靠缓存仍难保证顺滑。

## 可替代路径

| 路线 | 与当前程序的适配 | 获得的能力 | 代价/限制 |
| --- | --- | --- | --- |
| OpenTK 4 + GLControl | 直接放进现有 .NET 8 WinForms `TabPage`，改动窗口结构较小 | OpenGL GPU 三角形渲染、深度缓冲、交互相机 | 要自己写网格上传、材质、相机、拾取、透明和剖切；工作量在我们项目侧。官方 WinForms 控件及 MIT 许可：[GLControl](https://github.com/opentk/GLControl)。 |
| HelixToolkit.Wpf.SharpDX v3 | 使用 `ElementHost` 在现有 WinForms 三维页嵌 WPF 视口；后续也可整体迁移 WPF | DirectX 11 场景、相机控件、3D 命中测试与材质基础设施 | 需要 WPF/SharpDX 依赖，并重点验证跨屏 DPI、启动速度、显卡兼容与宿主嵌入；不是直接替换当前画布 DLL。v3.1.2 包兼容 .NET 8 Windows：[NuGet](https://www.nuget.org/packages/HelixToolkit.Wpf.SharpDX)、[视口 API](https://helix-toolkit.github.io/helix-toolkit/api/HelixToolkit.Wpf.SharpDX.Viewport3DX.html)、[命中测试 API](https://helix-toolkit.github.io/helix-toolkit/api/HelixToolkit.Wpf.SharpDX.ViewportExtensions.html)。微软提供 WinForms 承载 WPF 的 [ElementHost](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.integration.elementhost)。 |
| OCCT + IFC 工具链 | 适用于以后替换实体建模和 IFC 交换，而非只解决拖动预览卡顿 | 布尔运算、精确实体及 IFC | C++/原生依赖和数据转换成本大；不应把渲染迁移与实体内核迁移绑在一起。[OCCT](https://dev.opencascade.org/sites/default/files/pdf/Preliminaries.pdf)、[IfcOpenShell](https://github.com/IfcOpenShell/IfcOpenShell)。 |

**建议：先做独立 HelixToolkit.Wpf.SharpDX v3 试验页**。它更契合“直接编辑模型”：项目已经有带 ID 的墙、板、柱、楼梯等参数对象；试验页可以先用每个构件 ID 对应一份三角网格和拾取目标，实现旋转、缩放、点选、楼层隐藏和水平剖切。将同一场景与 OpenTK GLControl 小样比较，若 Helix 嵌入/发布包/DPI 成本过高，再选 OpenTK。不要立即删除当前体量画布；试验页失败时仍能使用旧视图。

已用独立的 .NET 8 Windows 小程序验证 `HelixToolkit.Wpf.SharpDX 3.1.2` 能还原依赖，并能在 WinForms `ElementHost` 中构造 `Viewport3DX`。这只证明程序集和窗口承载可行；没有运行真实建筑网格、CAD 宿主或跨显卡测试，不能据此宣称交互速度合格。

图纸生成仍应从 `BuildingModelDocument` 的参数和正交投影/制图规则计算，不能把显卡屏幕截图当立面/剖面 DWG。显卡预览解决实时交互和遮挡，精确落图、更新 CAD 视图与建筑实体几何属于不同层。

## 替换验收

1. 用相同参数模型生成 276、约 2000、约 10000 面场景，分别在核显和独显机器记录首帧、旋转时 P95 帧耗时、内存/显存与图元数量；交互目标 P95 < 33 ms（约 30 FPS），不能把数字理解为已实现。
2. 同一相机/剖切参数下比较墙、洞口、玻璃、楼梯与屋面的可见性和点选 ID；验证透明玻璃不会造成墙体穿帮。
3. 在 100%、150%、200% Windows 缩放、跨屏拖动、睡眠唤醒、远程桌面及低端显卡上验证视口恢复；GPU 初始化失败有可见错误和 CPU 旧视图回退。
4. `.NET 8` 独立建模程序发布包运行；CAD 插件 R24/R25 的加载和 DWG 输出流程保持通过。

当前代码修复与自动自检不等于新引擎已经接入；替代方案需要先用真实项目模型做试验与实测。
