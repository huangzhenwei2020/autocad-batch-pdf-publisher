# 建筑模型网格、CAD 比例与显示编号修复

## 实现与验证

- GLB 墙面在同一楼层、同一构件、同一平面和法线范围内先求并集，去掉内部网格边与共线点，再由 LibTessDotNet 三角剖分。非墙构件不做跨面的合并，避免改变窗框等叠合构件。
- 两层样例三角面数量由 1588 减至 464；GLB 文件 38252 字节。Blender 5.2.1 实际导入并重新导出，16 个构件、2 个楼层，包围尺寸 7.44 × 5.64 × 6.9 m，窗洞射线检查及表面积、法线检查通过。
- L 形相邻墙回归：宿主墙开窗前后，未开窗邻墙都为 10 个三角面，不受宿主墙洞口的全局切分影响。
- CAD 生成采用 `ComposeModelSpace`：建筑保持真实毫米，图框按比例分母放大。1:1、1:50、1:100、1:200 自动检查通过；混合比例仍保持建筑原尺寸并提示统一图框比例。`Compose` 仅保留纸面预览/旧回归用途，不用于正式落图。
- 旧纸面缩放图纸禁止直接落图，需重新生成；不能从带显式尺寸文字的旧图纸猜测原建筑尺寸。
- R24 使用本机 AutoCAD 2022 API 与已安装的 .NET Framework 4.8.1 引用程序集编译，无警告/错误。隔离 AutoCAD 2022 命令行宿主实测：6000 mm 墙线、42000 mm A3 图框、真实测量 6000 mm 标注通过。
- 宿主测试把制图规范图层重命名为 `QA-*`；墙线、门窗细线、图框和标注都落在对应自定义图层，生成实体均未绕过规范。颜色、线宽、线型按层；保留已存在图层参数，沿用标准服务的默认策略。
- 墙增加持久化显示编号 `Code`，与内部 `Id` 分离；新建、分墙、复制后补齐唯一短编号。项目浏览器与 Blender 节点显示“墙 W-编号”；门窗只显示 `Code`。内部 UUID 与标准层来源 ID 仍在元数据中。
- 公共几何/编辑回归及 GLB 测试通过；复制编号唯一、保存重开编号稳定。Avalonia 1100×720 实际截图检查短编号与门窗编号可见，GPU 拾取检查通过。

## 边界

- GLB 本身为三角网格，必要的对角线仍会存在；本次去掉的是无关墙洞口造成的密集格线，不承诺全四边面拓扑。
- 已登记项目图框的放大倍数与比例属性代码已修正，但本次 CAD 宿主实测使用自动图框，未覆盖全部用户登记图框及复杂真实项目。
- SketchUp DAE、3ds Max OBJ/MTL 与后续 FBX 已列入互通计划，尚未实现或实机验收。
- 首次命令行宿主已输出 `CAD_MODEL_SCALE_QA_OK`，但脚本末尾缺少空行，退出时停在 DWT 保存确认；终止该测试进程后补齐脚本末尾，再次执行验收通过并正常以退出码 0 结束。宿主退出有临时文件清理权限提示，不影响几何检查。没有修改用户 DWG 或正式项目配置。测试工具为 `build/Test-BuildingModelCadScale.cs` 和 `.scr`，必须设置独立 `WANLUO_USER_DATA_ROOT`。
