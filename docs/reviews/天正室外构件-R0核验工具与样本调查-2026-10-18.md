# 天正室外构件 R0 核验工具与样本调查

日期：2026-10-18。版本：**1.5.6**。状态：**核验工具已实现；R0 样本适配进行中，未覆盖安装**。

对应 [开发计划](../plans/天正室外与屋面构件识别及栏杆绘制-开发计划-2026-10-18.md)。本轮不表示五类构件已能生成模型，也不表示栏杆绘制或新登记 UI 已交付。

## 1. 已实现的源码

- 扩展现有“天正字段核验”为构件核验，仍从建筑模型工作台“更多 → 天正字段核验”进入，不新增功能区入口。
- 核验窗口增加“原始几何”页，可切 XY/XZ/YZ，保存用户指定的对照类别；该类别始终是核对标签，不自动成为已确认的导入语义。
- 记录实际 DXF/RX 类型、CAD 版本、INSUNITS、原始路径、局部顶点、有向 bulge、法向和局部到图纸的变换；预览点为图纸坐标，不能用来反推精确建模轮廓。
- 临时副本分解释放资源；块参照直接只读遍历定义并累积矩阵，避免先炸开大块、分配全部子对象后才检查上限。限制深度、路径和顶点数，超限/未支持均明确记录，缺字段的旧核验 JSON 可打开。
- 去掉旧诊断路径的通用 COM 属性试读；登记与诊断共用明确白名单，未核验类型不调用 COM 属性。阳台白名单只纳入本轮实际读取并对照过的标量字段；散水仍不扩大正式白名单。
- 新增元数据读取和 CAD 私有副本清单工具。元数据使用 `LoadTypeLibEx(REGKIND_NONE)`，不注册 COM、不实例化厂商对象、不调用接口成员。

主要代码：`CadBuildingObjectProbe.cs`、`TianzhengBuildingProbeService.cs`、`CadBuildingDiagnosticGeometry.cs`、`TianzhengBuildingProbeWindow.cs`。测试及诊断入口位于 `BatchPdfPublisher.Tests` 和 `build`。

## 2. 实际样本与环境

用户指定了住宅楼与社区商业楼方案图，并允许使用天正功能补样本。本轮只复制该 DWG，再用只读侧数据库核对；用户原图未打开为编辑文档、未保存或覆盖，前后 SHA256 一致。图纸副本、坐标、原始核验 JSON 和本机元数据报告不提交仓库。

实际调查环境为 **T20 天正建筑 V9.0 + AutoCAD 2022**。控制台环境下对象仍为代理，即使尝试加载内核也未恢复原生对象；这只证明代理身份存在，不能算原生几何读取成功。随后启动完整天正的空白会话，侧数据库读取相同私有副本，阳台和散水恢复为原生对象，几何可读取。调查前后空白文档 DBMOD 相同。

用户图纸包含的相关原生定义对象：

| 实际对象 | 本轮证据 | 尚待确认 |
|---|---|---|
| `TCH_BALCONY / TDbBalcony` | 32 个定义对象；抽样原始几何可读，全部阳台样本的指定标量属性可读取 | 精确板边/栏板边的对应、各种阳台形式、组合语义与模型生成 |
| `TCH_APRON / TDbApron` | 1 个定义对象；抽样 60 条显示几何，指定原始字段可读取 | 内外高度、地坪、厚度和坡面之间的准确关系；文本宽度的分段语法 |
| `TCH_WALL / TDbWall` | 存在 800、1800 等低墙高度；原有已验证字段可读 | 不能仅凭低墙高度确定女儿墙，仍需屋面上下文或人工确认 |
| 屋面泛水 | 本次类别清单未发现可独立确认的泛水对象 | 不能据此断言图纸没有泛水，可能以普通线/其他构件表达；需继续屋面核对与天正补样 |
| 独立栏杆 | 本图未核验到独立栏杆类型；阳台含栏板参数 | 不把阳台自带栏板当成已验证的路径栏杆接口 |

上述数量来自模型空间及内部块定义遍历，**不是标准层展开数量、三维构件数量或工程统计结果**。

## 3. 字段含义的发现

本机类型库中确有 `IComBalcony`、`IComApron`、`IComHandRail`、`IComRail`、`IComWall` 等接口；只有元数据声明的字段不自动进入白名单。

- 阳台 `Elevation` 在类型库说明中为地面高差，天正绘制窗口显示地面标高；须作为相对楼层的参数继续校验，不能用显示几何 Z=0 覆盖它。
- 阳台 `RailWidth`、`RailHeight`、`SlabThickness`、`GirderThickness` 为独立参数；`HasGirder` 在样本中是“无”等文本，不是 CLR 布尔值。
- 临时空白图实际执行 `TBalcony` 创建阳台，绘制窗口与对象接口读数对应：地面 -100、栏板宽 100、高 1000、板厚 100。只在测试文档创建一个对象，核验后不保存关闭。
- 散水 `InHeight`、`OutHeight`、`Elev` 在样本中是数值；`Dists`、`PathLength` 是格式化文本，`CloseFlag` 为“否”，`Vertex` 为空。通用读取器保留原始类型，不能强行把任意字符串当尺寸、把非空字符串当 true。
- 天正 `TOutlna` 实际调出散水工具，有散水宽度、室内外高差、偏移和绕柱/阳台选项。但创建工具的室内外高差与对象 `InHeight/OutHeight` 的对应还未完成受控验证，不能把两者混为同一参数。
- 阳台和散水的显示几何均可能是平面 Z=0 的表达；真实构件高程和做法必须结合字段，不按包围盒直接拉伸。
