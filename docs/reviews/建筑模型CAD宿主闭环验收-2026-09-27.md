# 建筑模型 CAD 宿主落图闭环验收

日期：2026-09-27。宿主：本机 AutoCAD 2024 `accoreconsole.exe`，临时 DWT 与临时项目；插件使用 R24 构建。用户正式项目、DWG 和项目配置没有参与测试。进程通过 `WANLUO_USER_DATA_ROOT` 指向独立用户数据目录。

## 结果

| 步骤 | 实测结果 |
|---|---|
| 建模程序格式生成视图并标记待落图 | 14 个视图，5 张图纸待落图 |
| 执行 `LTTZ` 选择第一张图纸 | 真实 CAD 实体创建成功，约 141 个生成实体；待落图由 5 减到 4 |
| 同一图纸再次选择“更新位置” | 模型空间实体总数保持 150（包含后来画的一条手工线），没有重复叠图 |
| 从源视图 JSON 删除一条线后更新 | 模型空间实体总数 150 → 149；生成图元按新视图替换 |
| 在 CAD 执行 `U` | 实体总数 149 → 150，上一版图元恢复 |
| 更新后核对手工线 | `(10000,0)` 到 `(10100,0)` 的手工 LINE 仍存在 |

发布包 R24/R25 构建和随包自动检查通过。实际宿主测试只在 AutoCAD 2024 / R24 上运行；R25 仍是编译验证。测试视图没有登记项目图框，因此 AutoCAD 使用视图自带 A3 图框。未覆盖交互式 AutoCAD/T20、已登记图框、多个放置实例、跨机器迁移、DPI/显卡和复杂真实项目。

## 发现与修正

完整插件原本在命令行宿主 `NETLOAD` 时发生 `StackOverflowException`；改动前旧 DLL 同样复现。最小 .NET 插件可正常加载，定位到完整插件的无界面初始化路径。`Commands.Initialize` 和 `Terminate` 在 `accoreconsole` 中跳过 Ribbon、菜单及其他 UI 生命周期服务；CAD 命令本身仍被注册，`LTTZ` 可执行。正式 R24 发布 DLL 再次加载、更新并以退出码 0 结束。

`UserDataPaths` 新增显式 `WANLUO_USER_DATA_ROOT` 进程环境变量，供隔离集成测试和便携部署使用；未设置时仍使用原用户配置目录。测试进程通过该变量读临时项目，避免触碰用户的当前项目。测试过程中一次脚本把坐标误送给“更新/另插”序号提示，宿主持续等待；修正输入为 `1` 后按预期完成，确认不是视图生成循环。

## 后续门槛

在正常 AutoCAD 图形界面中，用一个复制的真实项目验证多个放置实例、人工补绘保留和登记图框；再用 AutoCAD 2026 对 R25 做相同宿主复测。通过前不把命令行样例验收称为全部真实项目验收。

## AutoCAD 2022 复测

用户改以 AutoCAD 2022 为当前目标后，使用本机 `C:\Program Files\Autodesk\AutoCAD 2022\accoreconsole.exe` 和 AutoCAD 2022 API 重新构建 R24。测试仍使用独立的 `.artifacts/cad-2022-smoke` 项目、进程级 `WANLUO_USER_DATA_ROOT` 和 2022 自带样板复制出的临时 DWG；没有打开正式项目。

| 检查 | 2022 实测 |
|---|---|
| `LTTZ` 首次落图 | 临时 DWG 原有 7 个实体，落图后 147 个；待落图 5→4 |
| 新增手工 LINE 后更新同一视图 | 148→148，无重复叠图 |
| 源视图删除一条线后更新 | 148→147；坐标 `(10000,0)` 到 `(10100,0)` 的手工 LINE 仍存在 |
| 执行 `U` 撤销更新 | 147→148 |

两次 2022 宿主脚本均以退出码 0 完成。首次测试用 DWT 调用 `QUIT` 时停在保存确认提示；后续改用临时 DWG，并在退出前执行 `QSAVE`，此时能正常结束。这个差异属于测试脚本的文件/保存方式，并未观察到插件落图故障。发布脚本现在优先选本机 AutoCAD 2022 的 R24 API，也可用 `-R24AutoCadYear 2022` 显式指定；仍需在图形界面和真实复杂项目中继续验收。
