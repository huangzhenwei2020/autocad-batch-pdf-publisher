# 洞口超高与编号反馈

日期：2026-10-06。接续 [尺寸、编号及重名决策](洞口尺寸编号与修改范围-2026-10-05.md)，不改变既有编号和标准层规则。

## 原因

用户截图输入窗 C0722 的洞口 900×2600 mm、窗台 800 mm。只读核对当前山水湾保存模型，原窗仍为 700×2200 mm，宿主 W-3 随楼层高 3000 mm，定位 747.89530825003 mm。

800+2600=3400 mm 超出 3000 mm，尺寸事务实际没有提交。预览绑定此前只返回 bool 并吞掉校验原因，导致旧模型及 C0722 保留、属性输入却显示新尺寸，容易误以为尺寸已经修改但编号没更新。

## 修复

- 洞口预览保留完整校验错误，在输入区附近和状态栏显示具体数值、可用高度及“未应用；当前模型仍为 C0722”。输入原值保留，不自动缩小或提升墙高。
- 计划编号随尺寸草稿更新；字段明确为“计划编号”，下方注明未应用，禁止单独提交草稿编号。无效草稿禁用应用按钮，避免仍然只改编号。
- 有效草稿之后输入无效数值时，清除前一份有效预览、恢复已提交模型和三维场景，不能继续留着过时预览。
- 完整数值修正后自动清除错误、恢复可应用状态。按原范围和重名规则，真实洞口、分格及编号一次提交，Ctrl+Z 一次恢复。Esc 只取消未提交草稿。
- 本例保持窗台 800 / 墙高 3000 时，洞口高最多 2200 mm；900×2200 可以提交为 C0922。若确需 2600，应由用户调整墙高或窗台等实际参数，不自动改这些值。

## 验证

- 核心模型完整回归通过，新增截图数值夹具：超高整笔拒绝且零撤销记录；900×2200 与 C0922 一起应用及撤销。
- 原生窗口 1440×920 / 900×650 参数回归通过：错误/计划编号、纠正输入、整笔应用、有效后无效的场景恢复、Esc 与 Ctrl+Z；原有单樘/整组、重名合并/后缀及门高闪退检查仍通过。
