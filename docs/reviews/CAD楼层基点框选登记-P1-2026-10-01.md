# CAD 楼层、基点与框选登记

日期：2026-10-01。这是正式模型导入前的登记核对阶段。下一步已加入 [门窗补充定位](CAD门窗补充定位-P1-2026-10-01.md)，该功能的范围和实测限制以该记录为准。

`WLMCREGISTER` 或 `JZMX → CAD 楼层登记核对`：

1. 在建筑模型中完成楼层设置并保存，选择该模型文件。
2. 选择独立楼层，查看名称、标高、层高和标准层来源。引用标准层不能另行登记，须登记其来源层；来源层的引用楼层随清单保存。
3. 输入统一模型基点 XY 和源图单位倍率，例如毫米图纸为 1。各层应使用相同模型基点。
4. 在 CAD 拾取对应的轴线交点作为源基点，再沿模型正 X 方向拾取第二个点。
5. 用两个角点框选本层平面。采用交叉多边形选择，保留范围相交的完整墙，不裁短源对象；保存实际 WCS 范围多边形。
6. 核对门窗洞口，选择对应立面记录，读取本层名称匹配的已保存门窗表离地高度，显示窗底模型标高，勾选并确认单位后保存清单。

## 数据与限制

- 源 CAD UCS 拾取点转换到 WCS；倾斜 UCS 暂不支持。框选保留原始墙参数和曲线采样，门窗宽高换算为毫米；定位变换和逆变换保存至清单。
- 框选最多 5000 个墙门窗对象，超限明确拒绝，不截断；探针仍限 100 个。仅使用已验证的墙、洞口属性白名单。
- 标准层保留各个引用层身份、层高和标高。当前门窗核对针对来源层；逐引用层离地高度差异未实现自动套用。
- 当前须打开已有模型设置楼层；登记窗口尚不提供新建/编辑楼层。统一模型基点暂由用户保持一致，跨次登记自动复用/一致性校验尚待实现。
- 天正门窗编号仍未完成原生自动读取；位置和宿主墙尚待验证。因此保存的是核对清单，包含墙候选，不能作为 model.json 打开，也没有创建可编辑构件。
- 门窗表以本次所选楼层名称匹配，名称不一致时不会猜测对应楼层。标准层名称别名映射、编号标注对象关联、准确定位与宿主核验、模型侧批量导入/撤销是后续步骤。

## 验证

自动测试覆盖：地下层与标准层楼层列表、引用层阻断、楼层快照、方向点重合阻断、方向点映射正 X、跨层旋转与大坐标、单位换算、逆变换、墙单独登记、上下文序列化、最小窗口按钮与表格布局、门窗表优先级及缺失/冲突状态。CAD2022 插件编译通过。

实机验证使用 AutoCAD2022 / T20 天正建筑 V9，加载发布目录中的 R24 插件，对 DWG 测试副本执行 `WLMCREGISTER`：

- WPF 楼层窗口正确显示地下层、一层和引用一层的二层；选择引用层继续时明确阻止重复登记。
- 选择一层后，依次完成源基点、方向点和矩形框选，进入门窗核对窗口。该范围读取 246 面墙、110 个门窗洞口，共 356 个对象；核对窗口显示一层标高 0 和一个标准层引用。
- 门窗宽高能显示，但编号仍为空，未以尺寸推测编号。关闭核对窗口可返回 CAD，没有保存清单或创建模型。
- 退出自行启动的 CAD 测试实例时选择不保存；原图与测试副本的 SHA256 均保持 `2FA058783E7426140CD2F4BF22A8D651C55F5C3E87D27B736ACC6A04B9F587B5`。

本次实机只验证一个楼层的交互闭环和取消操作，没有实测跨楼层轴线交点对齐、旋转 UCS、非毫米源图或核对清单保存。相关变换与序列化已有自动测试，但仍须补充对应天正宿主案例。UCS 转换依据 [Autodesk 官方示例](https://help.autodesk.com/cloudhelp/2027/CHT/OARX-DevGuide-Managed/files/GUID-096085E3-5AD5-4454-BF10-C9177FDB5979.htm)。
