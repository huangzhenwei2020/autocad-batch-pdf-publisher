# 应用后 Esc 取消提交

日期：2026-10-06。用户明确操作为“已点应用，再按 Esc”。本次纠正此前只测应用刷新完成后 Esc 的验证盲区。

## 原因与复现

`ApplyGeometryAsync` 在提交事务前等待 `_parameterPreviewTask`，并要求输入代数仍一致。预览较慢时，用户点击应用后任务停在该等待；此时 Esc 调用 `CancelActiveCommand`，增加输入代数并恢复属性栏。等待结束后应用因为代数变化直接返回，确认的参数根本没有提交。虽然未调用 Undo，用户看到的效果确实像后退。

新增原生窗口回归，用预览工作信号量保持计算未完成：修改洞口高 2100→2300，点击应用，立即按 Esc，再释放预览。修复前实际运行失败，错误为 `Clicking Apply then Escape while preview was pending lost the confirmed dimensions/code.`，退出码 1；并非只根据代码推测。

## 修复

- 应用先读取、验证并提交确认的数值，不等待不具备提交权的预览任务，也不让 Esc 的预览代数变化取消已确认操作。
- 事务提交后按既有模型/场景代数刷新，过时预览不能替换正式模型；预览完成时仍可复用有效场景。
- 未提交的草稿和正在操作的命令仍可由 Esc 取消；编号冲突弹窗的取消仍不会提交。无效尺寸仍由事务拒绝，保留明确错误提示。
- 保持 Ctrl+Z 一次撤销真实尺寸、编号及构造，不改变历史栈接口。生产修改只去掉 `ApplyGeometryAsync` 的等待/输入代数返回条件。
