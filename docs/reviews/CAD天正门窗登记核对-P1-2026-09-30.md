# CAD 天正门窗参数登记核对（P1 第一段）

## 已实现范围

- CAD2022 命令 `WLMCREGISTER`，也可从 `JZMX` 选择“天正门窗登记核对”。选择限制为 TCH_OPENING，一次最多 100 个，不修改源图。
- 登记读取 ObjectName / Width / Height 三个已在真实 CAD2022 + T20 V9 图纸验证的 getter；不遍历原生属性。
- 用户按编号选择当前项目 MCLM 做法。编号相同的历史记录保留为独立选项，不静默取第一条或最后一条。
- 洞口宽高保留 CAD 实例值；与做法库尺寸不同时提示差异，仍使用洞口尺寸和原有立面样式。
- 未验证的天正编号不猜测，不使用图层或实体句柄代替编号；现阶段在窗口选择对应做法。
- 窗台/洞口底高按编号优先读取已保存门窗表，之后才使用所选立面明确保存的参数；不使用类型默认的 900。表内“—”、缺失或同编号高度不一致时保持空值。存在分楼层表时先要求楼层上下文，目前核对窗口尚未接入楼层选择，可手动补充确认。允许明确输入 0；修改宽高或底高后自动取消确认，清单保留高度来源。
- 每个门窗独立勾选登记；单位确认、尺寸有效性、编号对应做法、底高与参数确认均通过才可保存。
- 输出 `.openings-register.json`，保留 DWG 指纹、来源句柄和所选完整立面参数；原子替换、保留 `.bak`。

## 边界及后续

这份清单是参数登记结果，**不是 model.json，也不能直接生成模型洞口**。`PlacementVerified` 明确为 false。下一段继续实现楼层登记、CAD/模型坐标校准、门窗定位与宿主墙关联；必须核验后才能创建正式模型，并支持重复登记更新和撤销。

门窗造型、分格、框料、开启、材料继续复用现有 OpeningElevationAdapter / 门窗立面生成器，不另写一套。

## 验证

- 参数测试：编号大小写及空白匹配、同编号多记录阻断、保留 CAD 宽高、复用框料参数、未知底高阻断、NaN/无穷/非正尺寸阻断、单位未确认阻断、原子保存及备份。
- WPF 测试：1080×630 / 720×400 内容区，表格保持可用高度、操作按钮不越界；选择具体做法预填底高但不自动确认，编辑尺寸取消确认。
- CAD2022 插件编译成功；R24/2022 完整发布成功，楼梯 92 项、LineVision 32 项以及启动器布局/缩放检查通过。建筑模型 Avalonia 分析器有两条既有 CS9057 编译器版本警告，未阻止编译。
- 在测试副本上执行 CAD 自带 `vlax-dump-object` 时，天正 BayThick 等属性出现原生 0xC0000005 访问异常。因此登记采用经过验证的读取白名单，禁止依赖“公开属性都安全”的假设。该检查没有写入源 DWG，副本 SHA256 未变。

- 真实 CAD2022 + T20 V9：在工程测试副本中运行 `WLMCREGISTER`，选择原生门窗对象后成功打开核对窗口，读取洞口 800×2200；选择现有立面做法、预填底高、确认参数及单位未确认时阻止保存均通过。本次做法选择只用于交互验证，不代表已自动识别天正编号，未保存测试登记结果。
- 测试会话关闭后，副本 SHA256 与测试前一致。以上宿主验证限于本次环境，不能据此宣称全部天正版本都已支持。

追加变更验证：门窗表优先级、明确零值、“—”不回落、重复编号底高冲突、分层表上下文与来源记录；基点跨层大坐标/旋转对齐、逆变换、单位倍率、地下层窗底标高、缺基点及楼层错配阻断。该追加变更通过自动测试与 CAD2022 编译，尚未另作真实门窗表的宿主复验；基点计算尚未连接登记交互。
