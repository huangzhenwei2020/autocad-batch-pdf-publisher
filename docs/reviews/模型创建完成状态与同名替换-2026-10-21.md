# 模型创建完成状态与同名替换

日期：2026-10-21。版本仍为 1.5.6。

## 用户要求与调查

用户报告 CAD 建筑模型工作台点击创建后一直显示“正在处理…”。只读检查确认项目里已有旧“6#”，其模型及登记文件时间仍为 10 月 11 日，未因本次操作被覆盖。随后用户明确：同名不能只报失败，须让用户选择是否替换旧文件。

回归已复现一个明确缺陷：`WorkspaceRun` 对成功但未更新状态的操作，只恢复按钮而不清除“正在处理…”。另一个需要覆盖的边界是 CAD 非模态宿主同步上下文：异步保存/等待必须回到 WPF Dispatcher，不能依赖宿主后续消息调度。没有向正在使用的真实 CAD 注入诊断代码、重放创建或修改用户模型；因此不把截图直接等同于某一条已捕获的阻塞调用栈。

## 实现

- 工作台执行入口临时为整个异步操作捕获 WPF `DispatcherSynchronizationContext`，同步入口返回前恢复宿主上下文。成功、失败和取消均恢复交互；无专用结果文本时不残留“正在处理…”。
- CAD 拾取返回后的窗口恢复再排入新的 WPF Dispatcher 操作，避免宿主完成任务时内联延续仍处在原生回调退栈中就 Show/Activate。
- 新建发现同名时显示替换确认，默认不作破坏性选择；“否”或“取消”保留旧模型和当前名称/楼层草稿。
- 用户确认后调用独立的 `BuildingModelProjectWorkflow.ReplaceExisting`，按确认时的原文件 SHA-256 核对，拒绝覆盖仍有三维编辑会话或已被其他窗口改动的模型。
- 替换仅接受项目内 `建筑模型/<同名>/model.json`。在同一模型根目录的唯一暂存目录写入新模型，将旧模型整个目录移动至 `.model-replaced-<名称>-<时间>-<随机号>`，再提交新目录。目录均为经过验证的同级路径，包含链接的目录不作替换。
- 旧 CAD 登记、图纸、请求、门窗库及其他模型内文件完整进入备份，不混入新的空模型；备份不会列成当前项目模型。新模型按当前楼层设置保存、登记、选中并切到 CAD 平面登记页。
- 提交失败时恢复原目录；恢复也失败则明确报告完整旧模型备份位置。不静默覆盖或删除旧模型，不取消原有新建 API 的禁止覆盖保护。

该同名确认本轮接入的是用户截图中的 CAD 统一工作台新建入口。Studio 独立新建及旧模态新建入口未在本轮改成相同确认流程，不把共享核心 API 的存在当成所有界面都已接入。
