# Blender 导出材质复用与受保护打开

日期：2026-10-14。产品版本保持 1.5.6。

## 背景与边界

用户反馈插件导出的 GLB 自动打开 Blender 后立即整机卡顿，强制重启。只读核验原 GLB 为约 2.4 MB、240 网格、63,616 三角面；Windows 给 Blender 记录了 RADAR_PRE_LEAK_64，随后记录非正常关机。旧后台导入约 0.8 秒、清理约 0.2 秒，采样提交内存约 345 MiB，未复现卡死。日志不足以证明真实泄漏位置、显卡故障或插件必然是整机卡顿根因。

原文件确认 333 个材质只有 7 种不同内容。原导出器逐构件调用 SharpGLTF CreateMeshes，各次调用分别创建 schema 材质，是确定的冗余缺陷。

## 实现

- 跨构件转换共用 schema 材质映射。不合并构件、不改网格、坐标、法线、透明度、双面、类型／实例 ID 或楼层层级。
- 自动打开拆成两个独立进程：后台导入／清理／保存私有准备场景；成功后，前台直接打开该场景，默认 SOLID 实体显示，不启动材质预览、贴图编译或渲染。
- 采用 factory-startup、disable-autoexec、2 线程；后台 BelowNormal、90 秒超时及 Windows Job 2 GiB 提交内存硬上限。前台首次显示前 BelowNormal、30 秒超时及 4 GiB 硬上限；超限或取消只停止本次启动的进程及其子进程，不关其他已开的 Blender。
- 前台在实际 VIEW_3D POST_PIXEL 回调记录首帧及显卡，首帧确认后释放 Job 内存及生命周期限制，将 Blender 交给用户。此保护不覆盖用户后续渲染或驱动内核卡死，不能宣称防住所有系统故障。
- 网格清理仅做原来的同面整理，按实际 mesh 身份去重；单网格超过 25 万多边形或已处理超过 5 秒时保留原三角网格，不丢几何。后台 Undo 临时关闭并恢复。
- 每次创建独立本机运行目录，分阶段 UTF-8 JSONL、stdout/stderr 和内存／耗时日志；临时文件与 session recovery 均落入该次 scratch，避免占用全局恢复路径。准备文件不覆盖原 GLB／语义模型。
- 现有取消按钮在自动打开阶段显示“取消打开”；“Blender 日志”入口可打开本次目录。取消、失败或超时都保留已导出 GLB，不再把“启动了进程”当作成功显示。
- 同一 Studio 进程中的自动打开串行保护拒绝重复任务。没有额外公共图库或 CAD 导入流程，也未扩展外部资源变尺／运动能力。

## 验证

- GLB 全套通过：跨构件／楼层／标准层共用材质，玻璃透明双面保持；体积尺寸、面积、绕序、构件 ID、取消和原子覆盖保持。
- 新 BlenderLaunch 独立测试通过：安全参数与 Unicode 路径、成功、错误退出、Windows 内存硬上限、超时、取消／预取消、无孤儿进程、首帧失败／成功释放和旧 ready 标记拒绝。
- 8#01商业已保存语义模型只读导出到私有测试目录，7 材质、237 构件、63,598 三角面，尺寸／面积／法线校验通过，源模型哈希不变。该保存快照与旧 GLB 的构件数不同，本轮未代覆盖旧 GLB，不能把二者差异归于本次优化。
- 小楼板前台验证通过后，再验证新导出的实际项目私有副本。后台准备采样提交内存约 287 MiB；导入约 0.36 秒、清理约 0.18 秒。前台实际首帧约 0.52 秒，日志确认 RTX 5080，测试自动正常退出。未进行高负载材质／渲染，也未验证旧故障完整现场。
- 建筑模型核心回归通过，Studio 编译通过；保留现有分析器版本及 Bitmap 过时警告。
- R24／R25 正式编译、自包含 Studio、820×600／1500×930 出图栏及原分格／图纸／GPU 回归通过，R24 旧图框原生 QA 通过。正式包 Blender 脚本实际首帧回归通过。截图第一次因测试输出目录未预建失败，预建后重跑通过，不是业务模型导出失败。
