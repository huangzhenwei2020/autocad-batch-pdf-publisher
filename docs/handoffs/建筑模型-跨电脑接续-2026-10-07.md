- 门窗平面来自 CAD/语义线条，不用三维三角网格投影替代。平面与三维可有不同细节，但洞口、基点、方向和宿主必须对应。
- 共享目录是同电脑 CAD/模型协同，不是云同步；家具后续沿用同一资源身份，不另造图库流程。
- 外部模型按固定框、各扇、五金/门槛等拆部件；变尺寸须结合锚定/可变中段/固定截面与运动轴重算，不能整体非等比拉伸。
- 窗平面保留闭合固定轮廓，可开启部分增加浅色单线虚线，不画门扇式厚度；开启弧也为浅色虚线。门的立面开启线尖头指向合页，两扇合页在外侧，不能两扇自由端相对画成合页。
- 门窗编号可改；尺寸变更自动编号，区分当前一樘/同编号集合。新编号冲突时让用户选择并入已有集合或加后缀，尺寸不合法应提示并保持原模型。
- 已点应用后，Esc 只取消未提交命令，不撤回已提交参数；Ctrl+Z 才撤销。夹点拖放直接提交；夹点要容易点中、可预选；编号有移动夹点；门窗移动可输入距墙边距离，右键沿墙居中。
- 图纸几何和 CAD 落图 1:1，1:100 指图框放大 100 倍；用户可改出图比例、CAD 毫米线宽、字高、宽度因子。尺寸文字为整数且位于界线之间。图纸墙交接内部对角缝不显示，墙板重合边不重复显示，实体边界描边向实体内部收。
- 标准层共享一份平面数据，三维必须展开每个实际楼层，不能只画一层。旋转以所选物体为焦点，保留 Z/ZF 适配工作流。
- 新 UI 沿用已选第二张图库网格稿和现有 Ribbon/右侧属性布局；部件列表画实际形状。设计稿里的后续尺寸/开闭按钮不能冒充已实装。
- 版本不要大幅增加。覆盖原目录前保存并关闭 CAD 与模型，检查进程，备份后覆盖，不另装一堆版本，不改用户项目/设置。

## 3. 数据和代码地图

默认本机公共库：`%LOCALAPPDATA%/WanLuo/ComponentLibrary`。测试可用 `WANLUO_COMPONENT_LIBRARY_ROOT` 隔离。

索引 `records/<AssetId>.json`：`Version` 是整条共享记录的并发版本；`PlanHash` 是原生平面哈希；模型关联由 `ModelRevision`、`ModelHash`、`ModelPlanHash` 表示。平面变化后模型失效不是删除模型。`.wlopkg` 内的模型修订不可变，与索引版本不是同一个计数器。资产 ID、项目类型 ID、项目实例 ID、可见编号也不能混用。

建筑 `model.json` 仍是可编辑建筑语义来源；“保存项目资源副本”只复制资源，不等于已创建项目实例。当前 GLB 检查仅允许有界、自包含、无贴图/动画/蒙皮的静态几何，不执行资源携带脚本。

## 4. 新电脑开始

1. 拉取本仓库最新 `main`，检查工作区，不覆盖已有改动。
2. 阅读本说明、当前上下文入口、共享图库验收与最新规划。历史文档顶部状态可能已被后续记录取代。
3. 安装/准备 .NET 8 SDK、Visual Studio Build Tools、.NET Framework 4.8/4.8.1 Targeting Pack 和目标 CAD SDK/安装。`.tools` 不随 Git 上传；只有运行时不够编译。
4. 从当前源码恢复/编译，不复制旧机 `dist` 或 DLL。正式发布入口和前提见 [BUILD_AND_INSTALL](../BUILD_AND_INSTALL.md)：

```powershell
git pull --ff-only
git status --short
powershell -ExecutionPolicy Bypass -File .\build\Build-Release.ps1
```

默认发布目录 `dist/WanLuoArchitectureTools`，通过其中正式启动器加载。正式重建会清理发布目录，先备份该目录内需要保留的数据并关闭软件。R24 对应 CAD 2021–2024，R25 对应 2025–2026；CAD/SDK 路径按新电脑实际情况选择，不照抄旧机 C:/D: 路径。

**Git 不包含旧机个人公共图库、CAD 配置、山水湾模型/图纸、测试临时文件和 SDK。** 本轮测试资产通过下一节核心测试自动重建。若需要自己的生产图库/项目，另行迁移对应数据，并保留整个 `ComponentLibrary` 的 `records` 与载荷文件；不能只拿索引，也不能只拿 GLB。

## 5. 可重复验证

在仓库根目录执行，使用具备 SDK 的 `dotnet`。不要在干净机器直接加 `--no-restore`。

```powershell
dotnet run --project BatchPdfPublisher.Tests/BatchPdfPublisher.ComponentPackages.Tests.csproj
dotnet run --project BatchPdfPublisher.Tests/BatchPdfPublisher.ComponentSources.Tests.csproj
dotnet run --project BatchPdfPublisher.Tests/BatchPdfPublisher.ComponentAssets.Tests.csproj
dotnet run --project BatchPdfPublisher.Tests/BatchPdfPublisher.ComponentPlan.Ui.Tests.csproj -- .artifacts/component-ui
dotnet run --project BatchPdfPublisher.Tests/BatchPdfPublisher.BuildingModel.Tests.csproj
dotnet run --project BatchPdfPublisher.Tests/BatchPdfPublisher.BuildingModel.Interop.Tests.csproj
dotnet run --project BuildingModelStudio.AvaloniaProbe/BuildingModelStudio.AvaloniaProbe.csproj -- --smoke --component-package-check --snapshot-size 960x680
dotnet run --project BuildingModelStudio.AvaloniaProbe/BuildingModelStudio.AvaloniaProbe.csproj -- --smoke --component-package-check --snapshot-size 1600x960
```

先运行 `ComponentPackages.Tests`：它生成 `.artifacts/component-packages` 的窗/椅 GLB、平面与配对资源，供 UI 回归使用。窗口/GPU 测试需要 Windows 桌面与可用图形环境，不是无头服务器断言。

CAD 原生 QA：在一次性测试图纸加载刚编译的插件，运行 `WLCOMPONENTPLANQA`、`WLLIBRARYQA`，要求出现 `CAD_COMPONENT_SOURCE_NATIVE_OK` 和 `CAD_COMPONENT_LIBRARY_OK`。不要用用户正在编辑的图纸测试；Core Console 的 .NETLOAD 用绝对路径，当前环境使用 ASCII 临时路径较可靠。成功后自身临时日志 errno=13 清理警告不等于插件断言失败。

本机这些测试与 R24/R25 编译已通过。Avalonia 编译有既有 CS9057 分析器版本提示和 Bitmap.Save 过时提示；不是新逻辑错误。安装后也须核对哈希和实际安装目录程序自测，不仅看源目录构建成功。

## 6. 后续推荐工作

**G2 先打通固定规格真实实例**：选一樘固定窗，从共享记录进入 MM/宿主/实例资源引用，完成保存重开、缺失回退、平面/图纸/CAD/三维/GLB 一致输出；再做一个独立固定椅家具实例。旧参数类型不转外部类型、不修改已有项目。

**G3 再联合尺寸与开闭**：固定框、各扇、五金分组，关闭姿态建模，图形化指定合页/轨道/固定区/伸长区；先解尺寸和净扇，再求运动轴，同步平面和三维。门窗/柜门转动，抽屉平移，刚体部件保持厚度。规则不完整的资源继续固定规格/静态，不靠猜测。

家具沿用共享库但独立放置语义，不切墙，不套门槛/窗台字段；普通用户只看允许编辑的参数，节点和矩阵留作者界面。完整材质、软件版本和更新差异验收单独排期。
