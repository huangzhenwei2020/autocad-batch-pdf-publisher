# 三维模型门窗分格编辑开发计划

日期：2026-10-02。状态：方案已确认，首版已开发、验证并安装。实施记录见 `reviews/三维模型门窗分格编辑-2026-10-02.md`。

## 1. 目标与范围

将现有“门窗立面”的分格、开启方式、面板材料、构造参数和模板操作迁移到建筑模型中。用户在三维或平面视图双击一樘门窗，即可编辑；无需先到 CAD 生成门窗表、再打开另一套设计入口。

CAD 楼层登记仍提供洞口编号、宽高、窗台和定位，并自动形成项目门窗表。缺少深化参数的门窗先以默认做法生成，用户以后再编辑。模型编辑后的同一份做法驱动三维、平面图、建筑立面、门窗立面、门窗表及导出模型。

首次版本覆盖已有普通门、窗、门联窗、百叶和凸窗能力。参数化框料、扇框、玻璃及板件为本次范围；厂家型材复杂空腔截面、五金细部、加工拆单和性能计算留作后续扩展。

## 2. 当前代码基础与缺口

| 部分 | 现状 | 本次处理 |
| --- | --- | --- |
| 门窗立面 | 已有分格、面板编辑、拖动分隔、多选、开启、构造和凸窗编辑 | 复用行为与几何规则，将界面迁移到 Avalonia |
| 二维生成 | `OpeningElevationAdapter` 调用共用门窗立面生成器 | 增加统一的可供三维使用的构造结果，避免重写另一套分格规则 |

| 三维 | `BuildingVolume` 简化外框宽度约 60 mm、玻璃厚度 20 mm，普通门统一开 35° | 改为读取真实分格与三维参数生成框、扇和面板 |
| 编辑界面 | 原分格编辑为 WinForms，建模界面为 Avalonia | 迁移交互，抽出框架无关的编辑状态与校验逻辑 |
| 联动 | 二维已有按编号查做法机制 | 建立编辑、预览、撤销、缓存刷新与导出的一致流程 |

主要代码位置：`Shared/BuildingModel/ModelTypes.cs`、`OpeningElevationAdapter.cs`、`BuildingVolume.cs`；`BatchPdfPublisher/Features/DoorWindows/Models` 和 `Views/DoorWindowLayoutEditorControl.cs`、`CustomDoorWindowDivisionForm.cs`；`BuildingModelStudio.AvaloniaProbe/ModelViewport.cs` 与模型编辑会话。

## 3. 用户操作流程

1. 单击门窗选中并显示编号、洞口尺寸、楼层；双击打开“门窗编辑”。平面视图、项目浏览器及属性区的“编辑门窗”提供相同入口。
2. 编辑窗显示当前门窗的正面分格，旁边有可旋转的局部三维预览；两者读取同一草稿。
3. 用户添加横向/竖向分格、等分、拖动分隔线、输入尺寸，或选择模板；单击格子设置开启方式与材料，Shift 多选保持原有习惯。
4. 修改框宽、框进深、玻璃厚度等有效参数后，局部三维和场景中的门窗实时预览。正在输入的空值、负数和不完整数字不写入正式模型。
5. 点击“应用”将草稿作为一次可撤销操作提交；“取消”恢复进入编辑前的状态。连续拖动不产生大量撤销记录。
6. 编辑结束后，关联图纸标记需要刷新；刷新或推到 CAD 时生成当前版本。已有 CAD 落图通过更新替换，避免叠加。

双击需精确命中门窗，包括框、玻璃和门扇；各子部件都归属于同一樘门窗，墙后被遮挡的门窗不应被选中。与旋转、拖动视图和正在执行的建模命令协调，防止双击触发其他操作。

## 4. 编辑界面

编辑窗口安排：顶部显示编号、类型、洞口宽高和编辑影响范围；中央为正面分格画布；右侧为当前面板和构造参数；可切换局部三维预览；底部提供应用、取消和重置当前草稿。

保留现有功能：横竖分格、等分、尺寸/比例设置、分隔线拖动与吸附、格子合并/删除分隔、面板多选、逐格材料与开启设置、外框与分隔框开关、安装缝、门联窗门位置、凸窗侧面，以及保存/套用模板。迁移前逐项核对现有界面，建立功能对照表。

画布按毫米计算，缩放只改变观察比例；图形、尺寸和三维厚度不随滚轮变更。吸附步长可设置。显示用户编号和名称，不展示内部构件 ID。

## 5. 参数设计

必须区分正面看到的“宽度”和垂直于门窗正面的“进深/厚度”，避免一个字段承担两种尺寸。

| 参数 | 含义 | 默认策略 |
| --- | --- | --- |
| 洞口宽、高、窗台 | 墙体洞口及安装标高 | 沿用 CAD 登记/模型实例 |
| 安装缝 | 洞口与门窗外框之间的间距 | 保留现有设置；新做法默认 20 mm |
| 外框宽 | 外框正面占用宽度 | 保留现有设置；新做法默认 50 mm |
| 外框进深 | 外框实体沿墙厚方向的深度 | 建议初值 70 mm |
| 分隔框宽、进深 | 中梃/横梃的正面宽度与实体深度 | 宽沿用现有 50 mm，进深建议 70 mm |
| 扇框宽、进深 | 可开启扇的边框尺寸 | 建议初值 40/50 mm |
| 玻璃厚度 | 玻璃面板实体厚度 | 建议初值 6 mm，可修改 |
| 门扇/实板厚度 | 不透明板件厚度 | 建议初值 40 mm，可修改 |
| 安装位置 | 沿宿主墙厚方向的位置 | 默认居中，支持靠内、靠外及偏移 |
| 开启方式、方向 | 固定、平开、推拉等原有做法 | 沿用原立面定义，逐格设置 |
| 三维开启角度 | 模型预览的打开程度 | 默认关闭；需要时用户设置 |
| 凸窗侧面、进深 | 左右转折几何及分格 | 沿用已有参数 |

以上三维初值是软件建模默认值，不代表具体产品的构造尺寸。旧数据已有二维参数必须完整保留，只有缺失的三维字段补默认值。

玻璃首版使用实体薄板，实体边线模式下维持清晰的表面和遮挡；透明材质与实际厚度分开处理。避免为了透明效果让背面线穿透。中空玻璃组合层作为后续可扩展结构，首版不将“总厚度”错误画成多块重叠玻璃。

门联窗默认闭合；二维开启符号仍表达设计开启方式，三维打开角度是另一个参数。普通门也不再固定以 35° 打开。

## 6. 同编号、标准层与批量修改

做法默认归属于项目门窗类型，同编号且同尺寸的门窗共享分格和构造。编辑窗口明确显示“同编号共 N 樘”，默认应用同编号做法，提交前即可看清影响范围。

提供“仅修改这一樘”：需要与同编号做法不同的分格、材料或厚度时，创建独立做法并按现有编号规则自动加后缀，更新门窗表，避免同一编号代表两种不同做法。安装位置等实例参数可单独修改，不因此复制整个类型。

同编号异尺寸继续使用已有自动后缀规则；无编号沿用登记时的尺寸编号，禁止重新发明编码规则。

标准层共享平面的门窗默认共享做法，显示实际影响楼层和数量。若要求某一实际层不同，必须显式解除该层对应做法的共享关系，并保持原楼层标高、宿主墙与统计正确；这项依赖要在类型与实例阶段解决，不能只修改临时展开后的三维副本。

批量编辑以类型为单位，可从项目门窗表选择多项统一修改框料进深、玻璃厚度、材料等；不强制用户重新核对已经登记完整的洞口。

## 7. 统一二维、三维算法

新增共享的“门窗构造解析结果”，包含洞口、安装后的外框范围、分隔框、扇框、净面板范围、材料、开启定义和凸窗转折面。该结果由现有分格算法解析，二维与三维均使用它。

不能直接把立面的每条线拉伸成实体：尺寸线、开启虚线、材料符号不属于实体构造。应从面板和框料的语义区域生成几何，并与已有立面生成结果做回归对照。

三维按局部坐标生成构件，再利用宿主墙方向、墙体定位方式、洞口中心与窗台转换到模型坐标。斜墙、反向墙、镜像门窗使用同一转换规则。

框料交接采用一致的接头规则，避免横竖框重叠、角部重面和玻璃穿框。面板净尺寸扣除对应框料，安装缝只扣一次。凸窗主面和左右面共用拐角节点；门联窗明确区分门、窗和门上亮子。

百叶及其他重复细部采用按视图用途分级的几何：编辑局部预览可显示细部，整栋观察与 1:100 出图适当简化；简化只能省略细部，不能改变分格、洞口或外形尺寸。

## 8. 数据与兼容

类型做法扩展保存分格及三维构造参数；实例继续保存编号关联、宿主、洞口定位和必要安装偏移。将来可扩展材质和型材预设。

项目为主要数据源，保留现有 `openings.json` 导入/导出适配，并明确模型内做法与外部文件的版本关系。重新登记 CAD 更新洞口尺寸和位置时，应保留已编辑做法；尺寸变化导致分格不适配时标记待调整，并提供预览，不静默丢弃用户设计。

旧项目可直接打开；旧自定义分格、逐格开启、凸窗侧面及模板须无损转换。数据保存带版本迁移；应用与撤销覆盖类型、实例引用、编号和相关缓存，保存失败不得造成半更新。

原 CAD 门窗立面功能保留，双方调用共享核心与转换适配，防止产生两套不同算法。三维新字段在旧二维编辑器不支持时，也应在往返转换中保留。

## 9. 性能与实时预览

将宿主墙开洞和门窗细部网格分离：仅改分格、框料或材料时，重建受影响门窗，不重新计算整栋墙体和楼板。

按类型做法版本、实际尺寸和显示精细度缓存局部门窗几何，标准层重复实例复用。绘制、拾取及导出映射仍对应各自实例。

输入和拖动采用短延迟合并、后台计算与过期结果取消；场景中只提交最新有效草稿，不允许较早的后台结果覆盖后来的输入。局部三维优先更新，全楼相关实例随后刷新。

将门窗网格重建时间、UI 响应和内存作为单独指标记录。验收目标为普通门窗局部预览约 100～200 ms 内响应；大量同编号实例不阻塞 UI，不强制每次生成全部 CAD 图纸。最终用当前 15 层项目实测，不只用简单样例判断。

## 10. 分阶段实施与交付

| 阶段 | 工作 | 阶段验收 |
| --- | --- | --- |
| P0：现有功能与数据整理 | 原编辑器功能对照、样例收集、参数结构、类型/实例/标准层规则、迁移设计 | 明确旧功能无遗漏和数据兼容边界 |
| P1：共用构造核心 | 提取分格编辑状态与构造解析、补三维参数、序列化和撤销支持 | 二维结果与原算法一致，保存往返无丢失 |
| P2：建模编辑入口 | 双击拾取、Avalonia 分格编辑、局部预览、作用范围、应用与取消 | 单樘编辑完整跑通，原操作习惯可使用 |
| P3：三维真实构造 | 外框、分隔框、扇框、面板厚度、安装位置、门联窗、凸窗、开启 | 任意视角与剖面检查尺寸、交接、遮挡正确 |
| P4：全链路与批量 | 同编号同步、标准层、模板和批量编辑、门窗表/图纸/GLB/CAD 联动 | 修改一次后各输出一致，CAD 更新无重复 |
| P5：性能与实际项目验证 | 局部重建、缓存、取消旧任务、旧项目与大楼回归、打包安装 | 当前项目操作顺畅，旧数据无损，验证后发布 |

开发顺序先完成普通窗的纵向闭环，再扩展复杂门窗；最终发布须覆盖本计划的首版范围，不能以仅有双击弹窗视为完成。

## 11. 验证清单

- 几何：单格、多格、局部合并、横竖框接头、不同面板材料、无框、安装缝、门联窗、凸窗、斜墙、反向与镜像；框料和玻璃实际尺寸可量测，无自交和重面。
- 交互：三维/平面/树入口一致，双击遮挡正确，吸附、多选、拖动、输入预览有效，取消完整恢复，应用后一次撤销/重做恢复所有关联数据。
- 类型：同编号同步、仅这一樘自动后缀、同编号异尺寸、无编号默认、标准层共享与单层差异，门窗数量与编号一致。
- 输出：正面三维构造与门窗立面相符；平面、建筑立面、剖面、轴测、门窗表、GLB 和 CAD 对应更新；平面无填充、轴测仅可见边的既有要求继续满足。
- 兼容：缺少类型库、旧自定义分格、旧凸窗数据、CAD 重新登记、保存重开、二维/三维编辑往返。
- 性能：修改一樘不重建整栋；快速连续输入只显示最终结果；标准层大量重复实例与大尺寸多分格不冻结窗口。

## 12. 方案约定与待评审项

本计划建议：默认编辑同编号类型，支持单樘分离；三维默认闭合；局部预览与场景同步；复用现有分格操作与算法；型材用可参数化简化实体，首版不做厂家加工细部。

方案经用户确认后开始实施。上述内容保留为目标与验收基准；已交付范围、验证结果与剩余限制以实施记录为准。
