## 1. 产品目标和完整操作流程

用户既能从空项目建模，也能把 CAD 中的已有平面作为建模依据；在平面、三维、立面、剖面中编辑同一栋建筑；生成可继续制图的 CAD 实体，后续更新保持图纸位置并保留人工补绘。

1. 从 CAD 当前项目打开新版万落建筑模型，或在独立程序中打开项目。
2. 登记楼层、标高、层高；从 CAD 选取平面范围、轴线、轴号、墙线和门窗等，核对单位、方向、原点和楼层对应。**天正原生墙、门、窗必须识别实例位置与可读取的建筑参数，用户可在登记时及导入后修改相关参数。**
3. 将登记内容作为锁定底图，选择性转换成轴网、墙、门窗等构件；不确定的识别结果先确认。
4. 在平面或三维中新增、选择、修改、删除构件，支持精确输入、吸附、撤销及重做。
5. 建立各方向立面与剖面；直接选取构件修改高度、窗台、洞口等；添加视图专属尺寸、文字、填充和大样补绘。
6. 选择出图视图，设置图框、比例、图名、图号和排版，预览并检查问题。
7. 点击“推到 CAD”，由 CAD 2022 的 LTTZ 选择落图或更新已有放置实例，返回每张图的结果。
8. 模型或 CAD 源平面改变后，查看差异、确认更新，再生成受影响图纸；全过程可追溯和恢复。

**完成标准是上述流程可重复使用，不是出现相应按钮或显示一张模型。**

## 3. 统一的数据与编辑规则

### 3.1 同一模型，多种编辑视图

- 建筑构件以领域模型为权威，三维网格和平立剖线稿是其生成结果。平面、立面、剖面编辑最终提交到同一个命令和校验层。
- 构件、楼层、轴线、视图、图纸和 CAD 放置实例均使用稳定 ID。不能靠列表序号、网格面序号或显示名称建立关联。
- 每次成功编辑产生模型修订；一次拖动只提交一笔撤销记录。属性批改、宿主关系调整和几何更新必须整体成功或整体失败。
- 重计算采用模型及类型库快照；任务携带修订号。新编辑、换项目、取消、窗口关闭后不得提交过期结果。
- 输入 CAD 的大坐标先转换为项目局部坐标，单位明确保存；回 CAD 使用记录的逆变换。UCS、旋转、镜像与比例不可隐式猜测。

### 3.2 必须分清“修改模型”和“补绘图纸”

| 用户操作 | 预期影响 |
| --- | --- |
| 平面移动墙、调整洞口位置 | 改模型；三维、立面、剖面及相关标注同步更新 |
| 立面调整窗宽、窗台高或屋面标高 | 通过构件 ID 修改对应语义参数；先预览影响，再提交 |
| 剖面调整层高、板厚、楼梯参数 | 校验关联楼层、门窗、楼梯及屋面后整体提交；失败不部分修改 |
| 在视图中添加说明、折断线、材料填充、尺寸 | 保存为视图专属制图内容，重算模型时保留 |
| 拖动一条无法对应唯一构件的投影线 | 不允许静默改模型；提示选择构件或转换为独立补绘线 |
| 在 CAD 中改动生成图元 | 视为生成图元的外部改动；更新前提示处理，不能假定已反向更新模型 |
| 在 CAD 中新增人工线稿 | 作为独立人工内容保留，除非用户明确纳入某个补绘层或视图 |

关联尺寸锚定构件和几何角色；宿主被删除时标记“关联失效”，供重新绑定或转为静态标注，不能消失或悄悄绑定到别的构件。

### 3.4 天正墙、门、窗登记与参数修改（必做）

目标是在安装并加载相应天正环境的 AutoCAD 2022 中读取**原生建筑对象**。门窗表提供的类型和规格可补充实例参数，但不能替代平面中每一道墙、每一樘门窗的位置与关系。当前 `BuildingModelCadBridge.Describe` 只覆盖普通实体；`TianzhengDoorWindowService.Read` 读取表格，并非原生墙门窗实例适配器，此项尚未完成。

#### 参数清单

| 对象 | 要识别并允许核对修改的内容 | 校验重点 |
| --- | --- | --- |
| 墙 | 起终点或路径、方向、所在楼层、基底标高、墙高、总厚度、基准线及两侧偏移；原对象能提供的墙类型、材质 | 不把轮廓包围盒当墙轴线；不把非对称墙厚改成居中；墙交接和洞口位置正确 |
| 门 | 插入/洞口中心位置、所在墙、沿墙定位、洞口宽高、底标高、方向、镜像/开启方向、编号和类型 | 区分洞口尺寸与门扇尺寸；有宿主才能开洞；无门槛、旋转及镜像门定位正确 |
| 窗 | 插入/洞口中心位置、所在墙、沿墙定位、洞口宽高、窗台高、方向、编号和类型；能提供的凸窗进深及转角信息 | 窗台相对楼层的标高基准明确；同编号的各个实例不能合并；复杂窗型不能静默降为普通矩形窗 |

这张表是所需的领域参数，不是对天正各版本公开属性名称的断言。B08 先用真实对象记录可读字段及单位、确定映射；读取不到的字段标记“待补充”，几何推断值标记“推断”，类型库补充值标记其来源，不能用 0 或默认值伪装成原始数据。只有在当前模型结构能够完整表达参数时才允许转换，否则保留原始对象信息并提示待适配。

#### 读取与登记规则

1. 检测 CAD/天正版本、对象类型和可读取能力。按真实版本验证可用的对象属性/接口，再确定适配器；读取在 CAD 允许的文档与事务上下文内进行，交给后台的仅是数据快照。
2. 先读取原生语义参数，再用几何与图面做交叉核对。若原生语义不可读，可提供非破坏性的几何辅助识别，但必须标明“待确认”，不可把它算成原生参数读取成功。读取登记不得炸开或修改源 DWG 对象。
3. 宿主关系优先来自可验证的原生关联；无法取得时按位置、墙厚和方向匹配。多候选墙、跨墙门窗、无宿主门窗必须高亮供人工选择。
4. 同一平面中的原生对象、普通图元及嵌套对象分别处理，依来源引用去重。天正未加载、代理实体不可读、字段缺失或不支持的对象应逐项列出，不能从登记结果中静默消失。
5. 按源文档身份、实体 Handle 和引用路径保留实例身份；复制、镜像及同编号实例均独立登记。门窗表/类型库和实例参数冲突时显示两边的值，让用户选择。

#### 参数核对与修改界面

- 登记窗口显示左侧平面预览、右侧参数表；点选行与高亮墙门窗双向联动。每行可勾选是否进入模型，并按楼层、类型、编号、异常状态筛选。
- 显示“原始值 / 修改后值 / 数据来源”，支持单项编辑和适用对象的批量修改、恢复原始值；模型创建后仍可在平面、立面、剖面和属性面板继续修改。
- 修改墙厚、墙高、门窗尺寸、窗台高或定位后即时预览；提交前检查洞口越界、重叠、超墙高、宿主缺失以及无效几何。整笔修改可撤销，不能只成功一半。
- 第一版参数修改作用于登记结果和万落模型。**回写原生天正墙门窗是独立能力**，不能与“推到 CAD 生成图纸”混为一谈；未完成原生写回适配前，界面应明确修改目标为万落模型。
- 重新登记采用“上次源值 / 当前源值 / 用户修改值”逐字段比较。源图未变时保留用户修改；两边都变时列出冲突并提供采用源值、保留修改或手动合并，禁止覆盖后再提示。

## 4. 技术路线和复用边界

- **独立编辑器采用现有 Avalonia 入口**，五个真实工作区为“建筑建模 / 平面编辑 / 立面编辑 / 剖面编辑 / 图纸发布”。不能用一条静态标题代替工作区切换。核心沿用 `BuildingModel.Core` 与 `Shared/BuildingModel`，旧 WinForms 作为行为参考，不再承担新增产品功能。
- **继续推进用户选定的 Blender 服务方向**：先完成常驻工作进程、版本化请求、取消与故障恢复，再扩大几何样例。编辑方式由万落开发。当前 GPU 视口并不是 Blender 内核已经接入的证据；正式剖切、隐藏线和毫米公差必须单独验证，失败时明确报错并使用已验证的几何路径，不输出看似成功的错误图。
- **CAD 适配层当前以 Windows AutoCAD 2022 为验收目标**。独立模型编辑和文件协议保持跨平台；macOS/Linux 实机验收另设任务，不能把 Windows 插件原样运行视为跨平台目标。
- **复用已有项目配置**：项目/图框登记、门窗类型与立面模板、楼梯工程参数、制图标准、图层/文字/尺寸样式、比例和打印设置。通过适配器读取及版本化快照使用，不在新界面重复录入已知参数。
- 楼梯的多跑、平台、构造数据必须完整保留；现有简化双跑 `StairModel` 不足以承载时先扩展模型，不把复杂楼梯压成两跑。
- DWG 内源平面和模型可能同时修改；第一版通过“差异预览→确认应用”同步，不做无提示双向覆盖。源平面登记和模型出图登记分开，避免把刚生成的图又自动识别回模型。

#### 命令栏与跨视图编辑补充（2026-09-28）

- 命令栏统一解析别名，再交给共享编辑事务；三维和平面只负责把屏幕点换算为模型坐标。`M/MOVE` 整体移动与 `CO/COPY` 连同宿主门窗复制已接入三维和平面，支持基点→目标点和 `@ΔX,ΔY` 精确位移。每次提交为单笔撤销记录，失败不修改模型。
- 平面绘墙和移动时按住 Shift，按当前指针相对基点的较大分量自动约束水平或垂直，松开立即恢复自由；轴线和对象捕捉仍优先用于确定点位。
- `MI/MIRROR` 需要定义镜像轴两点、墙左右面厚度交换及门窗开启方向；`F/FILLET` 需要弧墙/圆角的参数模型和布尔几何。现阶段命令栏只识别并提示未实现，不写入伪几何。
- 命令输入采用视图键盘直达：输入 `WA` 后按空格或回车启动画墙，画墙时先点起点，再输入墙长或 `@长度<角度` 精确生成下一段；`Esc` 取消并返回选择。F8 持续正交、Shift 临时正交、F10 极轴，正交与极轴互斥；`POLAR30` 可设置 30° 极轴步长。下一阶段让立面、剖面和三维共享同一命令状态机，并将快捷键配置持久化。
- 交互参考 LibreCAD 的命令行与空格/回车确认、FreeCAD Draft 的分步绘制和对象捕捉；F8/F10 语义按 AutoCAD。仅参考交互行为，几何和事务继续使用本项目实现。
- D02/E02 的立面、剖面编辑器落地后复用同一命令解析、事务和撤销栈；视图适配器必须明确屏幕水平/竖直对应哪些模型参数，不允许把剖面拖动错误地解释为平面 XY 位移。验收时分别核对三维、平面、四向立面和任意剖切线的坐标映射与发布结果。

### 第一批：新版真正能从空项目建模

先做 A01–A04 的必要部分、C01、C02 和 F01。交付一个可实际切换的平面工作区：新建项目→选择楼层→画四面墙→放门窗→三维检查→保存重开→生成平面/立面/剖面→推到 CAD。A03 中其他工作区先有明确可用范围和禁用说明，不以空按钮交付。旧版已有几何/交互规则先整理成共享命令，再接到新版，避免复制第二套规则。

**第一批通过条件：**全流程在新版完成，墙窗 ID、尺寸和宿主关系正确，撤销可恢复，AutoCAD 2022 能落图并更新；新增绘墙功能不依赖打开旧程序。

**第二批通过条件：**一份有多个楼层平面的真实天正 CAD 副本可分别登记；轴号、间距、方向、标高与 CAD 对得上；天正墙门窗位置及可读参数与源对象一致，用户修改后模型和平立剖相应更新；字段缺失和复杂类型明确提示；重复导入不产生重复构件，用户修改不被无提示覆盖。
