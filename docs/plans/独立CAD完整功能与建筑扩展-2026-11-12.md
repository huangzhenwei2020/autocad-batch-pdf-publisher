# 独立 CAD 完整功能与建筑扩展

2026-11-12 根据用户对独立工作台的反馈调整后续开发范围。万落版本保持 1.5.6。MiniCAD 功能基线固定为 0.8.4，提交 `9740e7fbc288f1ea5a71af2b89503fce1496389c`。

## 产品目标与当前进度

工作台中间区域建设为完整 CAD 文档工作区，承接 MiniCAD 已有的文档、图形、编辑、捕捉、标注、布局、保存及三维相关能力。后续在同一工作区增加建筑专业工具，形成独立建筑 CAD，并继续提供 AutoCAD／天正协同入口。

上一批完成启动器双入口、共用项目模型管理、MiniDWG 基础读取及三维编辑器打开。本批已接通原生 Document／Editor／D3D11 视口与 WPF，工作区改为“二维 CAD”，实现基础绘制、选择、移动复制、属性、图层布局及 DWG／DXF 编辑保存。AutoCAD 2022 临时图回读和真实工程独立测试通过，安装状态见 [首批编辑保存记录](../reviews/独立CAD编辑保存首批-2026-11-12.md)。

上一批 DrawingCanvas 已由原生视口替换。正式绘图文档持续持有源 DWG 数据、Scene、Document、Editor、Viewport 和撤销栈，支持实体级编辑及保存。标注、填充、椭圆、多行文字等沿用原生场景构建和渲染，具体兼容性继续按实际工程验收。

## WPF 与原生内核接入

WPF 负责工作区、功能区、属性、图层、文件对话框、参数窗口和命令面板。C++ 负责真实文档、图形构建、拾取捕捉、工具状态、编辑命令、撤销、源图保存和视口几何。渲染接入沿用原生视口及渲染接口，首先验证 Windows 渲染宿主的输入、焦点、中文输入、DPI、缩放、遮挡和资源释放。

MiniCAD 当前 `MiniCADEngine.h` 的部分公共入口仍为注释占位。适配层使用应用正在调用的 DocumentManager、Editor 和 Viewport，封装稳定的 C ABI，再接入 WPF。原生 ABI 使用会话句柄、文档句柄、实体 ID、版本化结构、UTF-8 文本、错误返回及明确的内存释放接口。

文档在打开到关闭期间持续保留编辑状态。UI 发出工具、输入、属性和文件操作，内核返回选择集、命令提示、脏状态、可撤销状态、图层和显示修订。跨线程的读取、进度及取消明确归属文档任务，渲染资源按对应宿主释放。

源图信息保留在 CadSource，并与实体及原始句柄关联。模型稳定 ID、图库资源 ID 和 CAD 实体身份分别记录对应关系。MiniCAD 的 JSON／MCAD 保存格式按功能需要接入，既有万落模型继续沿用原有语义格式。

### 编辑与保存

- 鼠标、快捷键、命令行和属性面板调用同一操作入口。
- 一次完成的绘图／修改对应一个撤销单元，夹点落点提交，Esc 按现有规则结束当前交互。
- 活动工具的草稿显示与已提交几何具有明确状态，切换文档保留各自状态。
- 打开、另存、关闭和外部修改使用可见的修改提示及冲突处理。
- DWG／DXF 编辑保存通过原生 Scene 与 CadSource 完成，回读对照句柄、实体、属性、图层、块、布局和附件。
- 未识别对象及跨格式／跨版本表达变化纳入保存报告，保留原始文件及恢复路径。

### 渲染与真实图纸

优先覆盖截图已暴露的标注、多行文字、填充、椭圆与引线。实际工程同时核对颜色、线型、线宽、字体、文字旋转、块变换、外参和布局裁剪。使用原生几何、空间索引、增量更新和缓存提交，记录打开耗时、内存、首帧、平移缩放和选择耗时。

当前截图对应的 17,999 个数据库对象、304,503 条预览线段和 2,302 段文字可作为大图回归样例。其原文件只用于经允许的项目副本对照，测试报告记录实际结果。

## 工作区界面与交互

顶部功能区采用“项目、绘图、修改、建筑、标注、出图、管理”。图纸采用多文档页签，每张图有自己的模型／布局栏。左侧项目树管理图纸、楼层与建筑模型，右侧显示选择对象属性，图层可停靠。底部显示命令、输入提示、坐标、捕捉、正交、极轴和任务进度。

```text
项目  绘图  修改  建筑  标注  出图  管理
绘图／编辑／建筑工具及当前工具参数

项目浏览器      四层.dwg  五层.dwg  模型        属性／图层
图纸与布局        CAD 绘图和动态操作区域        选择对象参数
楼层与模型        框选、捕捉、夹点、预览        尺寸与构造

               模型  布局1  布局2  …
命令及历史  输入提示             坐标  捕捉  正交  极轴
```

图纸保存使用 Ctrl+S，撤销／重做使用 Ctrl+Z／Ctrl+Y。F3、F8、F10 接对象捕捉、正交和极轴。命令行、文字输入、参数输入和门窗分格快捷键按所在编辑上下文分配。大小窗口及高 DPI 下工具名称完整可读，长名称提供提示和可调整区域。

重新登记继续采用已确定的替换规则。同编号、同洞口大小的门窗保留已修改做法，位置按新平面计算，其余登记构件按既有范围重建。部分识别结果通过提示、底图和人工补绘入口继续处理。

## 本批核对与实验

已核对上述固定提交的文档、编辑器、工具注册、界面命令、布局、字体、渲染及保存接口。在私有实验目录单独编译 MiniCAD 核心，并以原有图层命令、多段线工具、圆角、倒角、布局、属性和多文档视口测试验证接入基础。实验采用二维核心配置，实体内核与完整 Windows 应用的编译及窗口集成单列后续测试。

原生二维核心 Release 编译成功，七组测试共 322 项检查通过。最初布局字形检查缺少字体而失败，配置本机 simplex.shx 私有测试素材后完整通过。该字体素材保存在排除上传的实验目录，正式包的字体查找、开放字体资源及随包许可需要在界面集成时验证。上游属性测试另有一个字符串转义编译警告，本轮保留记录。

随后完成 WPF 编辑器桥接、Direct3D 视口与基础编辑保存，正式包继续由 `build/Build-Release.ps1` 生成。完整工具 UI、三维实体内核及建筑专业扩展继续按上述阶段实施。前期内核实验结果在 `.artifacts/minicad-core-audit-20261112/result.json`，私有素材和构建产物排除于源码上传。

原生内核实验及非 CAD 检查可继续进行。AutoCAD 宿主回归按仓库规则每批先取得批准，只使用 2022 临时图及侧数据库。安装仍在取得本轮保存关闭确认、复查进程并完成备份后更新原目录。
