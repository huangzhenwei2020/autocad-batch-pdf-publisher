# 建筑模型实现审查与计划调整

日期：2026-09-27；审查基线：本地 main，提交 6f99921。相对本地 origin/main 跟踪引用领先 31 个提交，本次未获取远端，不判断 GitHub 是否有新版本。

## 结论

现有代码有实质进展，可以继续作为原型基础；开发计划不能原样当成生产交付计划执行。建议保留独立建模程序、共享领域代码、CAD 提取/落图桥接、门窗生成器复用，在扩展更多建筑构件前先通过几何正确性、保存安全与关联更新三个门槛。

本次是建模相关代码、计划和测试的审查，不是整个 CAD 插件所有功能的全面验收。未操作用户正式模型或修改图纸，也未在 AutoCAD 中完成真实项目落图验收。

## 2. 需要优先处理的问题

### P1：剖切面穿过墙厚但不穿过中心线时漏画剖面

位置：`Shared/BuildingModel/OrthographicProjector.cs:1187`。

`crossesCut` 只用墙中心线两端与剖切面的关系决定是否进入实体求交。墙平行于切面时，即使切面位于墙厚内部，也可能走到非剖切分支。

已在独立审查程序复现：墙轴线 (0,0)→(5000,0)，厚 200，高 3000，切面为 CutY。

| 剖切位置 | 实际是否穿墙 | 当前剖切线 | 当前填充 |
|---|---|---:|---:|
| Y=0 | 是 | 4 | 1 |
| Y=50 | 是 | 0 | 0 |
| Y=-50 | 是 | 0 | 0 |

建议：以墙实体平面轮廓的投影区间/多边形与切面相交判定；根据实际交集处理洞口，不能仅靠轴线定位。新增平行、斜墙、贴边、洞口边界和两种观察方向用例。

### P1：落图目前是追加，尚未实现更新既有 CAD 视图

位置：`BatchPdfPublisher/Features/BuildingModel/Services/BuildingModelCadBridge.cs:34`，多个 `AppendEntity` 调用。

当前流程读取视图文件、再次询问插入点、追加线/文字/标注/填充。没有看到为输出实体持久化 ModelId/ViewId/Revision 并查找替换上一版视图的实现。现有 Erase 用于删除创建失败的填充，不是更新旧视图。

影响：模型修改后再次落图会保留旧图；同点插入可能重影，换位置则多份图纸并存。不能把“重新生成 JSON”视为“CAD 图模联动完成”。

建议：先实现稳定建筑 ID、视图 ID、CAD 放置实例 ID；用块或扩展字典登记生成所有权与版本。同一视图可有多个合法放置实例，更新需逐实例定位，不能只按 ViewId 删除全部。提供更新/另存副本、差异预览、事务撤销，并把人工补绘从自动替换对象中分离。

### P1：保存失败后仍继续生成视图，可能形成图模版本不一致

位置：`BuildingModelStudio/Program.cs:893–911`。

`SaveModel()` 捕获保存异常后仅写日志并返回；`GenerateViewsNow()` 无论是否保存成功都继续使用内存模型生成视图。磁盘满、目录不可写或文件被占用时，落图文件可能对应未持久化的模型，重新打开后无法重现。

建议：保存返回成功结果或抛出可处理异常；失败停止“生成并发布”。视图携带模型版本/内容摘要；先写入完整暂存结果，再发布清单，失败保留上一版。预览可以使用内存模型，但必须与正式发布区分。

### P1：原子保存遇到 IOException 后退回直接覆盖

位置：`Shared/BuildingModel/BuildingModelJson.cs:156`。

`File.Replace` 失败后直接 `File.Copy(..., true)`，使“写盘一律临时文件+替换”的保证不成立。替代复制途中失败时，目标可能不是完整旧版或新版。此外静态 `lock` 只能保护同一进程，并不能阻止两个建模窗口覆盖同一模型。

建议：不能对所有 IOException 无差别降级覆盖。保留完整旧版/暂存文件，明确报错；模型保存加入磁盘版本比对与跨进程锁/单实例项目占用策略。用写入故障与双进程保存测试验证，而不只测试普通序列化往返。

### P2：生成全部视图直接运行在界面事件中

位置：`BuildingModelStudio/Program.cs:905`。

按钮事件同步执行 SaveModel、GenerateViews 和预览刷新。当前样例不大，不能从小样例通过推出大型模型不卡。复杂投影和批量文件写入会占用 UI 线程。

建议：界面线程取得不可变模型快照，后台计算；发布带版本的结果，旧请求结果丢弃；取消、进度、窗口关闭处理一起做。不得在后台直接读写仍被编辑的集合。

## 3. 计划与实现的差距

### 楼梯参数复用尚未兑现

`Shared/BuildingModel/ModelTypes.cs:160` 是新建的简单双跑 StairModel（步数、步宽、梯段宽、平台等），目前未找到它导入已有 `StairProjectDefinition` 或调用 `WL.Stair.Core` 的适配路径。门窗已有复用，楼梯仍是一套简化参数与算法。

计划应把“一个字段都不用重填、直接调用现有楼梯生成器”改为待实现项：先导入旧楼梯参数，明确楼层对应、旋转/平移、单双三跑和非标准平台支持范围；无法映射的参数必须提示，不能静默退化为双跑。

### 正式投影不能直接等同于三维画面优化

`VolumeRenderer.Project` 包含 `DropFacesBehindParallelPlanes`，其中有 600 mm 距离阈值和采样覆盖判断；轴测出图 `OrthographicProjector.ProjectAxonometric` 又使用该渲染结果。

这类规则可以作为预览优化，但它不是通用精确消隐的证明。需要用近距离分离平行面、狭缝、退台和细小外露轮廓建立几何基准，确认不误删实体后才用于正式矢量图纸。此处是需验证的算法风险，本次没有把所有情况认定为已复现错误。

### 权威计划内部仍有架构矛盾

`docs/建筑模型与立面剖面生成-开发计划.md` 已声明为唯一权威文档、采用独立程序自研投影，但约第 118 行仍说“不需要第三方投影内核（宿主已有）”；约第 34、413 行又将面深度排序和轮廓剔除描述成充分方案。两者应统一。

建议明确：独立程序架构保留；自研内核先限定已验证几何范围；几何正确性不达标时评估独立 OCCT 后端，不能因为“不在 CAD 中建模”而排除成熟外部内核。是否引入 OCCT 用同样例质量/性能比较决定。

原计划中的比例、自动化覆盖率、零重复输入等应作为目标，不能作为已达成事实。本次无需重新做产品选型调研，先修正文档状态和验收门槛。

## 4. 建议按这个顺序继续

| 顺序 | 内容 | 验收条件 |
|---|---|---|
| 1 | 剖切几何修正与自研投影范围清单 | 200 mm 墙偏移切面用例通过；墙交接、洞口与共面结果有人工基准 |
| 2 | 保存/发布事务、版本摘要、同项目并发保护 | 保存失败不发布；崩溃后能恢复完整上一版；旧视图可识别 |
| 3 | CAD 视图登记和受控更新 | 连续更新三次不重复；人工补绘保留；一次撤销恢复 |
| 4 | 楼梯参数适配与制图样式核对 | 现有项目导入无需重新手输已知参数；不支持项明确提示 |
| 5 | 后台生成、取消和规模测试 | 固定硬件上测 1000/10000 构件，记录 P95 延迟/峰值内存；不阻塞界面 |
| 6 | 三个真实项目试用后再扩展曲墙和复杂节点 | 原图、模型、立剖面、标注及打印结果逐项一致 |

2026-09-27 进展：第 5 项已将独立建模窗口的“生成全部视图 / 推到 CAD”改为模型快照后台计算、临时目录写盘、界面核对版本后发布；支持按钮取消和窗口关闭取消。真实窗口自检覆盖正常发布及编辑期间丢弃旧结果。1000/10000 构件的固定硬件耗时与内存测试尚未完成，因此第 5 项仍未验收。

不建议按功能按钮数判断完成率。当前定位更准确的是“具备编辑和出图能力的原型”，距离“模型修改后可靠更新正式 CAD 图纸”仍有明确的工程任务。
