# 独立建筑软件与 MiniCAD 技术评估

日期为 2026-11-12。评估源码固定在 MiniCAD 提交 `9740e7fbc288f1ea5a71af2b89503fce1496389c`，该提交的工程版本为 0.8.4。万落当前产品版本继续使用 1.5.6。

## 结论

MiniCAD 有较高参考价值。优先验证其 MiniDWG 文件交换层、天正对象解析和二维编辑架构，逐步建立万落自己的独立绘图能力。

万落可以采用 WPF 桌面界面，保留现有建筑语义模型、工程管理、共享图库和导出核心，并增加独立的图纸文档与绘图服务。AutoCAD 接口作为一种可选协同入口。独立模式的验收条件是机器未安装 AutoCAD 时，也能完成约定的打开、编辑、建模、保存和出图流程。

本轮重新核对上游 main，仍为同一提交。已完成 MiniDWG 与项目内 MiniI18n 的独立编译、自带 46 项测试，以及一张 AutoCAD 2022 临时图在中文路径下的读取和同版本内存写回／回读。完整 MiniCAD 应用、真实天正工程、跨软件回读审核、复杂出图及性能仍待验证。以下路线属于实施建议。

| --- | --- | --- |

| UI 与平台 | 自有 MiniGUI，平台应用与核心分离 | 参考职责划分，万落界面按 WPF 方向设计 |

MiniDWG 的 DWG 读取范围记载为 R13～R2018，写出包括 R2000、R2004、R2010、R2013、R2018。具体对象与版本组合需要样本验证。其源代码来源记录为 ACadSharp 的 C# 实现移植，后续也可将原始 ACadSharp 纳入同一组文件兼容性对照。[MiniDWG 文档](https://github.com/CHMOSE023/MiniCAD/blob/9740e7fbc288f1ea5a71af2b89503fce1496389c/docs/MiniDWG/README.md) [来源声明](https://github.com/CHMOSE023/MiniCAD/blob/9740e7fbc288f1ea5a71af2b89503fce1496389c/THIRD_PARTY_NOTICES.md)

天正墙解析保存起终点、左右厚度、弧墙角度和连接信息。该层与我们登记建模的需要相关，仍须核对高度、标高、材料、洞口编号及原始对象身份等生产所需字段。门窗类别有解码失败原因记录，能够作为兼容性报告的基础。[墙解析源码](https://github.com/CHMOSE023/MiniCAD/blob/9740e7fbc288f1ea5a71af2b89503fce1496389c/src/Import/TchWall.h) [交换层实现](https://github.com/CHMOSE023/MiniCAD/blob/9740e7fbc288f1ea5a71af2b89503fce1496389c/src/Import/CadExchange.cpp)

## 落地前需要验证的边界

- 未建模的对象采用原始数据保留策略。同格式、同版本写回与跨格式、跨版本写出有不同处理，需要明确记录受影响对象。天正对象还涉及显示几何与原始语义之间的对应。[对象保留规则](https://github.com/CHMOSE023/MiniCAD/blob/9740e7fbc288f1ea5a71af2b89503fce1496389c/docs/MiniDWG/README.md) [交换接口](https://github.com/CHMOSE023/MiniCAD/blob/9740e7fbc288f1ea5a71af2b89503fce1496389c/src/Import/CadExchange.h)
- 当前检阅的应用命令与核心代码尚未找到能直接承接我们完整批量打印流程的实现。CTB／STB、SHX／大字体、布局视口、外参、图框属性、毫米纸张、线宽、裁剪和 PDF 都需要专门的出图验证。[应用命令入口](https://github.com/CHMOSE023/MiniCAD/blob/9740e7fbc288f1ea5a71af2b89503fce1496389c/apps/Common/src/GUI/MainCommands.cpp)
- 主仓库为 MIT，第三方声明还列出字体等组件的独立许可。复用时应保留对应版权与许可，并核对实际打包的组件清单。实体内核的来源与许可另有说明。[主许可证](https://github.com/CHMOSE023/MiniCAD/blob/9740e7fbc288f1ea5a71af2b89503fce1496389c/LICENSE) [第三方声明](https://github.com/CHMOSE023/MiniCAD/blob/9740e7fbc288f1ea5a71af2b89503fce1496389c/THIRD_PARTY_NOTICES.md) [SMLib 说明](https://github.com/CHMOSE023/MiniCAD/blob/9740e7fbc288f1ea5a71af2b89503fce1496389c/3rd/SMLib/README.md)

## 结合万落现状的结构

本仓库已有 `BuildingModel.Core`、`Shared/BuildingModel`、独立建筑模型程序和导出工作进程。发布脚本当前使用 .NET 8 Avalonia 建筑模型编辑器，旧 Windows Forms 工程用于回归，仓库另有 WPF 试验工程。本轮 WPF 改造覆盖 BPP 主窗口及关联窗口。

CAD 宿主相关代码集中使用 Autodesk 的 Document、Database、ObjectId、Editor、事务和打印接口。独立化需要替换这些底层服务，同时继续复用工程数据、图框登记、排序、统计、图库和建筑模型业务。

本轮确认的具体接口差异包括以下内容。

- `TchWall` 暴露起终点、厚度、圆心角、材质及连接句柄，多个解码分支读到的墙高只参与局部校验，尚未保存为该结构的公开字段。接入万落时需补齐高度和楼层标高映射。
- `TchOpening` 提供洞口位置、宽高、方向、标签和宿主墙句柄，可作为匹配既有参数门窗的输入，仍需对照真实编号、标准层与分格保留规则。[墙字段](https://github.com/CHMOSE023/MiniCAD/blob/9740e7fbc288f1ea5a71af2b89503fce1496389c/src/Import/TchWall.h) [门窗字段](https://github.com/CHMOSE023/MiniCAD/blob/9740e7fbc288f1ea5a71af2b89503fce1496389c/src/Import/TchOpening.h)
- MiniCAD 的场景导出接口需要携带原图 `CadSource`，同格式、同版本写回才采用原图作为基础。编辑后的场景、原始自定义对象和句柄关联需要统一维护。[交换接口](https://github.com/CHMOSE023/MiniCAD/blob/9740e7fbc288f1ea5a71af2b89503fce1496389c/src/Import/CadExchange.h)
- BPP 的 WPF 界面已经迁移，当前 ViewModel、图框扫描及 PDF 生成仍直接调用 Autodesk 文档与打印接口。独立化应保留图纸列表、顺序和输出组织，并增加独立扫描及出图实现。

建议形成以下职责关系。

```text
万落 WPF 工作台
  ├─ 工程、图纸列表、图库、房间统计、建筑模型和导出
  ├─ 业务核心与统一工程数据
  ├─ 独立二维文档、选择、夹点、捕捉、命令和撤销
  ├─ 独立绘图与 PDF 出图服务
  └─ 图纸适配层
       ├─ MiniDWG／其他候选读写器
       └─ AutoCAD／天正协同接口
```

C# 与 C++ 交界采用明确的数据结构、单位、版本和错误返回。可先沿用已有导出工作进程的组织方式做读取验证，测量启动、文件读取和数据传输开销，再决定正式集成方式。构件始终保留万落稳定 ID，并另存原图句柄、来源文档和楼层对应关系。

CAD 与三维共用一个本地构件目录及稳定资源 ID。既有参数门窗、标准层实例、分格修改、登记替换和导出行为继续纳入兼容性验收。

## 本轮独立库实测

测试在私有构建目录内进行，采用 MSVC、C++20、Release，独立编译上游 MiniDWG、MiniI18n 及其 Serialization 测试。生产源码及安装程序维持本轮评估前状态。

| 检查 | 结果与边界 |
| --- | --- |
| 上游版本 | main 仍为 `9740e7fbc288f1ea5a71af2b89503fce1496389c`，工程版本 0.8.4 |
| MiniDWG 自带测试 | 使用仓库 21 个 DWG／DXF 样本，46 项测试全部通过，覆盖数据库、版本、读写、压缩、校验和及跨版本等用例 |
| 中文路径 | 使用 Windows 宽字符文件路径读取字节，再交给 MiniDWG，成功读取中文目录中的临时图 |
| AutoCAD 2022 生成的临时图 | 原文件 14,431 字节，读取 151 个对象；同版本内存写出 13,228 字节并回读 151 个对象，跳过类型数为 0，原样保留类型数为 5 |
| 外部软件验收 | 上述写回结果由 MiniDWG 自身回读，AutoCAD／天正打开及审核尚待开展 |

第一次自带测试沿用中文源码目录作为样例路径，上游测试程序未正确读到样例，并在后续测试中异常退出。改用英文样例目录后 46 项通过。另写的读取验证采用宽字符路径，确认了中文文件路径到内存字节的读取链路。MiniDWG 的核心接口接收内存数据，产品中的路径处理由文件适配层负责。

这些结果确认了文件库能在本机单独编译和运行。真实天正墙／弧墙、门窗和房间的提取完整性、编辑后的语义保留、大图性能、字体与打印效果继续列为后续验收内容。

## 建议实施顺序与交付条件

### 第一步　独立读图验证

建立可重复的命令行读图验证入口，打开 DWG／DXF，输出图层、块、属性、模型与布局、天正墙／门窗／房间的统计和失败原因。

对用户选定的工程副本与当前 CAD 提取结果逐项对照，包括直墙、弧墙、洞口位置、标准层、带 Z 坐标对象和外参。记录读取耗时、峰值内存和异常恢复情况。此阶段达到“能够判断候选内核是否适合真实项目”的交付条件。

### 第二步　独立浏览与登记建模

在 WPF 工作台打开图纸，提供平移缩放、图层开关、楼层框选、基点、捕捉和参数修改，并接到现有建筑模型核心。进度、识别遗漏和待修正项可直接查看。机器未安装 AutoCAD 时也能完成登记、生成和模型保存。

### 第三步　二维编辑与往返保存

加入直线／多段线／圆弧、移动复制、旋转、修剪、圆角、文字、块与属性、线条校正和撤销重做。用另存副本的回读检查验证实体数、句柄关联、尺寸、文字、布局和外参。天正对象编辑后采用的保存表达需要明确展示给用户。

### 第四步　独立批量出图

接上 BPP 的图框、页码、CAD 文件／子项目顺序、目录、预览与合并发布。先验收模型空间和普通布局，随后验证复杂视口、打印样式与字体。A3、A2、加长图纸需要同时核对 PDF 页面尺寸和内容实际比例。

### 第五步　独立产品整合

统一启动、工程文件、恢复、保存、模型管理、图库和安装升级。以未安装 AutoCAD 的测试机器完成一套真实工程从打开到 PDF／FBX／SKP 交付的闭环，再确定独立版的正式兼容范围。

## 下一次适合开始的工作

用户已确定从同一启动器选择进入独立版，或打开 AutoCAD／天正，具体实施顺序以 [统一启动器与独立版双入口开发计划](统一启动器与独立版双入口-开发计划-2026-11-12.md) 为准。

首批完成统一启动器路由、WPF 项目入口和独立工作台，同时推进读取兼容性原型，产出真实样本对照表，再据结果确定 MiniDWG、天正解析层和绘图内核的正式选型。WPF 界面、模型核心与共享图库按上述职责边界演进。
