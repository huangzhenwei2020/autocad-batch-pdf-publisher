## 1. 产品范围

建议统一名称为“构件图库”。公共层管理分类、资源包、二维符号、三维模型、预览、来源和版本；放置行为按类别处理。第一阶段做门窗，后续家具、洁具、设备复用资源层，不继承门窗的沿墙开洞逻辑。

| 类别 | 放置方式 | 专有参数 | 后续范围 |
|---|---|---|---|
| 门窗 | 沿墙吸附，语义洞口开洞 | 编号、洞口宽高、窗台、门槛、扇运动及方向 | 首期 |
| 家具 | 楼面落点、旋转，后续靠墙 | 型号、长宽高、离地、材质 | 后续，不在首期开放空入口 |
| 洁具、设备 | 落地、壁挂等对应宿主 | 型号、安装高度、安装面 | 后续 |

二维与三维可以不同：CAD 平面用于制图，三维模型用于视觉。二者必须共享尺度、基点、朝向和可动部件绑定，不能把三维网格投影成一堆 CAD 三角线。

## 2. 保留现有能力

- `MM` 保留为门窗选型入口，增加“公共库”来源，不另起一套不兼容的放置工具。现有项目、项目模板和内置图例继续可用。
- 当前 `OpeningTemplates` 是参数模板，不是磁盘资源图库；不把原有模板数组改成外部文件路径。
- 项目语义数据仍决定洞口、编号、窗台、门槛、宿主和标准层。三维资产不负责切墙，不反向覆盖识别结果。
- 无外部资源仍能使用现有参数化生成器，旧模型无需迁移才能打开。
- 现有左右/内外翻转、编号夹点、沿墙居中、墙端净距输入、开启角度及撤销保持。立面开启线尖端指向合页，通用双扇门合页在两侧外框。

## 3. 用户制作流程

1. CAD：按毫米、1:1 画块，选块并指定基点、墙方向和墙法向，填写洞口尺寸与类别。提取受支持的矢量图元，不强制用户重新画已有块。
2. 3ds Max：按实尺寸建模，把固定框、每个可动扇和可替换门槛分为独立对象。三维资产通过 GLB 导入，原生 `.max` 只作为可选作者源文件保留。
3. 配对编辑：载入 CAD 符号与 GLB，核对单位、方向、洞口边界；给每扇绑定二维组、三维节点、合页/推拉轴，测试角度与翻转。
4. 验证后保存到本机公共库；MM 选中后先设置实例参数，再沿墙放置。用到的资源自动复制到项目内，跨电脑不依赖原作者文件路径。

建议规范化局部坐标：X 沿洞口从左到右，Y 为墙法向，Z 向上；基点为洞口左端、墙参考线、洞口底。作者可以保留自己的基点，通过向导转换，不能用模型最长边猜朝向。家具以后另有落地基点规则。

3ds Max 目标版本尚待用户确认。2026 官方 GLB 导出说明保留对象名称，但层级会扁平化，不导出动画、蒙皮和变形数据；因此不能依赖 MAX 原层级或控制器。首期在配对编辑中明确部件绑定，验证完手动导出闭环，再考虑可信的 MAX 导出辅助工具。旧版不支持 GLB 时另做 FBX 转换适配，不假装原生读取 MAX，也不为首期引入未经验证的全格式转换器。[Autodesk 官方说明](https://help.autodesk.com/cloudhelp/2026/ENU/3DSMax-Interoperability/files/GUID-5B4C8EC2-2230-4F9F-B3C6-48D9E347E37D.htm)。

## 4. 两个界面

### 图库选型

沿用独立软件的紧凑工具窗口，不新增大型 Ribbon。主窗口 Ribbon 保留 MM，管理页增加图库入口；工具图标复用现有统一资源，每个操作提供提示。新的命令名另行确认，不能抢占 CAD 现有命令。

- 顶部：搜索、来源筛选、导入/导出、创建模板。
- 左侧：类别树与来源；首期只开放真实可用的门窗分类，支持收起。
- 中间：可切换列表/缩略图网格，显示编号、名称、实尺寸、来源及可编辑能力；缩略图显示真实平面或三维，不用装饰占位图。
- 右侧：平面/立面/三维预览页签，下面是实例参数。宽高若被资产锁定，明确锁定而不是允许输入后悄悄拉伸；缺失部件给出具体状态。
- 底部：选中项状态、取消、放置；管理操作不与放置确认混在一起。
- 门窗“编号”与资产名称分开，编号由实例注释生成；家具未来显示“型号”，不显示无关窗台或门槛字段。

建议基准窗口 1120 x 760、最小 800 x 600，工具条 36、输入 32、行 40、间距 8/12 逻辑像素；小窗口收起类别栏，参数栏独立滚动，预览有稳定尺寸。这些是待核对的布局参数，不是已完成设计图。

### 配对编辑

独立编辑窗口，建议基准 1360 x 860、最小 960 x 680。采用“工具条＋工作区＋属性栏”，不给每个步骤套卡片。

- 顶部：基本信息、二维、三维、部件绑定、校验五个页签；保存/另存为与取消位置固定。
- 二维页：CAD 矢量画布，显示洞口边界、参考线和基点；可选择静态框、门扇、开启符号与编号锚点。
- 三维页：真实资产预览与节点列表，可拾取/高亮节点；设朝向、基点和原尺寸。
- 部件绑定页：二维/三维并排联动，点选同一扇；右栏设置固定/平开/推拉、合页位置、运动轴、符号生成规则、门槛替换规则。平开、推拉只显示对应参数。
- 校验页：闭合、15/30/45/90 度、左右/内外翻转测试；显示未绑定、尺寸不符、缺资源和不支持实体的清单，不用一个笼统“导入成功”掩盖问题。
- 应用前都是草稿，可取消；校验通过才启用保存。资产保存是明确操作，不能随预览改公共库或所有项目。

第一阶段先审定这两页的视觉稿，再实现。字体、边线、间距、按钮图标与现有工作台一致，不能把本方案的文字结构当成逐像素验收图。

## 5. 二维符号不是整块图片

- 首批支持 LINE、ARC、CIRCLE、带 bulge 的二维 POLYLINE/LWPOLYLINE 和可解析的静态嵌套块。保留原生圆弧及闭合路径，不烘焙为密集短线。
- CAD 桥接负责块变换与毫米归一化；动态块只读取当时可见的有效形态，不承诺保留所有动态参数。外参、代理实体、3D 实体及未知对象给出拒绝/跳过清单，不能静默用包围框代替。
- 镜像、非等比缩放后不再是圆的圆弧需要受支持的椭圆表示或明确拒绝；不能保留错误半径。
- 固定框和活动扇分组保存，合页用于转动扇，不转动整块。作者必须声明二维基准姿态；无法绑定的符号只支持静态显示，不开放虚假的开启角度编辑。
- 开启弧/箭头优先按合页及净扇宽生成，避免整块固定符号与新的开启角度叠加。导入已有开启线时必须标记替代范围，不能保留旧线再画一套。
- 识别编号文字/属性作为候选锚点，经用户确认后排除硬编码文本，实例生成编号，保留编号移动夹点。
- 原 CAD 图层作为来源信息保留，输出通过制图规范的用途映射。新增符号不能绕过已有图层、纸面线宽、字高与宽度因子管理。
- 实体轮廓与符号线分别标记，图纸实体轮廓向内加粗，开启弧等符号中心描边；不改变真实尺寸。
- 独立程序不装 AutoCAD SDK；DXF 直接导入列为后续，用成熟解析器并执行同一实体校验。

## 6. 三维与尺寸边界

- GLB 解码复用现有 SharpGLTF 依赖，正式选型前验证其读取、节点变换和材质能力；不手写二进制 glTF 解析器。
- GLB 单位/轴向按规范转换为内部毫米、Z 向上。保留节点变换与法线；负比例镜像需处理绕序与法线，不能只改包围盒。[Khronos 坐标约定](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#coordinate-system-and-units)。
- 每扇记录稳定部件 ID、资源节点定位、局部合页/运动轴与闭合变换。节点名只能作导入辅助，重复名称必须由用户明确选择。
- 三维默认闭合，实例开关控制是否使用平面角度；框不跟门扇旋转。门槛节点有替换/隐藏策略，不能与程序门槛重复。
- 按 2026-10-07 最新要求，尺寸能力与活动扇绑定一起设计：资源区分固定规格、规则可变尺寸两类。只读 GLB 校验和未声明尺寸规则的模型仍锁定，规则资源按下文部件约束调整；不直接把型材厚度一并拉伸。
- 分区尺寸规则属于首批可变尺寸门窗的放行条件，不留到完整图库之后补。家具以后另行声明尺寸规则，不默认任意拉伸。
- 首期显示基础色，并明确透明/贴图支持范围；不将读入材质数据称为完整 PBR 材质编辑。真实材质、贴图缓存与材质预览单独验收。
- 建筑立面/剖面仍由现有语义构造生成。外部网格不保证自动获得对应 CAD 立面细节；额外二维立面表达列为后续独立资源。
- 三维资产必须参与拾取、可见性、标准层和 GLB 导出，不能仅在预览小窗口显示。对象身份可追溯，家具以后沿用同样要求。

## 7. 资源与身份

沿用拟议扩展名 `.wlopkg`：清单、plan.json、model.glb、preview.png 和可选材质资源。原始 DWG/MAX 可选择附带，但不作为运行依赖。

- 通用资源定义：AssetId、Revision、Category、Name、尺寸、基点/轴向、资源路径和哈希、缩略图、二维组、三维部件、能力声明、作者/来源。
- 门窗绑定：现有 OpeningTypeModel 只新增资源引用及对应语义适配数据；资产 ID、版本、项目编号三个身份分离，不能只按 M0921 定位网格。
- 家具后续新增独立实例类型，不把家具塞进 OpeningModel 或伪装成没有宿主的门。
- 本机库用于创作复用；放置时固定资产版本与内容哈希，复制到项目受控目录。公共库更新不自动改变已经落地的项目。
- 项目模型仍存实例与类型，资源文件不直接塞进 model.json。跨电脑打包同时带引用资源；首次加载缺资源有明确状态与回退。
- 用到的图库条目从本机删除不删项目副本。项目引用不能无提示删除；失败导入不留半成品，资源替换可撤销，旧版本待无引用后再清理。

## 9. 安全与性能

- 限制压缩包展开体积、文件数、压缩比、嵌套路径、网格/顶点数量与纹理尺寸；拒绝绝对路径、路径穿越、链接逃逸、无效/非有限坐标、外部网络 URI、未知必需扩展。不自动执行附带脚本或读取文件包以外资源。
- 导入与解码异步、可取消；暂存校验完整才写入，失败保持模型不变。哈希校验不替代路径/体积安全检查。
- 同资源/版本的实例共享解码结果和 GPU 网格，逐实例仅变换与选择状态；缩略图列表虚拟化并延迟加载，关闭编辑取消未完成任务。
- 先测一个资源，再测山水湾多层实例；分别记录首次加载、移动/翻转/开启预览、提交、内存、帧时间与导出。缓存测试不冒充整栋帧率。
- 测试场景包含斜墙、偏心墙、双侧镜像、标准层单实例覆盖、同编号冲突、资源替换撤销、跨电脑相对路径、取消、异常包与缺少部件。

## 建议下一步

### 2026-10-07：三维开闭部件方案（待实施）

用户要求图库后续能控制外部三维门窗的开启和关闭。推荐“固定构件 + 活动扇组”，而不是把整樘门窗作为一个刚体旋转。当前 GLB 来源校验虽保留节点身份，但尚未实现正式资产部件绑定、实例运动或项目放置；以下属于下一段方案。

| 部件 | 组织与运动 |
|---|---|
| 门套/外框、固定中梃、上亮、固定玻璃 | 固定组，不受开扇状态影响 |
| 每一活动扇 | 独立组；扇框、玻璃、门板、把手等可为多个网格，绑定同一个 PartId，共用运动变换 |
| 门槛 | 单独固定角色，后续按已有门槛语义处理替换/高度，避免与程序门槛重复 |
| 导轨 | 固定组，推拉扇在独立轨道上平移，不随扇移动 |

- 作者以**关闭姿态**提供 GLB，双扇分别命名 `leaf_L`、`leaf_R`；固定框可用 `frame`。名称仅用于建议识别，用户确认实际网格绑定后生成稳定 PartId；不能仅凭名称猜合页。
- 在配对窗口中点选一扇，可把扇框、玻璃、把手等多个节点归到该扇。记录资源修订内的节点定位、闭合基准变换、运动类型、合页轴点/单位方向，或推拉轨道/最大行程。绑定后的部件局部坐标与整个资产基点必须明确，不能混用源节点坐标和世界坐标。
- 平开围绕真实合页轴转动；门/侧开窗通常用竖轴，上悬/下悬用水平轴；推拉使用轨道位移。双扇默认两侧合页，分别设置旋转符号；内外翻转与左右翻转必须变换轴和开启方向。没有声明运动的部件保持固定。
- 三维默认关闭。选择实例后提供“显示开启”开关、角度预设/输入；关闭只将三维呈现归零，保留用户设定角度和 CAD 平面表达。推拉用开启比例或位移，而不是伪造角度。双扇可联动，也可分别设置；可短时过渡，但首期不依赖导入动画。
- CAD 平面单独绑定固定组、活动扇/开启符号组及编号锚点，保持此前门实扇、窗单线虚线表达。三维开闭不能自动让图纸上的门扇也关闭；可另外显式提供“同步平面角度”。没有二维组绑定的外部符号只允许静态显示，不叠加一套无法对应的开扇线。
- 从不可变关闭基准计算每次运动，不能反复变换已转动顶点。目标是缓存网格、逐扇/逐实例更新变换，不重复解码 GLB、不重算墙洞；具体 GPU 路径及山水湾多层性能需实现后测量，不能提前声称已优化。
- 类型资产保存运动能力和默认值；实际开闭状态存实例，不改公共库或其他同编号门窗。标准层默认共享须沿现有模型规则，独立楼层/实例设置须明确其作用范围。提交一次形成一次撤销；开闭预览不能破坏已应用修改。
- 首批验收：固定窗、单扇门、双扇加上亮、双扇平开窗；验证 0/15/30/45/90 度、闭合回位、玻璃/把手随扇、外框不动、镜像与斜墙、保存重开、撤销、场景/导出一致。推拉随后；折叠、卷帘等复杂运动不在首批装作已支持。

Max 2024 官方明确 GLB 导出不带动画、蒙皮或变形数据，并会压平层级；对象名称会保留，重复名可能改名。因此我们的清单必须独立记录扇组及合页/轨道，不能只依赖 Max 的组层级、Pivot 或动画控制器。[Autodesk 2024 官方说明](https://help.autodesk.com/cloudhelp/2024/ENU/3DSMax-Interoperability/files/GUID-5B4C8EC2-2230-4F9F-B3C6-48D9E347E37D.htm)。

### 2026-10-07：可变尺寸与开闭共同约束（待实施）

新增要求：导入门窗必须考虑用户改洞口宽高。尺寸不是整樘模型缩放，也不能仅更新语义洞口而让外部模型保持旧尺寸。活动扇、合页和二维表达共用同一套尺寸结果。

| 部件 | 尺寸规则 |
|---|---|
| 左右外框、扇框竖料 | 随边界移动、沿长度方向调整；截面宽度、进深保持原值 |
| 上下横料、活动横料 | 按净宽调整长度；截面尺寸不随洞口缩放 |
| 玻璃、规则门板 | 按净格尺寸调整宽高；厚度、边缝独立保持 |
| 上亮、固定格、中梃 | 按作者声明的固定尺寸、等分、比例或边界偏距规则排布 |
| 把手、合页及其他五金 | 刚体移动，按所属扇边距/指定高度定位，不改变自身尺寸 |
| 门槛、导轨 | 按洞口净宽和独立高度/轨道规则调整，保持截面 |
| 合页轴、推拉行程 | 由改变尺寸后的关闭构造重新求得，再应用开闭状态 |

- 资源能力区分 `固定规格` 与 `规则可变尺寸`；固定规格可提供多个真实规格，选型不假装任意改尺寸。没有绑定/无法参数化的复杂雕花、曲面等网格只做固定部件，不猜测其变形方式。
- 首批可变资源必须声明参考洞口宽高、有效最小/最大尺寸、安装间隙、部件边界锚定、长度变化轴、固定截面及分格约束。把尺寸规则和部件运动规则存入同一版本化资源定义，现有 v1 参数包与静态来源检查不因此被称为已支持。
- 作者用关闭姿态制作；对于带精细端头、连接件或纹理的型材，推荐拆成刚性端部与可变中段。只伸缩明确声明的中段，不拉伸端角、五金或整樘模型。多网格可属于同一个运动扇，但尺寸规则可各自不同。
- 分格支持固定上亮高度、双扇等宽、子母扇固定小扇/剩余大扇等规则；固定约束优先后计算剩余空间。规则互相冲突、净格为负、五金越界或超过声明范围时拒绝应用并保留旧实例，给出具体原因。
- 同一尺寸解驱动 CAD 固定框/扇组、三维部件和合页/轨道。不能对整块 CAD 符号等比缩放来伪造可变能力；没有二维规则时需补绑定或退回参数化符号，提示用户，不能静默让二维与三维不同尺寸。
- 执行顺序：验证洞口与宿主 → 解算关闭构造/净格 → 调整明确允许的部件 → 重算轴与行程 → 应用实例开闭 → 更新编号和视图。始终从资源原始关闭基准计算，不在已缩放/已开启顶点上再次变形。
- 修改范围沿现有“当前一樘／同编号类型”选择；尺寸自动编号、重名合并/新后缀继续使用现有规则。合并到已有编号意味着采用该类型的完整资产与规则，不能只改编号后保留另一套外部几何。公共库资源不随项目尺寸修改。
- 若改尺寸导致推拉开度超过新行程等实例状态不再有效，在应用前明确提示调整后的状态，不静默保存越界值。宽高、资产引用、编号、分格及运动状态一起提交，失败不留半改，一次撤销恢复整笔。
- 验收加入放大/缩小宽高、固定上亮、子母扇、厚度与五金不变、改尺寸后开闭回位、尺寸越界拒绝、编号冲突、单实例与同编号范围、斜墙/镜像、保存重开/CAD及模型导出。先在少量样例验证规则，再测试山水湾多层变尺寸性能。

先确认制作约定和目标 Max 版本，完成“图库选型＋配对编辑”视觉稿，再开始 P1；首批用固定窗、单扇门、双扇加上亮三份可重复样例，不一下子铺开整套家具库。
