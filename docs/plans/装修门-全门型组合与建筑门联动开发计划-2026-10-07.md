本计划落实用户的新定位：原有门窗功能中的门称为“建筑门”，本轮共享 CAD／三维图库进一步发展为“装修门”。装修门需要按门套、门扇、五金等组合，先选类型和尺寸，再确定项目编号。本文覆盖住宅、办公、商业和酒店装修中常见的门型及扩展门型，不把“列入计划”当作已实现，也不声称穷尽所有厂商的特殊机构。

## 1. 建筑门与装修门的关系

| 项目 | 建筑门 | 装修门 |
|---|---|---|
| 主要任务 | 墙上洞口、楼层、定位、编号、建筑平立剖与统计 | 门套、门扇、玻璃、把手、合页、轨道、饰面与安装细节 |
| 既有数据 | 宿主墙、洞口宽高、位置、建筑类型与分格 | 引用门组合资源、部件参数、安装方式、材质与动作规则 |
| 用户入口 | 继续现有放门、CAD 登记、门窗表与参数门窗 | 同一“图库”入口内的装修门分类及已有模型属性面板 |
| 两者联动 | 提供洞口及项目语义 | 在该洞口内生成安装组件；变化经过同一编辑事务 |
| 编号与数量 | 项目的一樘门及其编号 | 沿用该樘门身份，不另建一个重复统计的门 |

具体规则：

- 已有建筑门可以“配置装修门”，先预览后应用，不重新切墙、不重复添加洞口。既有参数门窗继续使用原路径，不强制转换。
- 新建装修门时，如果有宿主墙，创建一樘建筑门及其装修配置；如果放在已有洞口，绑定该洞口。玻璃隔断内的门必须有隔断开口语义，不能假装挂在不存在的墙上。
- 两个阶段采用同一实例 ID。隐藏装修细节后可显示建筑简化表达；详细表达启用时替代简化门扇，避免两套门套／门扇同时重叠。
- 一樘门的部件不是额外的门：子母门统计为一樘、两扇；把手和合页进入部件清单，不进入门窗樘数。
- 装修资源改变外形，不自动改变洞口。需要改洞口时明确填写新洞口尺寸，同步检查宿主墙、相邻洞口、楼层和规则范围，再整体提交。
- 平面和三维细节可以不同，但基点、洞口、安装朝向、门扇、合页和运动状态必须对应。
- 装修门不能仅靠外观“升级”为防火、防盗或隔声门；性能为可追溯的产品资料字段，未确认的数据保持未指定。

## 2. 分类方式：机构、组合、构造与用途分开

不要用一个长下拉框把“木门”“子母门”“隐形门”“厨房门”互相排斥。这些可以同时属于同一樘门：例如木质、子母扇、隐形门套、书房用途。

| 分类维度 | 规划选项 |
|---|---|
| 开启机构 | 单向平开、双向平开、轴转、平移、联动平移、折叠、平折／转滑、折叠收纳、旋转、卷收／提升 |
| 门扇组合 | 单扇、等分双扇、子母扇、多扇；活动扇＋固定侧板；带上亮／侧亮 |
| 门套与安装 | 普通包套、单面／双面包套、平齐隐藏框、无装饰套、金属窄框、无框玻璃、墙外挂轨、墙内暗藏轨 |
| 门扇构造 | 平板、框芯、造型／拼板、玻璃、铝玻、金属、格栅／百叶、软质折叠等 |
| 用途 | 入户、卧室、书房、厨房、卫生间、阳台、办公、酒店、公区、设备／检修等 |
| 附加配置 | 把手／拉手／拉槽、锁具、合页／地轴、闭门器、插销、门吸、密封条、门槛／下沉密封、自动驱动等 |

“免漆、烤漆、实木、复合、覆膜、皮革饰面”等属于材料或饰面规格；“长虹、磨砂、透明”等属于玻璃样式，不重复实现开启算法。自动驱动是一项配置，自动平移门仍使用平移机构。

## 3. 常见门型覆盖矩阵

阶段代号见第 11 节。以下每类都列入总体计划；分阶段发布，不在第一版放置尚未支持的空菜单。

### 3.1 平开与转轴类

| 门型 | 核心组合 | 尺寸／动作重点 | 阶段 |
|---|---|---|---|
| 单开室内门 | 门套＋一扇＋合页＋把手／锁 | 左右、内外开；净扇宽高、门缝、固定截面 | R1 |
| 等分双开门 | 门套＋两扇＋各扇五金 | 两扇等宽或自定义；合页在各自外侧；开闭可分别控制 | R2 |
| 子母门 | 门套＋母扇＋子扇＋五金 | 子扇固定宽度／比例／明确双扇宽度；活动／常闭扇及插销 | R2 |
| 双向平开门／自由门 | 门框或无框＋一／两扇＋双向轴件 | 有符号的开启角、双向限位、关闭基准和净通行宽 | R4 |
| 中轴门／偏轴门 | 门扇＋上下轴件＋框或隐藏框 | 轴距边、两侧回转空间、地面／顶面安装关系 | R4 |
| 隐形门／墙面齐平门 | 隐藏框＋门扇＋隐藏合页＋饰面 | 门套不是“删除所有框”；墙面齐平、饰面厚度、关门缝和可选暗拉手 | R2 |
| 无框玻璃地弹门 | 玻璃扇＋门夹／地轴＋拉手 | 玻璃厚度不随尺寸拉伸；角夹、轴和拉手刚性定位 | R4 |
| 窄框铝玻平开门 | 细框扇＋玻璃＋框＋五金 | 框截面固定、玻璃净尺寸与分格、普通合页或专用轴件 | R2／R4 |
| 通顶门／高门 | 平开组合＋高门规格 | 高度范围、五金数量与位置规则；不可无限延伸 | R2 |
| 带上亮、单／双侧亮门 | 任一适用平开组合＋固定框玻璃／实板 | 洞口总宽高与活动门区分；门套／中框／分格优先级 | R2 |
| 百叶门／格栅门 | 门框扇＋百叶／格栅＋五金 | 节距、数量和余量解算；小比例输出简化，细节不污染平面 | R2 |
| 半门／上下分扇门 | 门套＋上下独立扇＋连接锁件 | 上下净高、分缝、分别转动和联动状态 | R4 |

### 3.2 推拉与隐藏收纳类

| 门型 | 核心组合 | 尺寸／动作重点 | 阶段 |
|---|---|---|---|
| 单扇外挂推拉门 | 门扇＋上轨／下导向＋拉手 | 墙外挂置、遮盖量、行程与墙侧收纳空间 | R3 |
| 谷仓门／明轨门 | 门扇＋外露轨道＋滚轮＋挡块＋导向件 | 作为外挂推拉的外观／五金配置；滚轮刚性随扇、轨道固定 | R3 |
| 双扇对开推拉门 | 两扇＋轨道＋各扇五金 | 关闭中缝、左右行程、对称联动或独立操作 | R3 |
| 双轨双扇错位推拉门 | 两扇＋两轨＋五金 | 两扇不同进深、搭接一次、轨道净距、有效通行宽 | R3 |
| 三／四扇多轨推拉门 | 多扇＋多轨＋固定扇可选 | 扇数、轨道数、排列、搭接链、轨道占深和收纳状态 | R3 |
| 联动／套叠推拉门 | 多扇＋联动五金＋分轨 | 主从行程、分段启动、速度关系和实际堆叠；不能所有扇同量平移 | R4 |
| 单／双扇墙内暗藏门 | 活动扇＋暗藏腔＋轨道＋隐藏框 | 预留腔、墙厚、收纳长度；不得通过整面墙切大洞模拟 | R4 |
| 同面闭合推拉门 | 门扇＋专用偏移轨道＋五金 | 开启前出／入平面，再平移；关闭位置与最终密封位置不同 | R5 |
| 提升推拉门 | 框扇＋提升／滑移五金 | 提升与滑移阶段、门槛、搭接和专用型材规格 | R5 |
| 转角无立柱推拉组合 | 两向扇组＋专用轨道＋角部连接 | 两面洞口／隔断关系、角部相交和先后顺序 | R5 |

吊轨、地轨、无地轨是安装配置，木扇、玻璃、铝玻是构造配置，厨房／阳台是用途配置。不能因为名称不同复制三套平移求解器。

| 门型 | 核心组合 | 尺寸／动作重点 | 阶段 |
|---|---|---|---|
| 两扇折叠门 | 两个折叠叶片＋连接合页＋端轴／导向轨 | 叶片链约束、转角与导向位置同时求解 | R4 |
| 多扇单侧／双侧折叠门 | 多叶片＋铰接链＋轨道＋端框 | 叶片数、收纳侧、折叠堆叠进深、连杆一致性 | R4 |
| 平折门／转滑门 | 主副扇＋专用转动／滑移五金 | 按真实机构定义运动链；与普通折叠区分 | R5 |
| 折叠后侧向收纳门 | 折叠扇组＋回转件＋收纳轨 | 折叠、转向、滑入的分阶段运动与收纳腔 | R5 |
| 风琴／软质折叠门 | 软质叶片组＋轨道＋边框 | 专用展开／收拢表达；不靠刚体合页规则伪造软体变形 | R5 |
| 多扇折叠玻璃隔断门 | 玻璃扇组＋专用轨道／夹件 | 独立隔断宿主、堆叠停车位、净开口与细节等级 | R5 |

### 3.4 用途配置、特殊门与相邻范围

| 类型 | 归入方式与部件 | 发布边界 |
|---|---|---|
| 入户安全／防盗门 | 平开单扇／双扇／子母扇＋安全框、锁、猫眼、密封等 | R2 基础造型；产品性能按厂家资料保存，不由外观推断 |
| 厨卫木门／铝玻门 | 平开、推拉或折叠机构＋防潮材料、玻璃、锁等 | 随基础机构发布，不重复新建运动门类 |
| 淋浴门 | 玻璃单扇／双扇平开、推拉或折叠＋密封／挡水配置 | R4；独立卫浴隔断宿主、挡水基准，不能套普通墙洞口逻辑 |
| 酒店／办公／商铺门 | 适用组合＋电子锁、闭门器、拉手或门禁外观 | R2／R4；门禁电气与设备控制不在本轮仿真范围 |
| 隔声／保温／防烟／防火门 | 既有组合＋经确认的规格和部件配置 | 保留建筑性能字段；受性能规格约束的门不能随意改尺寸／换五金后继续宣称原等级 |
| 通风／设备门 | 平开或推拉＋百叶、观察窗、锁等 | R2／R4；设备门与格栅材质配置联动 |
| 自动平移／自动平开门 | 相应机构＋机组、传感器、联动规则 | R5；显示和几何运动，不实现电控或安全控制仿真 |
| 旋转门／弧形自动门 | 中心轴／弧形轨＋多叶片＋围护及机组 | R5 特殊模块；独立入口组合，不能硬套直线墙洞口 |
| 检修暗门／护墙板暗门 | 隐藏框、饰面扇和对应五金 | R2 基础；顶面检修口后续单独宿主类型 |
| 空门套／门洞包套／垭口 | 框套、线条、收口，无门扇 | R2；保留为开口装修组件，不凭空统计门扇 |
| 衣柜／橱柜／柜门 | 可复用平开、推拉、折叠部件规则 | 后续家具分支，挂柜体，不作为建筑门切墙和计门窗樘数 |
| 卷帘／卷闸／提升／车库门 | 卷收或提升机构＋导轨／机组 | R5 扩展目录；专用求解器和商业／车库用途，不能用平板整体缩短冒充卷收 |
| 工业快速门、气密／屏蔽等专业门 | 专业资源及明确规格 | 保留扩展接口；基础版本只允许固定、静态展示或明确不可用，不自动推导专业性能 |

花色和不同厂家 SKU 作为上述组合的资源变体。所有复杂机构可以先收录固定静态资源，但发布的能力标识必须明确：静态资源不显示可变尺寸／开闭按钮。

## 4. 一樘门的部件体系

| 部件层级 | 可选部件 | 尺寸行为 | 动作归属 |
|---|---|---|---|
| 框与收口 | 结构门框、门套板、正反套线、上横框、止口、门槛、固定中框、封板 | 指定方向延长中段；截面、端接细节保持；套板适应墙厚规则 | 固定于洞口／安装基准 |
| 活动扇 | 主扇、副扇、左／右扇、折叠叶片、上／下扇 | 解算净扇边界；变形区、固定区、有效范围明确 | 转动／平移／组合运动；独立身份 |
| 扇内构造 | 扇框、芯板、玻璃、格栅、压条、装饰线 | 净格和指定伸长区；玻璃厚度、型材截面不变 | 跟随所属门扇 |
| 固定区域 | 上亮、侧亮、固定玻璃、固定实板 | 按固定区尺寸与组合约束解算 | 固定于框，不跟随活动扇 |
| 门扇五金 | 把手、拉手、锁体／面板、拉槽、猫眼、插销 | 刚体不变形；可换规格，按边距／安装高定位 | 跟随所属扇；可另外声明小部件运动 |
| 安装五金 | 合页、隐藏合页、地轴、门夹、闭门器、轨道、吊轮、导向件、挡块 | 固定规格或作者声明的轨道长度；数量由明确规则控制 | 明确框侧／扇侧连接；不能把整件合页简单全挂一侧 |
| 密封和附件 | 密封条、下沉密封、毛条、门吸、挡水件 | 截面固定、中段延长或换规格 | 依附框／扇／地面；单独配置 |
| 二维示意 | 开启弧、轨迹、方向箭头、编号与尺寸锚点 | 由解算结果生成，不按整块比例缩放 | 图示，不进入三维实体和物料清单 |

不是每樘门必须具备全部部件。无框玻璃门不能被强制加木门套；隐形门不一定有可见把手；子扇不一定配与母扇相同的锁和执手。模板列出必需、可选及互斥部件，允许作者关闭不适用项。

用户可将门套、门扇和把手作为可复用子资源保存；第一阶段先实现整樘资源内的部件绑定，后续再开放跨资源替换。子资源仍属于同一本共享目录，由整樘组合引用，不新增第二个相互孤立的库。

## 5. CAD 平面入库与三维补充

### 5.1 CAD 作者流程

1. 进入现有“图库”，选择装修门，填写资源名称、门型／机构和参考规格。项目门窗编号不是必填。
2. 框选一樘完整 CAD 平面，拾取统一基点和 X/Y 方向，确认毫米单位。
3. 在同一预览／CAD 视图中选取图元组，指定门套、主扇、副扇、把手、固定板或开启示意角色。可按块／图层提出候选，用户确认；未分组的旧符号仍可保存固定资源。
4. 指定每扇的闭合轮廓和合页／轨道锚点；如果来源画的是开启姿态，作者确认关闭基准。不能以开启后的总包围盒作为洞口宽度。
5. 为门套／门扇声明尺寸规则、固定截面与伸长区。二维符号图元允许绑定多个相关部件，但几何归属及展示角色必须明确，不能复制同一门套描两遍。
6. 保存草稿或发布可用平面。CAD 平面立即进入共享库；模型端显示同条记录及“待补充三维”。

### 5.2 三维作者流程

- 在同条记录中“补充三维”，载入支持的 GLB；不重复导入平面、不重新录入资源名称和基点。
- 按真实几何部件拆分／绑定：门套、每扇、玻璃、把手、合页、轨道等。不能凭节点名称猜测配对。
- 指定闭合基准、局部坐标、固定／可变区域、五金锚点和运动轴；二维／三维选择同步高亮，缩略图显示实际部件。
- 可选二维-only 或三维-only 细节必须有原因：开启弧为二维-only，细小锁件可三维-only。门扇等核心活动部件缺乏对应关系时不得宣称联动已完成。
- 规则不完整时可发布固定静态资源；只有通过尺寸及运动验证，才开放相应能力。以后可继续升级同一资源修订。

### 5.3 普通用户流程

选资源／组合 → 选宿主或已有建筑门 → 填洞口尺寸／墙厚／必要配置 → 同步预览 → 生成或修改项目编号 → 放置／应用。

普通用户不填写 PartId、节点号、变换矩阵或网格索引。部件划分由作者做一次，之后重复使用。

## 6. 尺寸规则、求解顺序与动作

### 6.1 尺寸含义

必须区分洞口宽高、框外宽高、框内净宽高、门扇净宽高、实际通行净宽高、墙厚、门扇厚度、门套进深和装饰线面宽。开门后有效通行宽不是门扇宽度，也不是洞口宽度。

装修组件不能照搬建筑简化门框统一进深。具体规格由组合资源／厂家型材声明；旧参数门窗的默认值继续保留。门扇缝、搭接、玻璃厚度、合页间距等按资源规则配置，不在所有门型上硬编码一个通用数值。

### 6.2 求解优先级

1. 确认资源修订、宿主、洞口、单位及安装朝向。
2. 锁定用户明确输入的洞口外边界，以及作者定义的固定截面／禁止变形区。
3. 应用安装间隙、门套／框、止口、门槛及墙面收口关系，计算框内净区。
4. 分配活动门区、上亮、侧亮和固定板；内部约束尽量复用现有门窗分格优先级，不另造冲突的门格算法。
5. 按组合规则计算各扇净宽高、门缝、搭接及轨道位置，再求扇内框芯和玻璃。
6. 定位把手、锁、合页和轨道五金，重新生成运动轴／轨道／行程。
7. 计算当前开启状态的二维、三维与通行净区，检查越界、明显部件穿插及收纳空间。
8. 更新项目类型／实例、编号与输出缓存，作为一次可撤销事务提交。

互相矛盾的固定约束应提示无法求解并保留原模型；不得偷偷缩小洞口、拉伸把手或挤扁型材来凑尺寸。缺规则资源保留固定能力，不自动升级为可变资源。

### 6.3 门扇组合公式约定

以下为算法关系，不是加工尺寸标准。`W净` 必须由框、止口与安装配置计算得出。

- 单扇：扣除定义的侧缝后求门扇宽；上下缝、地面和门槛独立处理。
- 等分双扇：在净区扣除侧缝和中缝后等分；若有止口搭接，按资源接触边定义计算，搭接仅计一次。
- 子母扇：支持“子扇固定，母扇补足”“母子比例”“两扇明确尺寸”。明确尺寸与洞口不相容时拒绝，不静默改变其中一项。
- 推拉：按每扇跨度、固定／活动扇、轨道编号和相邻搭接解算。增加尺寸后重新求行程与收纳边界。
- 折叠：按叶片数、连接缝与转轴链解算；必须同时满足导向轨和铰接关系。
- 通顶或带亮子：总洞口固定，亮子／活动区按明确优先级分配，不缩放所有部件。

### 6.4 几何变化方式

门套直段、轨道和指定型材沿声明方向改变长度，端部固定；芯板／玻璃只改变允许的面内区间，厚度保持；把手、锁、合页和端部五金作为刚体移动或切换规格。

复杂网格需要作者给出伸长区、固定区和端接规则。无法可靠分段的装饰模型只允许固定规格或换规格，不对整樘 GLB 使用非等比缩放。规则中应说明修订后节点失配怎样重新确认。

### 6.5 动作模型

采用固定、转动、平移及受约束的组合动作，建立框／扇／五金父子关系和锚点连接。双扇独立控制，子母门可声明先后顺序；自动门、联动门按明确主从关系运动。

尺寸变化后先求关闭姿态，再重算运动轴和轨道，再应用实例开启量。运动角度／进度不是加工尺寸。图纸默认使用规定的平面开启示意，立面／门表按关闭态输出；场景开闭是否带入轴测由视图设置决定。

安装间隙、扇边缝和推拉搭接是不同概念。沿用“场景默认不显示安装缝”的产品偏好，但装修资源必须明确它表示零建模间隙还是工程间隙的简化封边；不允许只隐藏线却留下不明空洞。真实工程间隙可保留在规格中，制造／详图表达由明确视图模式控制。

## 7. 资源名称、项目编号与修订

| 层次 | 示例 | 约定 |
|---|---|---|
| 稳定资源身份 | 内部 AssetId | 创建后稳定，不因名称、尺寸、项目编号变化而换身份；普通用户不显示 |
| 图库资源名称 | 现代平板单开门／木质子母门 | 入库可用此名称，不要求先定 M0921；支持品牌、系列、型号及参考规格 |
| 项目类型 | 某组合＋洞口尺寸＋配置 | 资源与规格的组合；同规格可复用，不污染公共库 |
| 项目门窗编号 | M0921、用户自定义编号 | 选定类型、尺寸后按项目规则生成，允许改；同编号代表同一有效规格／配置集合 |
| 项目实例 | 一层卧室入口的一樘门 | 自己的楼层、宿主、位置、镜像、开闭状态；引用明确类型和修订 |

现有编号算法继续使用：例如洞口 900×2100 默认 M0921，1500×2200 默认 M1522。非整百毫米尺寸遵循共享算法及完整宽高匹配，不从四位文字反推出真实尺寸。

- 同编号不同尺寸必须提示并按既有后缀规则处理；同尺寸但门型／五金／构造不同也不能直接并成同一个项目类型。
- 修改“当前一樘”建立所需项目规格或后缀；修改“同编号集合”先确认影响范围，一次事务更新；标准层共享实例保持既有范围语义。
- 入库作者资源不等同项目编号，多个项目可以用不同编号引用同一资源。CAD 直接插入共享资源时在选型阶段确定本次规格和编号，再生成 `WL_CODE`。
- 现有 `ComponentPlanSymbol.Code`、外部清单 `Code`、索引冲突规则和 `WL_CODE` 耦合需要联合迁移；不能只在 UI 去掉必填而让保存／模型发布继续报错。
- 新契约区分资源名称、可选参考编号和项目编号，升级读写／校验／共享索引冲突逻辑。旧 Code 保留为旧资源别名／参考编号，不无条件改写旧数据。
- 资源更新仍保留乐观并发、内容哈希、不可变修订和项目副本。项目锁定使用的修订，公共库更新需预览差异后才升级实例。

## 8. 作者界面和用户界面

沿用已选图库网格稿、已有 Ribbon 和右侧属性系统，不重新搭一套无关界面。

### 作者界面

步骤：基本信息 → CAD 平面分组 → 三维配对 → 部件与尺寸 → 动作 → 校验与发布。

- 基本信息：装修门名称、机构、扇组合、门套构造、参考尺寸、用途和材料；项目编号不必填。
- 部件列表：真实门套／门扇／把手缩略图、必需／可选状态、当前配对状态。
- 主视图区：二维与三维同步高亮、合页点、轨道、固定区／伸长区；可直接点击和框选；提供数值精调。
- 参数区：按当前部件显示截面、间隙、锚定方式、边距、数量规则、允许范围，避免不适用字段堆满窗口。
- 校验区：默认、最小、最大和作者测试尺寸；关门、半开、全开；误配／缺配／尺寸冲突定位到具体部件。
- 草稿和发布能力分开。规则未完成的资源显示“固定规格／静态”，不展示已完成可变动作的假按钮。

### 普通用户界面

图库按“建筑门／装修门”筛选，来源仍可选内置、项目与公共。装修门进一步按开启机构、组合、用途筛选；颜色／材质为过滤项，不制造大量重复门类。

右栏显示洞口宽高、墙厚、门型组合、左右／内外开、子母扇分配、可选把手／门套、预览与项目编号。不显示作者矩阵、节点号和工程内部身份。

“部件配置”只允许替换作者声明兼容的部件。更换把手不能改变门套，换门套后必须重算净扇和间隙，不能保留过期门扇尺寸。

已应用的修改不会被 Esc 撤回；夹点放下立即提交；Ctrl+Z 撤销。门窗沿墙移动、右键居中、拾取框、加减选和标准层编辑沿用现有行为。

## 10. 数据与代码改造范围

以下为拟定概念结构，不是要求立即将所有字段塞进既有 JSON：

## 11. 分阶段实施与验收门槛

### R0：契约与基础交互

2026-10-07 首批实现：名称优先／可空资源编号、稳定 CAD 部件标注、实际部件预览和当前部件提示、GLB 多节点合并、整组语义配对、草稿／修订兼容均已验证，见 [R0 验收](../reviews/装修门部件入库-R0-2026-10-07.md)。建筑实例关联仍按 R1 实施；本批测试门为自制简单几何样本，其他门型的合法 CAD／GLB 实际样本收集仍未完成，不能称 R0 全部样本或全门型能力已完成。

调整资源名称／编号生命周期；定义建筑门关联和组件角色，旧资源固定读取；CAD 作者入口与配对草稿增加部件基础定义。取得单开、双开、子母、推拉、玻璃和隐形门可合法使用的 CAD／GLB 测试资源。

验收：旧 M0921 可读取及插入；新“平板单开门”可不定项目编号入库；CAD 与模型仍是同一条记录；更新／并发／哈希／项目副本不回归。

### R1：普通单开装修门完整闭环（第一轮实现目标）

先完成固定外部单开资源的 MM／宿主／保存和输出，作为后续可变规则的基线；随后在同一阶段实现门套＋门扇＋把手／合页的可变尺寸与转动，不能将仅能预览 GLB 的状态宣称为实例闭环。

验收样例：参考 900×2100 改为 1200×2400；门扇和套框重算，把手不变形，合页及开启弧同步；关门／45°／90°；绑定旧建筑门不重切墙、不重算樘数；保存重开、离线项目副本、缺失回退、CAD／图纸／三维／GLB、单次撤销均通过。

### R2：平开组合、饰面与常见装修配置

等分双开、子母、通顶、上亮／侧亮、隐形、窄框玻璃、格栅、空门套；支持母子宽度规则和兼容五金／套框更换；卧室、厨卫、酒店、入户等用途作为配置组合。

验收：子扇固定／比例／明确尺寸三种策略；左右镜像、斜墙、不同墙厚、带亮子的尺寸优先级；每扇有独立五金和动作；同编号范围及标准层联动正确。

### R3：基本推拉族

单扇外挂／谷仓、对开、双轨双扇、多轨多扇、固定板组合；吊轨／地轨作为配置。门扇错位、搭接和收纳行程共同解算。

验收：搭接只计一次、扇之间有正确进深、轨道截面与把手不变形；关闭／半开／全开净通行及清单；左右收纳、镜像和尺寸改变后轨道／行程同步。

### R4：专业平开、折叠及空间约束

双向、地弹玻璃、中轴／偏轴、上下分扇、两扇／多扇折叠、联动套叠、墙内暗藏；接玻璃隔断／淋浴宿主和收纳腔规则。

验收：运动链闭合、导向轨一致、各阶段无明显自穿插，暗藏腔不误切相邻墙／洞口；不同安装基准正确；无法满足空间／规则范围时保留原模型并提示。

### R5：特殊机构和后续扩展

同面推拉、提升推拉、转角、平折、转滑／折叠收纳、软折、多扇玻璃隔断、自动驱动、旋转／弧形及卷收／提升门。每个机构独立资源样本、规则设计和验收后逐项发布。柜门沿家具分支复用基础部件规则。

该阶段还安排细节等级、部件复用库、材质能力和专项性能资料；材质贴图支持按现有 GLB 限制另行验收，不能靠写材料名称宣称完整材质系统已完成。

各阶段结束记录实际功能、测试和限制，更新当前上下文。业务代码、安装更新和 GitHub 上传按后续用户指令执行，不因本计划自动发布所有阶段。

## 12. 测试与完成标准

- **几何**：默认／最小／最大／非整数尺寸；固定截面不变、门套端接闭合、玻璃厚度正确；门缝、推拉搭接和五金边距各自独立。
- **组合**：单扇、等分、子母、固定板、亮子、不同框型；非法配置和冲突输入拒绝且模型不变。
- **动作**：关闭／中间／最大、正反开、镜像、斜墙、转轴／轨道变更；调整尺寸后运动轴与五金位置重算，关闭态能还原。
- **数据**：新旧资源往返、旧参数门窗、旧共享记录、更新失配、缺失／损坏资源、离线项目、版本锁定、并发作者窗口。
- **项目**：新放置和旧建筑门绑定；本樘／同编号／标准层范围；复制和删除；樘数不重复；旧建筑洞口与墙体保持。
- **输出**：平面、装修立面、建筑平立剖、门窗表、装修表、部件清单、原生 CAD、三维和 GLB 同一规格；几何 1:1、比例／字高／线宽一致。
- **交互**：小窗口与高 DPI、二维／三维同步高亮、直接点击和数值调整、夹点提交、Esc 与撤销、错误内联提示；部件小图为实际形状。
- **性能**：相同资源修订＋规格复用关闭几何和二维符号；实例动作主要更新变换；参数拖动局部预览／节流，提交刷新受影响项，避免每次键入重算整栋。以当前版本同模型基线记录耗时及内存，不虚构速度承诺。
- **真实样本**：每个发布机构至少一个可复现 CAD＋GLB 样本，不仅用简单盒子测试；CAD 原生测试使用临时数据库和一次性图纸，不操作用户图纸。

一个门型只有在作者配置、实例放置、尺寸／动作、保存重开、撤销和全部目标输出形成闭环后才标记“支持”；能导入、预览或显示缩略图不算完成。
