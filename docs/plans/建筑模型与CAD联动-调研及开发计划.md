# 建筑模型与 CAD 联动：案例调研与开发计划

调研日期：2026-09-22。状态：立项建议，尚未实施。本文基于当前工作区源码和公开官方资料；技术选型与性能数字中标注为“建议/目标”的内容需原型验证，不代表现有能力。

## 1. 结论与产品定位

可行，而且已有成熟产品证明“模型生成立面、剖面，并随模型更新”的工作方式。建议为万落建筑工具增加“建筑模型”模块，以现有 DWG 平面和已有楼梯、门窗参数为入口，建立轻量参数建筑模型，再输出可编辑的 CAD 矢量图纸。

核心不是把所有 CAD 线条拉伸，而是建立“这面墙、这个洞口、这一层楼板”的身份、位置和约束。二维平面通常不能唯一决定建筑高度、窗台、屋面坡度和构造层次，缺失部分必须由已有参数、规则或用户确认补齐。

推荐第一版覆盖规则建筑的墙、矩形门窗洞口、平楼板、楼层和已有楼梯。交付一个可持续更新的完整闭环，不一开始承诺任意旧图一键 BIM、所有天正对象写回、任意立面线条反推模型或全部施工节点自动生成。

建议用户流程：选择项目 → 登记楼层平面和基点 → 识别/指定构件 → 核对缺失参数 → 生成模型 → 在模型中改尺寸与位置 → 预览受影响视图 → 更新 CAD → 继续排版打印。

### 开源接入原则

Bonsai 与 IfcOpenShell 库不能混为同一种许可：前者 GPL-3.0-or-later，后者仓库按组件列出 LGPL 等许可；OCCT 为 LGPL 2.1 加附加例外；That Open Components 和 Three.js 当前所查许可为 MIT；xBIM Essentials 为 CDDL。具体锁定版本、依赖及发布方式在 P0 阶段逐项记录。外置进程有助于技术隔离，但不意味着自动免除许可证义务。建议参考完整应用的工作流，按模块引入底层库，附第三方清单和适用许可。

## 4. 参数复用与统一规则

建立 `ParameterValue = 值 + 单位 + 来源 + 确认状态 + 修改版本`。来源至少包括现有模块、DWG 对象、识别推断和人工输入。缺失值不可静默当成零或默认正确。

优先级建议：已确认的实例覆盖 > 项目统一类型 > 原模块导入值 > 可见的建议默认值。导入不是每次打开就覆盖用户修改；再次导入产生差异清单，由用户确认。

- 全建筑采用毫米和双精度工程坐标；预览端采用局部原点，避免大坐标抖动。
- 项目楼层表成为楼层标高的统一来源。首次从楼梯导入时先核对正负零、地下层和标准层；多个楼梯层高矛盾时暂停自动合并。
- 门窗编号不是唯一实例身份。同编号类型可以有多樘、不同朝向和不同楼层；每樘分配独立 GUID。更改类型尺寸要显示影响数量。
- 楼梯模块继续拥有专业参数算法，通过适配器与建筑模型绑定，不能形成两套相互覆盖的层高和踏步数据。
- 构造参数另建类型：墙芯厚、饰面厚、保温、防水、楼板结构厚度、完成面、窗框安装位置等。已存在可靠参数就导入，未提供则标记待补。
- 统计数量从已确认实例重新计算，与原门窗表比较；数量差异提示检查，不凭表格数量自动放置窗。

## 5. 建模输入路线与识别边界

优先级由可靠到不确定：插件已登记构件 → 经验证的天正对象属性适配 → 动态块/属性块 → 标准图层和线型 → 普通双线识别 → 图片/OCR 辅助。

每层需要楼层 ID、标高、层高、源 DWG、平面范围、基准点与方向。各层在同一 DWG 中并排绘制时，分别记录从图纸坐标到建筑坐标的矩阵。处理 UCS、WCS、旋转、镜像和插入比例，不能直接叠加原始坐标。

墙识别先支持直墙：选择中心线并指定厚度，或从双线候选中识别墙厚；墙端、T/L/X 交接、短线、重复线和闭合误差单独检查。门窗实例通过定位和宿主关联扣洞，禁止仅凭一个文字编号猜位置。屋顶、檐口、女儿墙和阳台由轮廓及参数登记。

天正接入先建立真实文件测试矩阵（用户使用版本、对象 DXF 类型、有/无对象解释器）。可读取属性就用正式可用接口；只读几何降级结果标为参考构件。没有验证的写入能力不自动回写天正原对象。

用户核对界面显示“已确认 / 待确认 / 缺参数 / 无法转换”，点击可定位原图；第一版支持人工选择和修正，避免卡在全自动识别准确率上。

## 6. 推荐架构与技术选型

### 分层

```text
原 DWG / 楼梯参数 / 门窗表 / 项目与制图标准
                    ↓ 提取、核对与适配
       BuildingDocument（构件、类型、楼层、版本）
           ↙                         ↘
三维预览与参数编辑                精确几何/视图任务
           ↘                         ↓
            变更命令            ViewResult 矢量结果
                                      ↓
                   CAD 事务写入 + 人工补绘层 + 发布打印
```

建议新增：`WL.Building.Core`（纯参数与规则）、`WL.Building.Adapters`（原模块转换）、`WL.Building.Geometry.Worker`（可选独立几何进程）、`WL.Building.Viewer`（三维交互）、`WL.Building.Cad.R24/R25`（宿主接口），在现有项目中挂接，避免重新建立不相干的项目管理系统。

### 几何后端：先对比原型，再锁定

方案 A：AutoCAD 原生 Solid3d 和 Section API。与现有插件接入最直接，可先做拉伸、洞口布尔和剖切验证。官方 `CreateExtrudedSolid` 支持实体拉伸，`Section.GenerateSectionGeometry` 支持从 Solid/Surface/Body/Region 生成剖切几何。但不据此承诺跨实体完整隐藏线和成图质量，必须实测；CAD 数据库访问遵守宿主线程/文档锁规则，不能简单 Task.Run 放到后台。

方案 B：独立 OCCT 几何进程。通过参数 DTO 构建实体并输出线/弧/剖切区域，适合耗时计算、取消与崩溃隔离。需验证墙交接、共面布尔、曲线精度、隐藏线性能及打包体积；不把完整 DWG 数据库传入该进程。

建议 P0 同样例比较两者：若原生方案的交互占用与出图质量达到目标，用它实现最小闭环；若长计算明显冻结 CAD，采用独立 OCCT 作为正式后台。接口保持 `BuildGeometry` / `GenerateView`，避免业务层绑定某一内核。不要第一天同时维护两套完整实体实现。

官方依据：[拉伸 API](https://help.autodesk.com/cloudhelp/2022/ENU/OARX-ManagedRefGuide/files/OARX-ManagedRefGuide-Autodesk_AutoCAD_DatabaseServices_Solid3d_CreateExtrudedSolid_Entity_SubentityId_double_SweepOptions.html)、[剖切 API](https://help.autodesk.com/cloudhelp/2024/ENU/OARX-ManagedRefGuide/files/OARX-ManagedRefGuide-Autodesk_AutoCAD_DatabaseServices_Section_GenerateSectionGeometry_Entity_out_Array_out_Array_out_Array_out_Array_out_Array.html)。

三维预览建议先评估 WebView2 + Three.js 小型视图，与现有编辑桥接模式接近；复杂 IFC 浏览再按需引入 That Open。Helix 为原生 WPF 备选。预览网格仅用于交互，不能作为精确出图唯一数据源。IFC 导出优先在第二阶段由 IfcOpenShell 工具完成；若部署或团队维护成本不合适，再比较 xBIM。

## 7. 数据结构和存储设计

建议结构：

- `BuildingDocument`：SchemaVersion、ProjectCloudId、BuildingId、Revision、单位、工程原点。
- `Storey`：Id、名称、结构标高、完成面标高、层高、标准层实例关系。
- `Element`：Id、类型、StoreyId、TypeId、局部变换、参数、宿主/约束、SourceBinding、Revision。
- `Wall`：中心线/轮廓、厚度、基底/顶部约束、分层构造。
- `Opening`：HostWallId、沿墙距离、宽高、底标高、朝向；填充门窗实例另关联 TypeId。
- `ViewDefinition`：Id、立面/剖面/大样、观察矩阵、剖切平面、前后裁剪、范围、比例、表达规则、模型版本。
- `CadBinding`：DrawingGuid + ElementId/ViewId + EntityHandle + 来源摘要。ObjectId 不跨会话持久化，Handle 不能单独作为全局身份。
- `AnnotationAnchor`：ElementId + 语义特征（窗左边、楼板顶等）+ 局部位置；不绑定易变的网格顶点序号。

建议项目内 `建筑模型/<BuildingId>/model.json` 保存可迁移参数；`views.json` 保存视图；本地缓存放到不同步目录。初期单建筑单文件便于原子提交和历史恢复，规模变大后再评估分块，避免多个 JSON 非原子写入造成楼层版本不一致。

DWG 扩展字典保存身份、模型版本与必要快照/恢复信息。外部模型文件和 DWG 的修改用操作日志协调：生成结果先暂存 → CAD 事务提交 → 更新绑定和版本；失败保留可恢复状态。模型文件丢失、DWG 另存、复制构件、跨图纸粘贴均要有检测与恢复流程。

## 8. 编辑与联动：明确谁负责哪部分

统一模型是受控构件参数的来源。二维和三维是编辑入口，修改均转成语义命令：移动窗、改洞口宽度、改层高、改墙厚、切换类型。命令执行前检查约束，完成后生成新 Revision 和受影响视图集合。

第一版支持：三维选取构件、属性修改、沿墙移动门窗、修改标高/层高、显示隐藏楼层、保存撤销；二维端通过专用构件命令修改模型。普通 CAD 拉伸/删除派生线条标记为本地覆写或脱离关联，不能悄悄反推为建筑设计变更。

更新保护规则：

1. 自动生成实体与人工补绘按所有权区分；新结果只替换该 ViewId 的自动部分。
2. 更新前展示新增、修改、删除及受影响图纸，提供一次撤销。
3. 手工文字和尺寸位置尽量保留；锚点构件消失时标记失联，不能保留看起来正确的旧尺寸。
4. 删除窗后其自动门窗编号同步删除，用户另画的说明保留并提示核对。
5. 绘图来源变更产生候选差异；原 DWG 和模型同时修改时要求选择或逐项合并，不使用“时间更新者获胜”。
6. 首版跨 DWG 以显式“更新关联视图”为主，不在用户编辑期间偷偷改其他图纸。以后再增加受控自动更新。
7. 多台电脑同时修改模型按模型版本冲突处理，先保存两个版本；后续才研究构件级三方合并。

## 9. 立面、剖面和大样的生成方法

立面：定义方向与裁剪 → 收集可见构件 → 遮挡/隐藏线判断 → 合并共线段 → 按轮廓、可见细线、隐藏线分角色 → 添加楼层标高、轴号和开口编号 → 转为 CAD 实体。保留圆弧/曲线，避免三角网格边线污染图纸。

剖面：剖切平面与实体求交 → 整理闭合轮廓与洞 → 按构造/材料填充 → 生成后方可见投影 → 加标高和尺寸。剖到墙芯、窗洞、楼板、梯段的结果各有测试；剖切线加粗不能靠整个模型投影统一加粗实现。

大样：采用“模型截取 + 构造规则/模板 + 人工补绘”。模型可以给真实位置和尺寸，但缺少防水搭接、保温收口、密封胶、预埋件等参数时不能凭空生成。第一批优先楼梯、门窗和窗台节点，复用现有专业出图规则；输出中标明待补参数。

比例表达建议：1:100/1:50 以主体和洞口为主；1:20 增加框、饰面和材料层；1:10/1:5 使用节点规则。详细门窗分格可作为二维语义叠加，避免所有螺钉都做实体。所有线宽、文字和填充读取现有制图标准。

## 10. 性能、界面与兼容性要求

用户关心不卡顿，因此“后台计算”和“快速预览”必须进入验收，而不是最后优化。

- 首屏先加载项目结构和缓存预览，模型按需加载；不因加入模型模块拖慢启动器日常启动。
- 拖动时只更新相关构件的简化网格，松手后提交约束与精确几何；约 150–300 ms 防抖可在实测后调整。
- 采用 ElementId/参数摘要缓存、楼层分区、可见范围裁剪、实例复用。修改一扇窗不能全楼重建。
- 所有后台任务带 RequestId 和 ModelRevision；旧结果丢弃，取消不写入半成品；Worker 失败可重启。
- CAD 线程只做必要读写，分批更新；不在文档锁内执行网络同步和长时间文件扫描。
- 高 DPI 使用设备无关尺寸，支持 100%、125%、150%、200%、250% 和跨屏移动；深浅主题、窗口缩放性能沿用现有用户要求。

暂定性能预算（P0 在记录 CPU/GPU/内存/分辨率后校准）：1000 构件三层样例，缓存预览 ≤2 秒；选取/属性反馈 P95 ≤100 ms；拖动预览 ≥30 FPS；单窗修改到局部精确结果 ≤2 秒；普通单立面出图 ≤5 秒，复杂全楼任务显示进度且可取消。10000 构件作为压力集单独记录，不沿用小样例数字作承诺。

## 11. 分阶段任务与交付门槛

估算假设：1 名主要开发持续投入，建筑设计人员每周参与样例确认；以下为工程估算，不是承诺工期。多人可并行部分任务，但不能消除几何和真实图纸验证成本。

| 阶段 | 估算 | 任务与交付 | 通过门槛 |
|---|---:|---|---|
| P0 技术验证 | 1–2 周 | 准备真实样例；原生 API 与 OCCT 小对比；楼梯参数转三维；墙开窗出一张剖面；输出选型记录、许可清单、性能基线 | 证明遮挡、洞口、精度和宿主响应可行，否则调整路线 |
| P1 领域与参数适配 | 2–3 周 | BuildingDocument、楼层表、身份/坐标、版本迁移；楼梯/门窗类型/制图标准适配；参数来源核对 | 同一参数只改一处；旧项目可打开；往返序列化无数值丢失 |
| P2 平面登记与基础建模 | 2–3 周 | 楼层对齐、直墙、楼板、矩形洞口和门窗实例；人工修正；基础预览 | 三层样例位置正确；低置信对象提示；不修改原图 |
| P3 模型编辑与精确出图 | 3–4 周 | 构件选取/属性/拖动；四向立面、一张任意直剖面；写入 CAD；图层与样式 | 窗宽/窗台/层高变化能更新所需视图，几何与基准一致 |
| P4 联动可靠性与试用 | 2–3 周 | 差异预览、撤销、人工补绘保护、失联标注、保存恢复、R24/R25 与 DPI/性能回归 | 多轮修改无重影重复实体，无人工补绘丢失，故障恢复可验证 |
| P5 专业深化 | 4–6 周 | 楼梯完整联动、常用门窗节点、平屋面/女儿墙、有限曲墙、天正已验证适配、IFC 导出 | 至少两类真实项目可交付，构造参数可追溯 |

P0–P4 约 10–15 周形成受控范围可试用版本；P5 后累计约 14–21 周。一般复杂旧 DWG 自动识别、任意自由曲面、可靠任意二维反向编辑属于后续专项，预计还需数月，不能计入最小版本。

建议最先实际动手的是 P0 的“现有楼梯 + 一面带窗墙 + 一块楼板”，不是重做界面或引入整个 BIM 软件。

## 12. 第一版验收脚本

样例 A：单层矩形建筑，两个相互遮挡墙体、普通窗、门与平板，验证轮廓和剖切。

样例 B：三层建筑，平面并排放置、标准层、现有双跑楼梯、同编号多樘窗，验证坐标和参数复用。

样例 C：带地下层、旋转楼栋、跨图纸来源及缺少部分窗台参数，验证降级和提示。

核心操作：

1. 读取楼梯层高和门窗表，逐项显示来源；未知实例位置明确待定位。
2. 在三维中将选定窗宽由 1500 改为 1800、窗台高由 900 改为 1100；确认是改一个实例还是所有同类型。
3. 更新立面和穿窗剖面，检查洞口、框线、编号及尺寸，其他楼层和不相关窗不改变。
4. 改二层层高，检查上部楼层、楼板、洞口和楼梯约束；不可实现的踏步方案给出原因。
5. 在立面加人工说明并移动尺寸文字，再更新模型；人工内容和合理的位置保留。
6. 删除洞口、撤销、保存重开，再更新；没有旧残线、重复编号及无提示的失联尺寸。
7. 切换 DWG、另存、复制构件、断开模型文件，均能检测并恢复或明确脱离关联。
8. 精确出图中断、Worker 崩溃或磁盘写入失败，原图纸不受损；不能发布半更新视图。
9. R24/R25 与常用缩放、低配机器运行同一组样例，记录耗时、主线程阻塞和内存。
10. 更新后使用原有图框和批量打印生成 PDF，与基准图叠加检查。

几何误差暂定目标：模型坐标普通建筑尺寸 ≤0.1 mm，最终图纸偏差按出图比例另审；极大坐标和容差布尔另立样例。几何单测必须覆盖墙接头、重复/微短线、门窗碰撞、切面贴边和共面构件。

## 13. 主要风险与应对

| 风险 | 应对 |
|---|---|
| 原图只画了表达线，没有构件语义 | 支持人工登记、显示识别置信度和参数来源，不假装全自动成功 |
| 读门窗表被误当作已获每樘空间坐标 | 严格区分类型与实例；实例需定位与宿主 |
| 天正版本/代理对象兼容 | 真实样例矩阵；读取适配失败就降级，不直接改未验证的天正对象 |
| 3D 看着对但投影线错 | 精确内核出图与专业二维规则结合；建立剖切/遮挡基准图 |
| 修改模型覆盖手工深化 | 生成所有权、独立补绘层、语义标注锚点与差异预览 |
| 开洞/墙接头导致布尔失败 | 容差策略、输入检查、局部失败定位与可回退操作 |
| 同步版本相互覆盖 | 模型 Revision、原子提交、冲突保留；不以文件时间推断唯一正确版本 |
| 楼层/楼梯参数各改一套 | 参数所有权、适配器、变更命令统一；禁止循环导入覆盖 |
| 界面和 CAD 冻结 | 后台快照计算、按需加载、局部更新、超时取消；原生调用实测后决定后端 |
| 开源许可/原生依赖负担 | 锁定版本和组件，逐项记录分发要求；不在 CAD 进程无控制加载大型依赖 |

## 14. 立项建议

推荐新增名称“建筑模型”，主入口放在建筑工具分组，后续命令名先查重再确定。项目管理中增加建筑与楼层面板；模型模块延迟加载，和日常启动工作台分开。

先实施 P0，交付可运行演示、导出的 DWG 立剖面、参数复用清单和实际性能报告。只有这些通过，再进入 P1–P4。后续立面、剖面、大样都从同一模型和专业表达规则派生，逐步减少重复画图，而不是生成一次后又失去关联。
