# 构件图库、多软件协同与家具扩展开发规划

## 最新流程约束

用户随后明确：CAD 平面入库后，CAD 可直接插入，三维图库也必须已有同一条记录；不采用先导出平面、再导入三维、再建库的流程。已落实本机共享目录、稳定资源 ID、CAD 原生块插入和三维“补充三维”入口，见 [共享图库增量验收](../reviews/CAD与三维共享图库-2026-10-07.md)。以下作者流程和软件表中的平面文件往返属于历史方案，正常操作以本节为准。

1. CAD“图库”：门/窗分栏，选择原生平面块，指定编号、洞口尺寸、基点和 X/Y，直接保存共享记录。
2. 同条记录立即用于 CAD 插入，也自动出现在模型“管理 → 图库”。没有 GLB 时显示真实 CAD 平面和“待补充三维”，不假造三维模型。
3. 三维端选该记录，只载入 GLB、对齐三维基点和部件；发布更新同一个资源 ID，不重复录入编号、尺寸和平面。
4. CAD 更新平面保留资源 ID 与旧模型载荷，平面变化时模型标记待复核；作者重新核对并发布，不能偷偷把旧模型称为匹配。
5. 家具沿用共享资源身份和几何配对，不再设计另一套导出/导入图库。后续增加家具 CAD 制作栏、正式实例、尺寸规则和部件开闭。

这里只是同电脑共享，不表示跨电脑/云端同步已完成。GLB 模型文件仍由三维作者软件输出并载入；原生 MAX 文件读取、活动扇/家具运动与可变尺寸尚未实现。旧 MM 参数门窗继续原路径。

日期：2026-10-07。状态：开发规划与 UI 设计草案，不是已实现功能清单。接续 [CAD/Max 门窗配对计划](构件图库-CAD与3dsMax门窗配对-2026-10-05.md)。本规划统一后续入口、尺寸/运动规则及家具扩展；历史阶段的安装、测试状态以各验收记录为准。

后续实施增量：用户已授权开始开发和覆盖；G1 的资源包、静态配对／真实部件预览、草稿、修订与项目副本已实现，见 [G1 第一段验收记录](../reviews/构件资源包与配对入库-G1-2026-10-07.md)。以下“本轮只写规划”和能力表保留规划时状态，不是当前安装状态。G2 实例放置与输出、G3 联合尺寸／开闭仍待实现。

本轮只写规划和设计图，不改插件业务、不覆盖安装、不上传 GitHub。用户“暂不覆盖”仍有效，产品维持 1.5.6。

## 1. 目标与当前边界

目标：用户能用 CAD 画清晰平面，用 Max/Blender/SketchUp 制作三维，在万落图库完成一次配对，以后直接选型、改尺寸、放置、开闭和出图。同一套资源能力以后支持家具、洁具、设备，不让用户在几个软件之间重复录入编号和尺寸。

| 状态 | 能力 |
|---|---|
| 已安装 | 参数门窗图库、v1 参数资源包、CAD 原生平面符号导出、GLB 只读来源校验、现有参数门窗三维开启及建筑 GLB 导出等 |
| 已编译未覆盖 | CAD“图库”单入口与门/窗参数窗口，输入/拾取基点、毫米宽高、X/Y 方向；旧长命令保留兼容 |
| 本规划待实现 | 外部资源包/项目副本、配对编辑、外部构件正式放置、部件尺寸规则/运动驱动、家具实例及软件资源更新 |
| 外部验证限制 | 本机 Max 2024 batch 授权启动失败，不能称为实际导出已验收；SketchUp 目标版本未确认；当前 GLB 检查器不接受贴图/动画，不等于完整材质系统 |

已安装来源工具只读检查，不能把画面上的导入文件名和预览误认为正式资源已进入项目。现有 v1 `.wlopkg` 只有参数，新增几何与规则需要明确新版本及兼容读写。

## 2. 软件职责与交换路线

| 软件 | 主要职责 | 交给我们的内容 | 我们交回的内容 |
|---|---|---|---|
| AutoCAD/天正 | 1:1 平面线、原生圆弧、编号/属性候选；识别项目墙与洞口；接收规范图层图纸 | CAD 插件生成 `.wlplan.json`，附来源图元/分组信息；DWG 可选作者文件，不是运行依赖 | 规范图层下的原生图元/可编辑块与注释；建筑几何始终 1:1 |
| 3ds Max | 精细三维建模，拆分固定框、每扇、五金与可变中段；制作材质 | 关闭姿态 GLB 与建议对象名称；MAX 可选作者文件 | 建筑/构件视觉模型及交换元数据；尺寸规则不自动变成 MAX 参数控制器 |
| Blender | 同等三维作者入口、检查交换模型；可作受控格式转换工具 | 关闭姿态 GLB；BLEND 可选作者文件 | GLB 与元数据；导出后打开沿用现有流程，不接管未保存场景 |
| SketchUp | 快速体块、组/组件和家具模型作者入口 | 已验证目标版本的 GLB；旧版本经 DAE 适配，不能假装直接读 SKP | 目标版本支持的 GLB，必要时 DAE；语义运动不自动转动态组件 |
| 万落建筑模型/图库 | 资源配对、单位/轴向、尺寸约束、部件运动、实例、编号、楼层/宿主、项目版本、视图/导出 | 上述标准交换内容，不执行资源附带代码 | 项目模型、CAD 图纸、视觉交换模型、可携带图库包 |

**首选路线**：CAD 平面 + 关闭姿态 GLB → 配对编辑 → 校验 → 本机/团队资源包 → MM 或家具放置 → 项目受控副本 → 图纸/CAD/三维输出。

**软件验证依据**：

- Max 2024 GLB 导出会压平层级、不带动画/蒙皮/变形数据；保留对象名，重复名可能添加后缀。绑定不能只依赖 Max 层级、Pivot 或动画。[Autodesk 官方说明](https://help.autodesk.com/cloudhelp/2024/ENU/3DSMax-Interoperability/files/GUID-5B4C8EC2-2230-4F9F-B3C6-48D9E347E37D.htm)。
- SketchUp 官方 GLTF 页面明确列出 `.glb` 导入/导出。仅对验证过的版本/订阅开放该路线，不把新文档能力套到所有旧版。[SketchUp GLTF](https://help.sketchup.com/en/sketchup/working-gltf-files)。旧版适配候选为 COLLADA 1.4；其二维文字、尺寸、剖切等不保留，不能代替 CAD 图纸。[SketchUp COLLADA](https://help.sketchup.com/en/sketchup/importing-and-exporting-collada-files)。
- GLB 的米制、Y 向上按规范转换到我们的毫米、Z 向上；材质和必需扩展须另做兼容检查。[Khronos 规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#coordinate-system-and-units)。
- Blender 官方开发说明确认内置 glTF 导入/导出覆盖网格等交换内容；不据此承诺任意 Blender 材质/约束能往返。[Blender 官方说明](https://developer.blender.org/docs/release_notes/2.80/import_export/)。

这些是格式/导出器能力依据，不是本插件相应路线已实机通过的证据。每个支持的软件版本、方向、格式和材质等级单独登记验收。

## 3. 三种身份与两类使用者

资产身份 `AssetId + Revision + 内容哈希`、项目类型身份、项目实例身份分开。门窗编号 M0921/C1216 不是文件路径或资产主键；家具型号也不直接等于唯一实例编号。

**普通设计用户**：搜索 → 点资源 → 看实际二维/三维与可编辑字段 → 改需要的参数 → 放置。无需知道节点、矩阵、纹理路径或合页坐标。

**图库制作用户**：导入二维/三维 → 指定尺寸/基点 → 看图选择部件 → 配置尺寸与运动 → 批量校验 → 发布新修订。高级参数只在作者编辑器显示；入库后的用户只看到被作者允许的参数。

资产修订发布后不可原地改。库更新、源文件更新都不自动覆盖已落地项目；采用新修订有预览/差异/影响范围和撤销。

旧门窗继续走现有参数化构造，不因为增加外部资源而批量转换。详细兼容规则和当前代码核对见第 19 节。

## 4. 入口不分裂

- CAD 功能区只新增一个“图库”入口。当前门/窗参数窗口是其中的“制作平面”子流程；后续扩展为来源制作、打开图库、发送到配对，不新增门、窗、家具等一排 CAD 按钮。
- 独立模型程序管理页共用“图库”，MM 继续直接打开门窗选型，不改变旧操作习惯。家具放置从构件/图库类别进入，首期不占用新的未经确认快捷键。
- 图库选型和图库管理共用分类/搜索/预览，但操作状态明确：放置模式主按钮“放置”，管理模式主按钮“保存资源”；不能两者同时作为主操作。
- CAD 模型放置仍采用已有二维规范桥接。项目身份与当前文档不符时明确选择目标，不偷偷把新资源塞到另一工程。
- 家具、洁具、设备未实现前不开放空分类；设计图展示的是最终范围，发布 UI 按已完成阶段开放。

## 5. 资源模型与项目文件

建议扩展 `.wlopkg`，版本升级采用与 v1 参数包并存的新清单。是否 `schemaVersion=2` 在契约实现时冻结，不能在同一个 v1 能力标记下塞入新文件。

| 数据 | 内容与责任 |
|---|---|
| ResourceDefinition | 稳定 ID/修订/类别/名称/作者来源；固定规格或规则可变；二维/三维/尺寸/运动/材质能力声明 |
| FileManifest | 资源相对路径、大小、SHA-256、实际格式、单位/轴向、源软件版本；源文件为可选附件 |
| PlanDefinition | 原生图元、闭合轮廓、固定/活动/符号/编号锚点分组、用途图层和实体/符号描边角色 |
| PartDefinition | 稳定 PartId、修订内节点选择器/内容指纹、二维组、固定/活动角色、关闭基准、部件缩略图与几何 |
| SizeRule | 边界锚定、允许的变化轴/中段、固定截面、净格/间隙、分格关系、有效范围和用户可见参数 |
| MotionRule | 固定、转动、平移；局部合页点/轴向或轨道/行程；联动关系和有效范围 |
| MaterialReference | 独立材质 ID/纹理/槽位；不与尺寸/部件绑定硬编码混在一起 |
| ProjectType/Instance | 固定资源修订引用、项目类型参数、实例变换/宿主/楼层、明确允许的尺寸与运动覆盖 |

资源包包含清单、平面符号、关闭姿态 GLB、缩略图及已支持的材质文件。原则：不再运行时访问作者绝对路径、不执行附带 MAXScript/Python、不把网格塞进 model.json。

本机库管理创建与搜索；项目模型引用内容哈希并将用到的修订复制到项目受控目录。离线打包同时带项目资源；删除公共库条目不删除项目副本。缺失/损坏门窗回退现有参数化表达并标状态；家具保留实例参数和已存 CAD 符号，三维缺失显示明确缺资源标记，不制造一个“已恢复”的假家具。

## 6. 尺寸改变与运动共同解算

不能整体非等比缩放整樘门窗。规则可变资源必须通过“改尺寸 → 看二维/三维 → 开闭”联合验收。

| 部件 | 改尺寸策略 | 图上给用户看的形状 |
|---|---|---|
| 外框/扇框竖料 | 变长度、跟左右边界移动，截面不变 | 固定端灰色、中段青色，标长度箭头和截面尺寸 |
| 上下横料/中梃 | 按净格边界或固定/比例位置解算 | 立面分格线、边距尺寸、可变轴 |
| 玻璃/规则门板 | 变宽高、厚度不变 | 净格填色及宽高标注 |
| 五金、合页、把手 | 刚体移动，自身尺寸不变 | 小零件真实轮廓及距扇边/高度定位线 |
| 上亮 | 固定高度/比例/随总高，选一种明确规则 | 上亮单独着色，显示其高度而非仅文字选项 |
| 门槛、导轨 | 独立固定角色，按净宽调整 | 横截面和沿洞口长度示意 |
| 活动扇 | 先重建关闭净格，再随真实轴转动/轨道平移 | 整扇高亮，轴或轨道直接在模型上标记 |

型材有精细端头时由作者拆为刚性端部 + 可变中段，禁止把角码/把手一并拉伸。复杂雕花、弯曲件未声明可变规则时固定规格；多规格选择是能力，不伪装成连续参数化。

解算顺序：宿主/尺寸校验 → 固定边界与安装间隙 → 分格净宽高 → 各部件关闭尺寸/位置 → 合页/轨道/行程 → 实例开闭 → 二维/三维/编号输出。始终从不可变作者基准计算，不能对已开启/已缩放顶点反复变形。

分格支持等分、固定宽/高、比例与剩余空间；子母门必须能固定小扇、让大扇占剩余。最小净格/最大尺寸、五金越界、约束冲突给出具体部件提示；拒绝提交时保留旧实例。

改尺寸明确“当前一樘／同编号类型”，沿用自动编号与重名合并/新后缀。合并到已有类型要采用其完整构造/资源规则，不能只换编号。整笔几何、编号、资源引用、运动状态一个撤销事务。公共资源不被项目修改污染。

## 7. 三维开启与关闭

- 固定框、门套、固定玻璃、上亮、中梃和轨道不动；一扇的框、玻璃、门板、把手等可为多个网格，共用运动组。
- 双扇各自一个运动组，默认两侧外框合页，不出现两扇前端互相对着作为合页的错误。上悬/下悬使用水平轴；推拉使用轨道位移。
- 三维默认关闭，实例有显示开启开关；平开用角度，推拉用比例/位移。角度预设 15/30/45/90，加数字输入；双扇支持联动或逐扇设置。
- 三维展示关闭不改变 CAD 平面角度。门平面实扇、浅色虚线弧；窗平面保持固窗轮廓，只叠加单线虚线开启部分。方向夹点和三维轴/方向必须一致。
- 配对时支持拾取轴点/轴线、标准边界建议和数字微调。闭合回位使用关闭基准，不累积误差；镜像必须同步变换合页轴、方向、法线与绕序。
- 开闭预览只变换实例/部件缓存，不解码整份 GLB、不重算整栋墙洞。开启提交可撤销，预览取消不撤销此前应用。
- 运动状态与尺寸规则分开保存、共同验证。尺寸变化导致行程/角度超出约束时先说明修正/取消选项，不偷偷保存越界状态。
- 首期简单刚体开闭；折叠、卷帘、复杂联动单独阶段，不开放没有驱动的假控件。

## 8. 家具、洁具和设备

家具与门窗共用资源/文件/缩略图/尺寸/刚体运动/材质层，不共用宿主开洞或门窗编号模型。

| 类别 | 首批对象 | 放置与专有能力 |
|---|---|---|
| 普通家具 | 桌、椅、床、沙发 | 楼面基点、旋转、离地、复制/阵列；选规格优先，软包不任意拉伸 |
| 规则柜体 | 衣柜、橱柜 | 可变宽/深/高、板厚固定、门片转动、抽屉平移；踢脚和把手独立 |
| 洁具 | 坐便器、洗手盆、浴缸 | 固定规格、落地/壁挂、安装高度；二维独立符号与统计 |
| 设备 | 空调室内机、机柜等 | 壁挂/落地宿主、离地、朝向、维修空间可选表达；不自动做设备系统连接 |

新增独立 FurnitureType/FurnitureInstance 或类别适配模型，不塞进 OpeningModel。自由放置不切墙；壁挂与靠墙只定位，除非另有明确孔洞构件。

家具基点默认落地基准、用户确认的中心或角点；壁挂另有背面安装面。放置预览有落点、正面方向、落地高度、碰撞候选边界；碰撞警告可选择继续，不以家具相交拦截整个建筑生成。

编辑提供移动、旋转、复制、靠墙/距墙输入、居中、尺寸/规格。柜门/抽屉复用 MotionRule；沙发等柔性造型只允许作者明确声明的规格或分区规则。家具清单统计型号/规格/数量/楼层，不能显示无关窗台或门槛字段。

标准层家具采用楼层集合/实例规则，三维展开每层效果，统计按实际层数；单层修改必须明确“仅本层／共用标准层”，不能用户改一层而无提示改全部。

## 9. UI 设计：图库选型

沿用用户已选图库网格布局：左分类、中缩略图、右预览参数、底部主操作。设计参考见 [既定稿](../designs/component-library-20261005/README.md)，本轮扩展图见 [配套 UI](../designs/component-collaboration-20261007/README.md)。

- 顶部搜索、来源、网格/列表；导入、新建、更多使用统一图标。来源“公共库／项目／内置”，权限/版本在管理时显示，不让放置面板堆文件元数据。
- 左侧门、窗、家具、洁具、设备类别；支持收藏、最近使用。只有实际可放置类别开放。
- 中间缩略图必须来自实际几何，注明名称/编号或型号、尺寸、固定规格/可变尺寸、可开启能力；状态不能只靠颜色。加载/失败/空搜索独立显示，不用照片冒充真实导入。
- 右侧平面/立面/三维页签；显示相应编号/型号、真实可编辑参数。固定规格显示锁及规格列表；可变显示范围和内联错误。门窗显示洞口/窗台/门槛；家具显示长宽高/离地/安装面，不混用。
- 可展开部件预览条，实际绘出固定框、左右扇、五金；悬停同步高亮，普通用户不在此改底层绑定。
- 主操作“放置”，取消位置固定；管理操作收在图标菜单，不与放置竞争。双击资源按当前已验证参数进入放置，不跳过校验或误发布。
- 放置中鼠标直接预览，左键落点，Esc 取消未提交动作；门窗沿墙居中保持右键规则。不会要求在鼠标预览期间去点击不可达的远处按钮。

## 10. UI 设计：作者配对编辑

窗口采用左部件树、二维/三维并排、右属性；顶部紧凑页签和来源工具，底部保存位置固定。页面是工作区，不套多层装饰卡片。

- 创建只先填类别、名称、参考尺寸并选择二维/三维来源；来源识别得到的建议可确认，不按编号猜节点，也不根据模型最长边猜方向。
- 基点/方向页在两幅预览画共同基点和轴向。CAD X/Y 沿墙输入配合当前 UCS；三维允许必要的轴向归一化，显示转换前后尺寸。毫米字段与 CAD 原单位字段明确分开。
- 左部件树每行是“真实形状缩略图 + 名称 + 固定/活动/未绑定状态 + 可见性”；多节点可以归一个扇组。点击任一列表/二维/三维，其他两个联动，不重复找部件。
- “隔离选中”用眼睛图标，将其他部件淡化而非永久删掉；提供恢复整体、剖切/透视观察与适合视图。轮廓、颜色和文字一起表示选择。
- 部件属性顶部放大绘出选中部件的局部形状；固定端、可伸长中段、变长轴、截面、合页轴、轨道以可区分颜色/线型标注。用户要求的“部件样子”必须在此看到，不用抽象框代替真实几何。
- 尺寸页签按当前部件显示规则：“固定”“随洞口”“可变中段”；尺寸箭头可点选相应字段，输入数字时同步两幅预览。简单作者先用预设锚定，高级表达式不作为默认输入方式。
- 开闭页签选择固定/平开/推拉/悬开，画轴或轨道；合页拾取/轴向/方向/限制仅在需要时出现。开闭测试有预设、滑块、数字输入，闭合能直接回位。
- 全部编辑先在草稿；重导入 CAD/GLB 时显示部件匹配/丢失列表，重名不自动猜绑定。校验通过才允许发布；未完成可“保存草稿”，不能出现在普通用户可放置集合。
- 保存到公共库创建新修订；保存项目模板与发布公共资源是不同操作。取消只丢草稿，不回滚已明确应用的项目修改。

## 11. UI 设计：实例编辑与家具放置

- 直接使用已有三维工作区，不开一个大型向导才能挪家具。选中对象后右侧“位置／尺寸／开闭”属性，所有字段按能力和类别显示。
- 平面/三维双视图可切换，不常驻一个遮挡操作的大型浮窗。门窗夹点继续支持编号、移动和方向；家具有落点、旋转、尺寸边界夹点。
- 家具放置时三维显示真实模型、底部落点与方向，平面显示 CAD 符号。柜体抽屉和门片直接可见，选择部件时小缩略图标出操作对象。
- 数值字段修改有即时草稿预览，但拖动/输入不每帧重建整栋。释放夹点即可提交；数值输入有明确应用动作，Esc 不撤销已经提交内容。
- 开闭对多个实例支持显式批量操作，但默认作用当前选中；关闭显示记住用户角度/比例。批量按钮显示影响数量，禁止按同编号暗中改整栋。
- 小窗口时收起类别栏，作者二维/三维改页签，属性可折叠；字段和主按钮不裁切，不缩到无法输入。滚动只有细轨道和胶囊滑块，无额外滚动箭头。

## 12. 软件间修改、导出与打开

第一版是明确的文件交接，不承诺几个软件同时编辑的实时同步。

1. 本机源文件关联只存作者工作区，不作为项目运行依赖。用户点“打开来源”之前检查软件路径/来源存在；外部进程失败保留现有资源。
2. 在 CAD/Max 等修改后重新导出交换文件，在配对里“更新来源”。比较原尺寸、部件/节点、材质槽、绑定与规则；匹配不确定项必须确认。
3. 修改保存成新修订。项目可预览旧/新差异、受影响类型和实例数量，选择更新；不自动改全部同名资源。
4. 外部导出的 GLB 只是可见几何快照，不自动保留我们所有参数化规则。另存交换元数据能辅助追踪，但外部删改节点/改名后要验证；不宣称无损参数往返。
5. “导出后打开”选择软件、整栋/楼层/选中范围、当前开启状态/闭合姿态。只启动自己的新实例/导入流程，不重置用户未保存场景；不能安全打开时给出路径和手动入口。
6. 外部修改三维默认作为视觉资产更新，不反向改项目墙、楼层、洞口或 CAD 语义。未来双向建筑编辑另立协议，不能把网格包围盒当真实洞口直接覆盖。

## 13. CAD 输出约束

- 建筑和家具几何 1:1，比例控制图框/纸面注释，不缩放建筑实体；线宽、字高/宽度因子和图层从现有制图标准映射。
- 门窗/家具平面优先 CAD 矢量，不投影三维三角网格制造乱线。静态/动态二维能力明确区分；改尺寸/开闭需要对应规则或明确参数化替代。
- 门窗编号与家具型号/实例标记为独立注释，贴近构件且可拖动。门窗沿用现有编号识别；家具 CAD 元数据通过稳定资源/实例 ID 标记，不只靠文字位置识别。
- 图纸只绘造型和表达需要的线，墙交接缝仍仅编辑平面保留、图纸隐藏；重合楼板线沿用现有裁剪。闭合实体线宽向内，开启符号虚线规则保留。
- 家具出图支持显示/隐藏/按类别及详简等级，构件清单独立；未来二维块重复定义缓存、按实例引用，避免巨大 DWG。
- CAD 回读区分插件生成块/原生来源块/代理实体，不将导出图中每段线重新当新门窗；自动回关联必须有稳定身份与用户确认。

## 14. 材质与性能

材质分期：基础色及透明/法线 → 贴图和基础 PBR → 材质预览与灯光。当前来源检查的无贴图限制继续有效，放开之前需纹理安全、缓存、透明和法线验收。Max/Blender 的所有原生材质不承诺一键相同效果。

性能分层：不可变解码网格按资源修订缓存；尺寸解按修订+参数缓存；实例只持变换/开闭状态；GPU 上传和纹理共享。改变一个门槛/方向/角度不能触发全库读盘或整栋重建。源更新失效只针对受影响资源，取消任务不提交半成品。

拟定验收目标，实测后才能标通过：现有山水湾模型在固定硬件记录基线；热缓存下单实例拖动/开闭目标至少 30 fps，预览输入到反馈 P95 不超过 100 ms；提交超过 300 ms 有忙碌反馈。低配可降预览精度，不降低最终保存/出图精度。记录中冷加载/热缓存、实例数/面数、硬件、内存和 P95 分开，不能用一个小样例平均值代替整栋验证。

## 15. 安全、失败状态与兼容

- 包路径相对且限制文件数量/展开体积/压缩比/网格与纹理；拒绝穿越、链接逃逸、非法坐标、外部网络资源、未知必需扩展。第三方文件用成熟解码器，附带脚本永不自动执行。
- 先暂存、完整校验、原子发布；失败不污染库、项目或源图。读写/预览异步可取消，关闭窗口释放任务和 GPU 引用。
- 状态至少包括无二维、无三维、未绑定、尺寸冲突、缺资源、不可变规格、解析失败、加载中、来源已变化；有具体修复操作，不只有“导入失败”。
- 类型/实例/资源修改均有作用范围和撤销；备份旧版本。导出读取快照，不将外部应用返回的脚本/文本当执行指令。
- 旧项目、v1 参数包和现有 MM 保持可用。新包在旧版明确拒绝，而不是部分加载后给出错误模型。
- 不因版本测试启动/关闭用户已有 CAD/Max/Blender/SketchUp 会话。安装覆盖仍需用户本轮明确授权和进程检查。

### 19.2 接入方式与普通用户体验

1. 图库卡片注明“参数门窗”或“外部构件”；项目门窗、旧模板、v1 公共库继续出现并可放置，不要求重新导入 CAD/Max。
2. 未设置外部引用的门窗默认原参数生成；以后采用独立渲染来源/尺寸驱动能力标记，项目洞口仍属于原 OpeningModel。外部资源只是受约束的表达来源，不创建第二份墙洞语义。
3. 旧分格编辑器及编号、尺寸、窗台、门槛、开启角度、翻转、沿墙居中、移动夹点保留。外部资源若不支持某项，只将不支持的作者构造操作明确禁用，并提供“恢复参数门窗”；不能让一个假按钮静默无效。
4. “保存到图库”默认把旧门窗保存为参数资源，可生成真实缩略图和部件图；不把每个旧门窗烘焙成锁尺寸 GLB。
5. 作者可以“另存为外部构件”，输出关闭姿态三维和二维候选，保留原参数资源。可建议分组/轴点，但须人工核对尺寸规则、部件身份、镜像与开闭，不能因导出成功就宣布参数化等价。
6. 若给现有门窗“替换三维”，先预览尺寸/朝向/动作支持和影响范围。默认当前一樘，必要时产生独立类型；同编号批量替换须明确范围。编号与墙洞位置不因选资源名称改变。
7. 资源缺失/损坏时，保留全部实例信息并用原参数构造回退，标明“外部资源缺失 · 参数回退”。复杂外形不能保证回退外观相同，不能把近似外观称为完全恢复。

### 19.3 读写、升级和撤销

- 新版读旧版：缺少资源字段按参数来源处理；缺字段归一化在统一读入路径做，不能仅依赖属性初始化器。`OpenIn3D=null` 保留现有旧数据解释，不能导入时一律写 false；“新插入默认关闭”不等于“历史开启状态强制关闭”。
- 不按编号字符串重新猜已有立面、开向或分格。已有类型/逐格开启数据优先；只有旧文件确实无类型时才沿用现有默认生成逻辑。
- 新外部字段必须覆盖复制、标准层物理展开、JSON 往返、编辑候选、撤销快照、CAD 重新登记保留等所有路径，防止 UI 上引用正确而保存/复制后丢失。后续修改先建专项测试。
- 外部包和模型版本分别管理。只有在确实使用新模型字段时升级模型 schema，并在覆盖保存前保存可回退备份。现有 `LoadModel` 版本闸门拒绝未来模型；仍需核对所有插件/程序入口都走该闸门。
- 旧程序读取新模型不能承诺无损。另提供明确的“导出旧版参数副本”，列出丢失的外部造型/动作/材质能力，保留原新项目；禁止自动降级覆盖。若直接读取已被改造的副本也不能绕过版本闸门。
- 替换/恢复/尺寸修改的类型、资源引用、实例参数和编号一次提交、一次撤销。Esc 取消未提交预览，不还原已经应用的操作。
- 不悄悄迁移安装库或批量重存工程。本轮用户“暂不覆盖”继续有效；规划和设计图不触发安装。

### 19.4 兼容验收矩阵与放行

G1 就建立旧版本文件固定夹具；G2/G3 每次外部功能变更重跑。真实山水湾工程使用用户文件的只读副本，并按现有类型/单樘/标准层建立前后比较，不拿生成图充当兼容样本。

| 样例 | 必须一致或明确提示 |
|---|---|
| 无类型旧门窗、内置模板、v1 包 | 能加载/放置、无强制外部依赖；缺类型默认行为有快照 |
| 单/双扇、子母、上亮、TLM、MLC、凸窗 | 分格/净尺寸/门联窗区域、合页/轨道及开向不变 |
| 固定/平开/推拉/上悬窗 | 固窗轮廓、窗虚线单线开扇、门实扇虚线弧保持区别 |
| 单樘改尺寸/改号/手工号/编号冲突 | 原子校验、范围和合并/后缀行为不退回 |
| 编号夹点、翻转、移动/居中、门槛 | ID/宿主/位移及输入距离不丢；Esc 不当撤销 |
| 标准层、复制、CAD 重新生成、保存重开 | 实际多层展示、计数、来源优先级、覆盖及引用一致 |
| 参数与外部混合项目 | 各自后端正确，不重复绘制门窗；缺资源回退有标记 |
| 另存转换、替换范围、更新修订、取消/撤销 | 原参数资源不变，项目与公共库不互相污染 |
| 山水湾大模型 | 单樘更新不重算整栋，记录硬件/数量/冷暖缓存及 P95 |

只有上述混合项目、文件升级和真实样例通过，才对用户开放外部正式替换。当前已能保留旧方式的结构依据充分，但不能提前声称新后端全部兼容已经完成。
