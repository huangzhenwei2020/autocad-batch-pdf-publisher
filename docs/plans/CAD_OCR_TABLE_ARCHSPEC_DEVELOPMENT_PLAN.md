# CAD 图像识别、CAD 表格转换与建筑设计说明增强开发计划

> 文件用途：后续 Codex 修改和测试的执行依据。  
> 建立日期：2026-09-06。  
> 基准分支：`codex/detail-layout-frame-ranges`。  
> 基准提交：`0726c65`（普通门默认图集迁移为“无”）。  
> 适用范围：`BatchPdfPublisher`、`LineVisionOcrWorker`、`CadArchSpecEditor`。  
> 关联计划：`docs/plans/CadArchSpecEditor_Codex_MasterPlan.md`。

## 1. 总目标

按相互独立、可以逐步交付的方式完成三项能力：

1. 提升“图片转 CAD”的中文、数字、尺寸符号和旋转文字识别能力；
2. 增加“CAD 表格转可编辑表格文件”功能；
3. 参考 GenOffice 的结构化文档和局部修改思想，继续完善建筑设计说明助手。

三项能力共享结构化数据模型和导出能力，但不得把所有识别流程混成同一种算法：

- 图片、扫描件、PDF 底图：使用 OCR 和图像结构识别；
- 原生 DWG：优先直接读取 CAD 实体，不经过截图和 OCR；
- 建筑设计说明：以结构化项目数据为唯一业务数据源，AI 只能提交可审阅的局部修改建议。

## 2. 不可违反的安全原则

### 2.1 不破坏用户图纸

- 识别、预览、导出阶段只读访问当前 DWG；
- 未经用户明确点击“写回 CAD”，不得新增、删除或修改实体；
- 写回操作使用单独事务，任一关键步骤失败时整体回滚；
- 不用识别结果自动覆盖原文字、原表格或原设计说明；
- 每次写回前显示目标、数量和处理方式。

### 2.2 本地优先

- PaddleOCR 默认在本机独立进程运行，图纸和图片不上传；
- OCR 模型版本固定，下载包必须校验哈希；
- 模型不可用时允许回退到现有 Windows OCR，并清楚显示当前使用的引擎；
- OCR Worker 崩溃、超时或内存不足不得拖死 AutoCAD UI。

### 2.3 结果必须可审查

- OCR 文字保留原文、规范化文字、置信度和坐标；
- CAD 表格识别保留源实体 Handle、所在空间、图层及几何范围；
- 低置信度、跨格、无法归属文字必须单独标记，不得静默丢弃；
- 导入建筑设计说明的数据保留来源和导入时间。

### 2.4 跨版本兼容

- AutoCAD 2022—2024 使用 .NET Framework 4.8；
- AutoCAD 2025—2026 使用 .NET 8；
- OCR 和复杂文件转换放在独立 Worker 中，避免原生依赖进入 AutoCAD 进程；
- 共享协议使用向后兼容的 JSON，并带协议版本号。

## 3. 技术选型结论

### 3.1 PaddleOCR 的使用边界

采用 PaddleOCR 作为增强 OCR 与扫描表格识别引擎，主要使用：

- PP-OCR 系列：图片转 CAD 的文字检测与识别；
- 文字方向、旋转框和置信度输出；
- PP-StructureV3：扫描图片或 PDF 中的表格结构识别；
- 后续根据测试决定是否使用单字坐标。

不采用以下做法：

- 不把 Python 运行时或 Paddle 原生库直接加载进 AutoCAD；
- 不让 PP-Structure 处理原生 DWG 线框表格；
- 不自动跟随 PaddleOCR 最新版本，必须锁定已验证版本。

PaddleOCR 为 Apache-2.0 许可。发布时保留许可证、版权声明和第三方依赖清单。

### 3.2 GenOffice 的使用边界

GenOffice 主要用于架构参考，不整体嵌入当前 AutoCAD 插件。重点借鉴：

- 原始文档作为事实来源；
- 结构化块模型；
- 仅更新被修改的块；
- 修改前后快照和差异；
- 文档解析、编辑、渲染、导出相互分离；
- AI 操作产生建议，用户确认后才应用。

不得直接复制 GenOffice 的 `ee/` 企业许可目录。引用其 Apache-2.0 代码时必须逐项记录来源和许可证。

### 3.3 表格文件格式

- 第一阶段支持 CSV，确保简单、稳定、可测试；
- 正式版本增加 XLSX，保留合并单元格、行高、列宽、换行和基本对齐；
- 不使用已废弃的 Excel COM 自动化；
- 优先选择支持 .NET Framework 4.8 与 .NET 8 的开源 OOXML 方案，选型后固定版本并补充第三方声明。

## 4. 总体架构

```text
图片 / 扫描件 / PDF
        │
        ▼
PaddleOCR 独立 Worker ──► OCR 统一 JSON ──► LineVision 预览和 CAD 写入
        │
        └────────────────► 扫描表格结构结果

原生 DWG
        │
        ▼
CAD 实体读取器 ──► 网格推断 ──► 单元格文字归属 ──► 表格识别预览
                                                        │
                                  ┌─────────────────────┼──────────────┐
                                  ▼                     ▼              ▼
                                CSV                   XLSX       建筑说明专业表格
```

建议新增模块：

```text
PaddleOcrWorker/
BatchPdfPublisher/Features/CadTableExtraction/
CadArchSpecEditor/src/.../Imports/
```

统一数据协议至少包含：

- `protocolVersion`；
- 输入文件哈希和尺寸；
- 识别引擎及模型版本；
- 文字内容、原始内容、置信度、旋转角和多边形；
- 表格范围、行列边界、合并关系和单元格内容；
- 警告、耗时及错误码。

## 5. 分阶段执行计划

状态标记：`[ ]` 未开始、`[~]` 进行中、`[x]` 完成、`[!]` 阻塞。

### 阶段 0：基线冻结与样本准备

- [ ] 记录当前 LineVision、门窗立面和建筑说明测试基线；
- [ ] 收集不少于 20 张建筑图像样本，覆盖中文、数字、标高、尺寸、轴号、旋转文字和低清晰度；
- [ ] 收集不少于 15 个 DWG 表格样本，覆盖原生 Table、线框表格、块内表格、旋转表格、断线和合并单元格；
- [ ] 样本脱敏，不把真实项目名称和敏感路径提交到 Git；
- [ ] 建立期望结果文件，允许自动比较文字、位置、行列和合并关系。

验收条件：

- 基线构建通过；
- 样本类型清单完整；
- 每类至少存在一个可重复自动测试的期望结果。

### 阶段 1：PaddleOCR 增强 Worker

#### 1.1 协议与进程

- [ ] 在现有 `ILineVisionOcrEngine` 基础上增加引擎标识和能力信息；
- [ ] 定义带版本号的 OCR 请求/响应 JSON；
- [ ] 新建 PaddleOCR 独立 Worker；
- [ ] 支持取消、超时、进度、标准错误日志和强制结束；
- [ ] Worker 临时目录使用唯一任务目录，完成后安全清理；
- [ ] AutoCAD 关闭时不得等待 Worker 无限退出。

#### 1.2 模型与部署

- [ ] 选定稳定的中文检测和识别模型；
- [ ] 测量 CPU 首次启动、重复识别、内存和安装体积；
- [ ] 明确“随安装包携带”或“首次按需下载”的发布方式；
- [ ] 增加模型版本、来源、哈希和许可证清单；
- [ ] 无模型、下载中断和模型损坏时给出可恢复提示。

#### 1.3 工程图文字处理

- [ ] 输出真实文字多边形、置信度和方向；
- [ ] 增加尺寸字符规范化，但同时保留 `OriginalText`；
- [ ] 处理 `×/X`、`Φ/φ`、`±`、小数点、负号和括号；
- [ ] 处理竖排文字和 90/180/270 度旋转；
- [ ] 对重叠识别框去重；
- [ ] 使用多边形而非粗略矩形遮罩文字，避免误删附近线条。

#### 1.4 UI

- [ ] 增加“自动选择 / PaddleOCR 增强 / Windows OCR 兼容”选项；
- [ ] 显示当前引擎、模型版本、识别阶段和进度；
- [ ] 允许取消；
- [ ] 识别完成后允许逐条编辑、启用或禁用文字；
- [ ] 低置信度文字使用明显但不妨碍查看的状态标识。

验收条件：

- AutoCAD UI 在识别过程中可移动、可取消、可关闭；
- Worker 异常不导致 AutoCAD 崩溃；
- 在基准图片集上，中文和工程符号正确率明显高于 Windows OCR；
- 原有 Windows OCR 模式仍可独立工作；
- LineVision 现有线、圆、圆弧和墙体识别测试无回归。

### 阶段 2：原生 CAD 表格转可编辑表格

#### 2.1 用户流程

- [ ] 新增命令和入口“CAD 表格转文件”；
- [ ] 用户框选一个表格范围或选择原生 Table；
- [ ] 只读分析后显示可编辑预览；
- [ ] 用户确认行列、合并单元格和文字；
- [ ] 导出 CSV/XLSX，或导入建筑设计说明专业表格。

#### 2.2 CAD 实体读取

- [ ] 支持 AutoCAD `Table`；
- [ ] 支持 `Line`、`Polyline`、`Polyline2d` 中的水平和垂直边；
- [ ] 支持 `DBText`、`MText` 和 `AttributeReference`；
- [ ] 正确处理块参照变换、嵌套块、比例和旋转；
- [ ] 默认忽略不可见、冻结或关闭图层，并允许用户选择包含；
- [ ] 记录每个识别元素的源 Handle，便于定位。

#### 2.3 网格推断

- [ ] 合并共线短线和被文字打断的边线；
- [ ] 建立 X/Y 边界聚类，容差随当前图形单位和文字高度确定；
- [ ] 判断外框、内部网格、缺边和多余装饰线；
- [ ] 识别横向和纵向合并单元格；
- [ ] 支持整体旋转后的表格；
- [ ] 对不闭合或无法唯一判断的区域给出警告，不自动猜测为有效单元格。

#### 2.4 文字归属

- [ ] 根据文字包围盒中心和重叠面积归属单元格；
- [ ] 同一单元格内按阅读顺序合并多段文字；
- [ ] 保留 MText 换行，清理 CAD 格式控制码；
- [ ] 跨格文字、边界文字和重复文字进入待确认列表；
- [ ] 数值按文本保存，避免编号、前导零和日期被 Excel 自动误改。

#### 2.5 编辑与导出

- [ ] 复用 `ArchitectureTable` 作为中间数据模型；
- [ ] 预览中支持改单元格、插入/删除行列、合并/拆分；
- [ ] CSV 使用 UTF-8 BOM；
- [ ] XLSX 保留合并、换行、基本对齐、列宽和行高；
- [ ] 导出文件名使用图纸名和表格标题，不使用内部 GUID；
- [ ] 导入建筑说明前显示差异，不覆盖已有专业表格。

验收条件：

- 原生 Table 能完整导出；
- 规则线框表格的行列、文字和合并单元格正确；
- 旋转、断线、块内表格不会造成崩溃或错误写图；
- 导出的 XLSX 可由 Excel/WPS 正常打开；
- 整个识别过程不修改当前 DWG。

### 阶段 3：扫描表格和 PDF 底图后备识别

- [ ] 在表格工具中增加“图片/扫描表格”来源；
- [ ] 接入 PP-StructureV3 有线表格识别；
- [ ] 评估无线表格识别，达不到稳定标准时保持实验功能；
- [ ] 将 PaddleOCR 表格结果转换为统一 `ArchitectureTable`；
- [ ] 同时显示原图、单元格框和可编辑网格；
- [ ] 低置信度单元格必须人工确认后才能导出；
- [ ] PDF 只处理用户指定页和范围，避免一次加载整套大图纸。

验收条件：

- 扫描表格可以生成可编辑网格；
- OCR 失败不会生成看似正确但实际错位的静默结果；
- 原生 DWG 表格仍默认走直接实体解析。

### 阶段 4：建筑设计说明增强

#### 4.1 结构化内容块

- [ ] 明确章节、段落、列表、专业表格、引用和人工锁定块；
- [ ] 每个块具有稳定 ID、来源、修改人/方式、时间和版本；
- [ ] 项目参数与正文、表格之间使用显式绑定；
- [ ] 未修改块在保存和导出过程中保持原样。

#### 4.2 局部修改与差异

- [ ] AI 或规则引擎只能提交局部补丁；
- [ ] 应用前显示新增、删除、替换的内容；
- [ ] 支持逐项接受、拒绝和撤销；
- [ ] 保存前创建版本快照；
- [ ] 人工锁定内容不得被自动修改。

#### 4.3 CAD 与表格数据复用

- [ ] 从 CAD 识别出的表格可作为新表或候选数据导入；
- [ ] 支持将专业表格写入指定 CAD 图框区域；
- [ ] 写回前校验图框 Handle、DWG 路径和可用范围；
- [ ] 来源 CAD 更新时只提示差异，不自动覆盖人工编辑结果。

#### 4.4 文档导出

- [ ] 在现有 CAD 输出基础上规划 DOCX/PDF 输出；
- [ ] 保留标题层级、编号、表格、分页和项目字段来源；
- [ ] 建立渲染后视觉校验，不以“文件能打开”作为完成标准；
- [ ] 不宣称自动替代设计、校对、审核或施工图审查。

验收条件：

- 单个章节或表格可以独立修改并查看差异；
- 未修改内容在保存后不发生无关变化；
- CAD 导入数据具有来源记录和冲突提示；
- 版本恢复能够还原正文、表格和字段绑定。

### 阶段 5：发布、兼容与回归

- [ ] AutoCAD 2022—2026 分别验证启动、识别、取消、关闭和写回；
- [ ] 在 100%、125%、150%、175%、200% Windows 缩放下检查 UI；
- [ ] 测试无 PaddleOCR、模型损坏、中文路径、超长路径和只读目录；
- [ ] 测试大图片、大表格和低内存环境；
- [ ] 安装包包含许可证、模型来源和版本清单；
- [ ] 用户版默认不要求安装 Python、Paddle 或网盘客户端；
- [ ] 建立升级和卸载测试，卸载不得删除用户项目或识别结果。

验收条件：

- 标准安装包可在未安装开发环境的新电脑上运行；
- 所有长任务均有进度、取消和超时；
- 不出现关闭窗口后 AutoCAD 仍被后台任务阻塞；
- 回归测试和手工验收清单全部通过后才进入用户版。

## 6. 测试矩阵

### 6.1 图片文字

- 白底黑字、黑底白字和彩色图；
- 低分辨率、压缩噪点、屏幕截图和扫描件；
- 简体中文、数字、英文缩写；
- 横排、竖排、倾斜和倒置；
- 标高、轴号、尺寸串、直径和正负号；
- 文字紧邻线条、文字压线和密集标注。

### 6.2 CAD 表格

- 原生 Table；
- 完整线框、断线、双线和局部缺边；
- 合并表头、跨行和跨列；
- DBText、MText、块属性和多行文字；
- 模型空间、布局空间、普通块和嵌套块；
- 旋转角度、非 1:1 块比例和不同图形单位；
- 不规则内容和无法唯一判断的反例。

### 6.3 数据安全

- 识别取消前后 DWG 数据一致；
- Worker 崩溃后 DWG 数据一致；
- 导出失败不产生半成品覆盖正式文件；
- 写回失败事务完整回滚；
- 项目文件恢复后来源和版本记录完整。

## 7. 每个阶段的固定工作流程

后续所有修改严格按以下顺序执行：

1. 在本文档中把当前任务改为 `[~]`；
2. 检查工作树，保留用户已有修改；
3. 补充或先写失败测试；
4. 实现最小闭环，不跨阶段顺手重构无关模块；
5. 运行针对性测试；
6. 运行相关模块完整测试和构建；
7. 检查 AutoCAD UI 是否可取消、可关闭；
8. 更新本文档状态、测试结果和已知限制；
9. 生成用户测试包，并明确测试入口和预期结果；
10. 用户确认后再进入下一阶段。

如果实际实现需要偏离本计划，必须先在本文档“变更记录”中写明原因、影响和新方案。

## 8. 第一轮实施范围

第一轮只完成“阶段 0 + 阶段 1 的最小闭环”，不得同时开始扫描表格和设计说明 AI 改写：

1. 固定 OCR JSON 协议；
2. 建立 PaddleOCR Worker 原型；
3. 用一组脱敏建筑图进行 Windows OCR/PaddleOCR 对比；
4. 接入现有 LineVision 预览；
5. 保留 Windows OCR 回退；
6. 验证识别期间 AutoCAD 不阻塞。

达到这一闭环后，再开始原生 CAD 表格提取。这样可以分别定位 OCR、CAD 几何解析和表格编辑的问题。

## 9. 已知风险

| 风险 | 处理原则 |
| --- | --- |
| PaddleOCR 安装体积较大 | 独立可选组件或首次按需下载，模型固定并校验 |
| CPU 识别速度不足 | 裁剪、缓存、限制输入尺寸，并提供取消 |
| CAD 表格线条不闭合 | 容差聚类加人工确认，不静默补成确定结果 |
| 表格中文字跨格 | 标记冲突，用户确认归属 |
| Excel 自动改变编号格式 | 数值默认按文本导出，需要时再显式转数值 |
| AutoCAD 多版本 API 差异 | 共享核心与薄宿主分离，分别构建测试 |
| OCR 或 AI 修改错误 | 原文、来源、置信度和差异始终可见 |
| 第三方许可证遗漏 | 安装包自动生成第三方声明，禁止引入许可不清依赖 |
