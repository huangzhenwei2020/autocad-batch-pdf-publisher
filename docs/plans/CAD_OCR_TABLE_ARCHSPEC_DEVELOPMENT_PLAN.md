## 1. 总目标

按相互独立、可以逐步交付的方式完成三项能力：

1. 提升“图片转 CAD”的中文、数字、尺寸符号和旋转文字识别能力；
2. 增加“CAD 表格转可编辑表格文件”功能；
3. 参考 GenOffice 的结构化文档和局部修改思想，继续完善建筑设计说明助手。

三项能力共享结构化数据模型和导出能力，但不得把所有识别流程混成同一种算法：

- 图片、扫描件、PDF 底图：使用 OCR 和图像结构识别；
- 原生 DWG：优先直接读取 CAD 实体，不经过截图和 OCR；
- 建筑设计说明：以结构化项目数据为唯一业务数据源，AI 只能提交可审阅的局部修改建议。

### 1.1 与现有门窗立面功能的边界

- 本计划后续功能与门窗立面业务无关；
- 不在 `Features/DoorWindows` 下增加 OCR、CAD 表格或建筑说明代码；
- 不复用门窗表格的业务模型、门窗编号规则、门窗图集设置或门窗 UI；
- 可以借鉴现有天正对象探针、只读爆炸和跨版本处理经验，但应提取为独立通用服务；
- CAD 表格识别结果的主要去向是 CSV/XLSX 和建筑设计说明专业表格。

## 2. 不可违反的安全原则

### 2.1 不破坏用户图纸

- 识别、预览、导出阶段只读访问当前 DWG；
- 未经用户明确点击“写回 CAD”，不得新增、删除或修改实体；
- 写回操作使用单独事务，任一关键步骤失败时整体回滚；
- 不用识别结果自动覆盖原文字、原表格或原设计说明；
- 每次写回前显示目标、数量和处理方式。

### 2.2 本地优先

- PaddleOCR 默认在本机独立进程运行，图纸和图片不上传；
- OCR 模型版本固定，下载包必须校验哈希；
- 模型不可用时允许回退到现有 Windows OCR，并清楚显示当前使用的引擎；
- OCR Worker 崩溃、超时或内存不足不得拖死 AutoCAD UI。

### 2.3 结果必须可审查

- OCR 文字保留原文、规范化文字、置信度和坐标；
- CAD 表格识别保留源实体 Handle、所在空间、图层及几何范围；
- 低置信度、跨格、无法归属文字必须单独标记，不得静默丢弃；
- 导入建筑设计说明的数据保留来源和导入时间。

### 2.4 跨版本兼容

- AutoCAD 2022—2024 使用 .NET Framework 4.8；
- AutoCAD 2025—2026 使用 .NET 8；
- OCR 和复杂文件转换放在独立 Worker 中，避免原生依赖进入 AutoCAD 进程；
- 共享协议使用向后兼容的 JSON，并带协议版本号。

## 3. 技术选型结论

### 3.1 PaddleOCR 的使用边界

采用 PaddleOCR 作为增强 OCR 与扫描表格识别引擎，主要使用：

- PP-OCR 系列：图片转 CAD 的文字检测与识别；
- 文字方向、旋转框和置信度输出；
- PP-StructureV3：扫描图片或 PDF 中的表格结构识别；
- 后续根据测试决定是否使用单字坐标。

不采用以下做法：

- 不把 Python 运行时或 Paddle 原生库直接加载进 AutoCAD；
- 不让 PP-Structure 处理原生 DWG 线框表格；
- 不自动跟随 PaddleOCR 最新版本，必须锁定已验证版本。

PaddleOCR 为 Apache-2.0 许可。发布时保留许可证、版权声明和第三方依赖清单。

### 3.2 GenOffice 的使用边界

GenOffice 主要用于架构参考，不整体嵌入当前 AutoCAD 插件。重点借鉴：

- 原始文档作为事实来源；
- 结构化块模型；
- 仅更新被修改的块；
- 修改前后快照和差异；
- 文档解析、编辑、渲染、导出相互分离；
- AI 操作产生建议，用户确认后才应用。

不得直接复制 GenOffice 的 `ee/` 企业许可目录。引用其 Apache-2.0 代码时必须逐项记录来源和许可证。

### 3.3 表格文件格式

- 第一阶段支持 CSV，确保简单、稳定、可测试；
- 正式版本增加 XLSX，保留合并单元格、行高、列宽、换行和基本对齐；
- 不使用已废弃的 Excel COM 自动化；
- 优先选择支持 .NET Framework 4.8 与 .NET 8 的开源 OOXML 方案，选型后固定版本并补充第三方声明。

### 3.4 追加调研结论

#### Autodesk 代理对象机制

Autodesk 官方说明表明：

- 第三方自定义实体在定义程序未加载时会以 `ProxyEntity` 形式存在；
- `ProxyEntity.Explode()` 可以返回其保存的图形副本；
- API 的 `Explode()` 是只读分解，不会删除或改写原实体；
- 这与用户执行的 `EXPLODE` 命令不同，后者会删除原对象并把分解结果写入图纸。

因此，天正文字兼容采用“原生属性优先、只读分解后备”，禁止为了读取内容而执行 CAD 的炸开命令。

#### `cad-extract`

开源项目 `ricklove/cad-extract` 提供了值得借鉴的 CAD 表格处理顺序：

1. 识别表格和单元格；
2. 将文字定位到单元格；
3. 识别合并单元格；
4. 分离相邻或接触的多个表格；
5. 输出 CSV/XLSX；
6. 用提取结果重新绘制并进行视觉回放比较。

该项目规模较小且 README 明确列有合并行列等未完成问题，因此只借鉴算法分层和视觉回放测试，不直接作为产品依赖。

Autodesk 在 2026 年的官方支持说明中仍表示 AutoCAD 不能直接把既有线条和文字转换成 Table，只能使用 DATAEXTRACTION 后人工整理，或自行开发自动化。因此“线框与文字自动还原成单元格”确实是需要本项目实现的独立能力，不是对已有 AutoCAD 命令的重复包装。

#### Camelot

Camelot 面向 PDF 而非 DWG，但其“结构由矢量线或图像线检测，单元格内容优先取原始文本层，只有扫描件才 OCR”的原则与本项目一致。可参考其结构与文字分离思想，不引入其 Python PDF 技术栈到 AutoCAD 插件。

#### ezdxf

`ezdxf` 适合独立 DXF 文件读写和测试数据生成，但本产品已经运行在 AutoCAD 内部，DWG 主路径应继续使用 Autodesk API，以保留对象 Handle、块变换、原生 Table 和天正运行环境。`ezdxf` 只考虑用于离线测试工具，不作为 DWG 正式读取器。

## 4. 总体架构

```text
图片 / 扫描件 / PDF
        │
        ▼
PaddleOCR 独立 Worker ──► OCR 统一 JSON ──► LineVision 预览和 CAD 写入
        │
        └────────────────► 扫描表格结构结果

原生 DWG
        │
        ▼
CAD 实体读取器 ──► 网格推断 ──► 单元格文字归属 ──► 表格识别预览
                                                        │
                                  ┌─────────────────────┼──────────────┐
                                  ▼                     ▼              ▼
                                CSV                   XLSX       建筑说明专业表格
```

建议新增模块，名称可在实施阶段按现有解决方案结构调整：

```text
PaddleOcrWorker/
CadTableExtraction.Core/
CadArchSpecEditor/src/CadArchSpec.Host.Shared/CadTable/
CadArchSpecEditor/src/.../Imports/
```

如果最终仍由主插件提供 Ribbon/命令入口，入口只负责启动独立功能，不得让 CAD 表格核心依赖 `Features/DoorWindows`。

统一数据协议至少包含：

- `protocolVersion`；
- 输入文件哈希和尺寸；
- 识别引擎及模型版本；
- 文字内容、原始内容、置信度、旋转角和多边形；
- 表格范围、行列边界、合并关系和单元格内容；
- 警告、耗时及错误码。

#### 2.2.1 天正文字兼容读取链

天正文字不是一个固定类型，T20/T30、不同 AutoCAD 版本以及“是否加载天正运行环境”会得到不同对象表现。因此不得只判断一个 CLR 类型，按以下优先级读取：

1. **标准文字**：直接读取 `DBText`、`MText`、块属性及原生 Table 单元格；
2. **天正运行环境已加载**：根据 `RXClass.DxfName` 识别 `TCH_*TEXT*`、`TCH_*WORD*` 等候选对象，通过只读 COM/IDispatch 候选属性读取真实文字、位置、高度和旋转；
3. **只读分解**：对无法直接取值的天正实体或 `ProxyEntity` 调用 API `Entity.Explode(DBObjectCollection)`，递归收集临时 `DBText/MText/AttributeReference`；
4. **图形 OCR 后备**：若对象有可见图形但前三层均取不到文字，只在用户允许时渲染选区并 OCR，结果标为低可信来源；
5. **无法识别**：保留源 Handle、DXF 名称和范围，在预览中显示“天正文字待确认”，不得丢弃或凭空生成内容。

实现约束：

- 禁止调用用户命令 `EXPLODE`；
- `Explode()` 返回的临时对象必须释放，不得加入数据库；
- 递归深度和对象数量必须有限制，防止异常代理对象卡死；
- COM/IDispatch 属性采用只读白名单，不调用未知方法；
- 文字坐标必须应用块参照和嵌套对象的完整变换矩阵；
- MText 同时保留纯文本与必要换行，不把格式控制码写入 Excel；
- 记录读取途径：`Standard`、`TianzhengProperty`、`ExplodedClone`、`OcrFallback`；
- 天正未加载时仍要尽量识别代理图形；天正已加载时优先读取真实对象数据；
- 分别建立 AutoCAD 2022—2026 与可获得的天正 T20/T30 样本测试。

现有 `TianzhengDoorWindowService`、`TianzhengScaleService` 和 `TianzhengTitleProbeService` 已验证 RXClass、IDispatch 与只读分解路径可行。实施时只提炼通用读取机制，不让新模块引用门窗业务服务。

- [ ] AI 或规则引擎只能提交局部补丁；
- [ ] 应用前显示新增、删除、替换的内容；
- [ ] 支持逐项接受、拒绝和撤销；
- [ ] 保存前创建版本快照；
- [ ] 人工锁定内容不得被自动修改。

#### 4.3 CAD 与表格数据复用

- [ ] 从 CAD 识别出的表格可作为新表或候选数据导入；
- [ ] 支持将专业表格写入指定 CAD 图框区域；
- [ ] 写回前校验图框 Handle、DWG 路径和可用范围；
- [ ] 来源 CAD 更新时只提示差异，不自动覆盖人工编辑结果。

#### 4.4 文档导出

- [ ] 在现有 CAD 输出基础上规划 DOCX/PDF 输出；
- [ ] 保留标题层级、编号、表格、分页和项目字段来源；
- [ ] 建立渲染后视觉校验，不以“文件能打开”作为完成标准；
- [ ] 不宣称自动替代设计、校对、审核或施工图审查。

验收条件：

- 单个章节或表格可以独立修改并查看差异；
- 未修改内容在保存后不发生无关变化；
- CAD 导入数据具有来源记录和冲突提示；
- 版本恢复能够还原正文、表格和字段绑定。

### 阶段 5：发布、兼容与回归

## 7. 每个阶段的固定工作流程

后续所有修改严格按以下顺序执行：

1. 在本文档中把当前任务改为 `[~]`；
2. 检查工作树，保留用户已有修改；
3. 补充或先写失败测试；
4. 实现最小闭环，不跨阶段顺手重构无关模块；
5. 运行针对性测试；
6. 运行相关模块完整测试和构建；
7. 检查 AutoCAD UI 是否可取消、可关闭；
8. 更新本文档状态、测试结果和已知限制；
9. 生成用户测试包，并明确测试入口和预期结果；
10. 用户确认后再进入下一阶段。

如果实际实现需要偏离本计划，必须先在本文档“变更记录”中写明原因、影响和新方案。

## 8. 第一轮实施范围

第一轮只完成“阶段 0 + 阶段 1 的最小闭环”，不得同时开始扫描表格和设计说明 AI 改写：

1. 固定 OCR JSON 协议；
2. 建立 PaddleOCR Worker 原型；
3. 用一组脱敏建筑图进行 Windows OCR/PaddleOCR 对比；
4. 接入现有 LineVision 预览；
5. 保留 Windows OCR 回退；
6. 验证识别期间 AutoCAD 不阻塞。

达到这一闭环后，再开始原生 CAD 表格提取。这样可以分别定位 OCR、CAD 几何解析和表格编辑的问题。

## 9. 已知风险

| 风险 | 处理原则 |
| --- | --- |
| PaddleOCR 安装体积较大 | 独立可选组件或首次按需下载，模型固定并校验 |
| CPU 识别速度不足 | 裁剪、缓存、限制输入尺寸，并提供取消 |
| CAD 表格线条不闭合 | 容差聚类加人工确认，不静默补成确定结果 |
| 表格中文字跨格 | 标记冲突，用户确认归属 |
| Excel 自动改变编号格式 | 数值默认按文本导出，需要时再显式转数值 |
| AutoCAD 多版本 API 差异 | 共享核心与薄宿主分离，分别构建测试 |
| OCR 或 AI 修改错误 | 原文、来源、置信度和差异始终可见 |
| 第三方许可证遗漏 | 安装包自动生成第三方声明，禁止引入许可不清依赖 |
| 天正对象随版本变化 | RXClass 分类加多级读取链，不绑定单一 CLR 类型或单一属性名 |
| 天正未加载只能看到代理对象 | 使用只读 `ProxyEntity.Explode()`，失败时明确标记并允许 OCR 后备 |
