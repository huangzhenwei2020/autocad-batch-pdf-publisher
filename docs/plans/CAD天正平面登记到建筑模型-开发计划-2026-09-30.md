# CAD（天正）平面登记到建筑模型：开发计划

日期：2026-09-30。代码基线：`4c4cede`。状态：2026-10-01 已接通楼层登记到直墙及门窗洞口模型生成，自动侧边定位和完整登记流程仍需天正宿主复验。

## 2026-10-01 用户流程修正

本节取代下文早期方案中“再次选择模型、拾取方向、先有 MCLM 做法才能登记”的要求：

- 先打开建筑模型并设置、保存楼层。CAD 楼层登记直接复用当前打开/另存为的模型路径，不提供“选择已有建筑模型”。项目模型状态通过项目目录的 `建筑模型/当前模型.txt` 连接；登记保存到模型文件旁的 `.cad-floors.json`。
- 楼层列表每行提供“拾取基点”和“框选登记平面”，每次拾取后返回列表，可连续登记多层。方向沿拾取时的当前 CAD UCS X 轴，无需第二个方向点。旋转平面须先设置对应 UCS。
- 每层基点及登记结果单独持久化；重新登记只替换本层。标准层来源登记一次，引用层自动复用，按当前模型的实际楼层统计，删除或变更引用后重新汇总。
- 门窗尺寸和来源洞口由框选范围内的天正 `TCH_OPENING` 读取；编号尝试读取该洞口自身显示部件的唯一编号文字，未知或不唯一时要求补充核对。该新增编号途径尚未在真实天正宿主复验，不能称为已完成全部编号适配；不从附近文字、图层或句柄猜编号。
- 登记不要求用户选择或核对门窗类型；读取尺寸及已有编号后生成普通门/窗默认做法，原图编号不可读时按尺寸自动编号。具体类型、分格、开启方式由已有 MCLM 功能调整；不以已有做法或门窗表为前置条件。
- 登记完成后点击“生成建筑模型”，创建当前模型的墙及宿主洞口，刷新三维和平面并保存，整批可撤销。洞口从自身侧边线或整宽框边线核验唯一位置；类型未知使用默认值，底高未指定时门 0 / 窗 900 mm（按墙高调整）。几何定位缺失仍报告；缺墙高须明确选择按层高。曲墙和非零/未知墙底偏移明确阻断。
- 登记结果同步生成分层门窗统计，MCLM 后续加载此表用于门窗做法设置。门窗立面继续使用现有分格、开启、框料和模板系统。离地高度修改后写回对应楼层登记记录，保留 CAD 原编号和来源；再次生成模型才更新相应洞口。
- 导入来源稳定去重，重登更新无人工修改的来源构件；发现模型内已有修改或删除时阻断并提示。已处理请求被消耗，避免撤销后重新打开模型自动重放。详细验证见[流程修正记录](../reviews/CAD楼层登记流程修正-2026-10-01.md)。
- 自动测试覆盖当前模型切换、多层累加、单层替换、标准层计数、重复洞口阻断、离地高度回存及失败原子回滚、窗口布局。新流程的完整 CAD 点击/框选及天正编号读取仍需宿主复验。

实施进展：P0 的只读核验代码、自动化测试和 CAD 2022 发布已完成，实机读取20面墙和20个洞口；墙厚、墙高及标高已抽样核对。门窗宽高可读，编号、准确位置和宿主尚需适配；门窗类别、样式和细部按编号复用门窗立面参数，窗台可从项目参数预填并确认。操作方法和验证边界见[P0 实施记录](../reviews/CAD天正对象只读核验-P0-2026-09-30.md)。其余批次仍按本文计划推进。

本计划细化[建筑模型完整工作流任务书](建筑模型完整工作流-开发任务书-2026-09-27.md)的 B01–B04、B06–B09。当前优先做原生天正墙、门窗及楼层登记；普通双线墙识别 B05、复杂楼梯建模和三维资产互通继续按各自任务推进。本计划不改变现有建筑模型入口，不启用旧版建模程序。

## 1. 本轮交付目标

用户在 AutoCAD 2022 + 天正中选择一层建筑平面，登记到当前项目的指定楼层，核对墙与门窗参数，确认后在新版万落建筑模型中得到可以编辑、保存、撤销和生成 CAD 图纸的构件。

完整操作顺序：

1. 从建筑模型入口打开当前模型，设置楼层后保存；“CAD 楼层登记核对”直接复用这个模型。
2. 设置楼层顺序、名称、各层层高和一个基准楼层标高；地下层、标准层使用现有楼层规则。
3. 选择登记楼层，再在 CAD 中框选该层范围；图框和手动选对象作为辅助方式。标准层登记一次，明确选择引用它的实际楼层，不用层数代替楼层身份。
4. 各层点击“拾取基点”，用同一建筑位置对齐；方向沿当前 CAD UCS X 轴，默认毫米，其他单位在坐标与单位设置中指定。
5. 扫描墙、门窗、轴线轴号，显示原始参数、缺失项和异常；用户勾选、补值、修改或排除对象。
6. 确认导入，整批创建墙和宿主洞口；在三维和平面核对，修改窗台高、尺寸、墙厚等。
7. 保存重开，生成平面、立面和剖面，使用已有发布链路推到 CAD。
8. CAD 源图改变后重新登记，显示差异，不重复建墙、不静默覆盖模型侧修改。

第一版读取源图，不修改原生天正对象。登记时修改参数作用于万落模型；回写天正原生墙门窗另设任务，不能把“推送生成图纸”当作原生对象回写。

以下结论来自仓库代码和已有验收记录，本轮没有重新在真实 CAD 图纸上验证。

关键证据与风险：

- 楼梯已有记录包含左右厚度为 `100/100` 和 `20/100` 的墙；不能统一把墙当居中墙。
- `TryReadCurveAxis` 当前在读取失败时使用包围框中线，`ReadNearbyWalls` 将不可读左右厚度置为 0。这两种兜底仅能用于诊断或人工辅助，**正式转换必须保留“不可读”状态，不能冒充原生参数**。
- 现有楼梯扫描忽略短于 200 mm 的墙；整栋识别不能照搬这个阈值，否则短墙和门垛会消失。
- `AxisModel` 当前只表达水平/竖直轴线；`WallModel` 没有独立墙底偏移。需要先定义扩展或明确阻止相应对象转换，不能默默损失参数。`OpeningModel` 没有实例镜像/开启方向；按用户本轮确定的范围，这些不再作为读取天正门窗的前置条件，使用现有门窗立面做法，实例差异后续由模型编辑设置。

详细历史证据：[楼梯平面提取计划 §16](../../StairDetail/docs/stair-plan-capture-and-layout-development-plan.md#16-首次真实天正图纸探针结论2026-08-23)。

## 3. 第一版范围

### 支持目标

- AutoCAD 2022，优先复验本机正在使用的天正版本；记录完整版本，不能仅凭 `TCH_*` 类型承诺所有版本可用。
- 原生直线墙，含斜直墙、不同厚度、左右偏心及已支持的 L/T 交接。
- 普通矩形门、窗、洞口的实例位置、尺寸和宿主；明确缺失字段后允许人工补值。
- 多层平面、地下层、标准层；同层多个登记区域的去重与边界归属。
- 正交轴网，两端轴号独立；其他轴网保留底图并列为待适配。
- 原始平面底图锁定显示，便于导入前后叠加核对。

### 暂不自动转换

- 弧墙、变截面墙、复杂幕墙、转角窗、凸窗、门联窗等现有实例模型不能完整表达的对象。
- 非均匀缩放、复杂镜像嵌套、外参中不可可靠读取的对象；第一版列出来源和原因，可改选已支持的源对象或手动建模。
- 天正未加载时的代理对象，以及只剩图形而没有可验证语义参数的对象。

不支持项必须出现在统计和预览中；可保留底图，但不能算作已成功创建的建筑构件。普通线条推断为墙是后续 B05，并非本轮原生识别成功的证明。

## 4. 数据读取和坐标规则

### 4.1 只读适配器

在 CAD 侧建立 `TianzhengBuildingObjectReader`（建议名称，尚未实现），按实际验证的对象类型和版本提供墙/洞口适配器：

1. 先读取 RXClass/DXF、托管类型、COM ObjectName，分类为墙、洞口、轴网、辅助对象或不支持。
2. 用已验证曲线接口和只读属性白名单读取；未知方法不自动调用。缺失字段分别记录，不吞掉异常后生成默认值。
3. 保存原始数值、属性名、单位、读取状态和适配器版本，再生成归一化候选。
4. 用图面和已知尺寸交叉核对；对象 Scale 可能是注释/制图比例，不能直接作为建筑几何缩放倍率。
5. 输出纯数据快照。后台不持有 `Entity/ObjectId/Transaction/AcadObject`，不调用 CAD/COM。

源对象不炸开、不 TRIM、不移位、不删除。若后续需要辅助轮廓，只使用不会写回源图的临时数据，明确标记推断。

### 4.2 墙参数

必须获得：源身份、基线起终点、方向、总厚、左/右厚度、目标楼层、墙高及墙底相对标高。材质和墙类型可作为扩展字段，未验证时不强行映射。

以基线起点到终点为正方向，左侧法向与现有 `WallReferenceGeometry` 一致。在验证天正左右宽度方向且两值非负后：

```
Thickness = LeftWidth + RightWidth
AxisOffset = (LeftWidth - RightWidth) / 2
```

例如左 20、右 100：总厚 120，实体中心相对基线偏移 -40 mm，不是居中 120 mm 墙。端点反向时左右数据和偏移符号须一致转换。

- 不把不同墙厚共线段擅自合并；天正因门窗/相接拆出的段保留来源关系。
- 几何融合继续使用现有墙交接服务。导入、移动、删除、重新登记后都走同一重算，不从选中高亮网格反推墙形。
- 墙高读取不到时，可由用户明确选择“随层高”或批量填写；保留来源，不能显示成“天正原值”。
- 墙底非楼层标高时，先支持独立 `BaseOffset` 并联动平立剖/体量；未完成前该墙阻止自动转换。

### 4.3 门窗与宿主

用户于2026-09-30确定：CAD 天正侧只需要识别洞口宽高和编号，门窗具体样式与细部参数使用插件现有“门窗立面（MCLM）”参数。不再以读取原生天正门窗分格、框料、开启或镜像为导入前置条件。

数据分两层：CAD 实例提供来源身份、洞口宽高及编号，并适配其空间位置和所属墙以正确开洞；按编号关联当前项目的门窗立面类型库，提供门/窗类别、分格、开启、框料、安装缝等做法。窗台/底高由可读实例值或项目参数预填，缺失时用户确认，不能静默置零。

按 2026-09-30 用户确认的流程：框选读取门窗编号并关联当前项目门窗表、门窗立面。编号原生读取尚待适配，不用附近任意文字、图层或句柄猜编号；有可靠对象关联的标注可作为后续备选，否则显示待确认。洞口实例宽高以 CAD 为准，造型与分格使用选定立面做法。窗底离地高度优先使用本登记楼层门窗表记录，其次使用项目通用门窗表，最后使用用户明确选择的立面已保存参数；“—”、缺失、非有限数或同编号不一致不回落为默认 900。分楼层表存在时必须先绑定楼层，不能将另一层的高度拿来使用。

离地高度定义为本层楼板基准面至窗底；窗底模型标高 = 本层楼板标高 + 离地高度。不能叠加上一层标高或重复加层高。表中若实际按建筑完成面计量，应在核对中明确楼板基准与完成面的差值，不自动假定为同一基准。同编号允许有逐层高度差异，作为实例参数保存，不修改共用立面类型。

复用已有 `BuildingModelCadBridge.ExportOpeningLibrary`、`DoorWindowElevationPreference` 和 `OpeningElevationAdapter`，最终继续调用 `DoorWindowElevationGeometryBuilder`，不再实现另一套立面画法。现有适配器已支持“模型洞口尺寸＋类型库做法”；正式登记需将它与 CAD 识别结果接通。

- 原生宿主关联可读时优先使用；不可读时按同楼层、方向、墙面带、基线投影和洞口跨度筛选墙。
- 按洞口中心在墙基线上的投影计算 `Offset`，不是沿任意包围框取距离。
- 多个宿主候选、洞口跨两道墙、墙段被拆分时进入人工确认，不采用“离得最近就一定正确”。
- 同编号的每樘门窗独立创建实例；编号用于类型匹配，不能当实例 ID。
- 编号优先读取已验证的原生属性；不可读时可适配相关编号标注或人工匹配。当前 P0 的 `Code/Number` 候选在实测洞口上不可读，不能宣称编号已识别成功，也不能把实体 Handle 当编号。
- 编号匹配不到类型库时显示“未匹配做法”，保留洞口并允许用户选择现有类型；不能默认猜成窗。一个编号对应多条不一致项目参数时列出候选让用户确认，不沿用当前导出器“最后一条覆盖”的方式作为登记规则。
- 门窗表补值展示原生值/表格值/用户值；冲突先确认，不能让类型表覆盖可信实例参数。
- 洞口宽高以 CAD 读取值为初始值；类型库中的宽高与其不一致时展示差异，由用户选择使用洞口尺寸或项目尺寸。确认后同一尺寸同时驱动三维开洞、平立剖及门窗立面，不让样式套用改变已确认的洞口。
- 明确窗台高是相对楼层还是绝对标高，只转换一次。检查洞口越界、重叠、超墙高及墙交接附近的开洞结果。
- 开启与细部按匹配的门窗立面参数生成；不承诺复制原生天正实例的左右开启/镜像。需要实例单独调整时再扩展对应编辑功能，不根据宽度猜测。

### 4.4 每层定位与轴网

每个平面登记保存独立的 CAD→建筑变换：源 WCS/UCS、单位、基准点、方向、变换及逆变换。不要按每层包围框自动居中，否则层间墙和轴网不能重合。

- 用户选择同一个建筑轴线交点作为基点，再以第二个交点确定方向；用已知距离复核单位。
- 第一次登记确立唯一的模型对准基点（可设建筑坐标 0,0）及建筑方向；后续每层在各自 CAD 平面选择同一建筑位置对应的源基点，映射到这个模型基点。界面显示“源 CAD 基点 → 模型基点”、方向、单位及楼层，不能各层自动居中。
- 采用 `模型XY = 模型基点 + 单位倍率 × 旋转(CAD WCS XY − 该层源基点)`；保存逆变换以支持核对及回 CAD。旋转平面通过第二个方向点校正，源 UCS 先转换到 WCS；源平面 Z 不充当楼层标高。
- 每层首次绑定时以第二个轴交点复核方向和距离，叠加上一登记层预览。缺基点、方向点重合、单位未确认或误差超允许范围时阻止正式登记；同层后续局部登记默认复用该层定位，不再次随意设置原点。
- 源平面 Z 和建筑楼层标高分别保存。平铺的 2D 平面不因 CAD 的 Z=0 都进入首层，也不重复叠加楼层标高。
- 水平/竖直轴线转换为共用轴网；跨楼层重合的轴线按几何与两端轴号合并，轴号不同先提示冲突。
- 轴线可无限或超出选取范围，不能按图框裁剪范围直接截断成错误定位线。
- 斜轴网需先扩展 `AxisModel` 及显示/捕捉/编号/出图；第一版保留待适配，不强制转水平轴。

## 5. 楼层登记

楼层采用用户明确的上下顺序，不能按字符串排序；复用 `StoreyElevationLayout`。

```
上层标高 = 下层标高 + 下层层高
地下下一层标高 = 地下上一层标高 - 下一层层高
```

只需一个基准标高及各层层高。例如 1F=0、1F 层高 3600、2F 层高 3300、B1 层高 4200，则 2F=3600、3F=6900、B1=-4200 mm。

- 提供地上/地下层、名称、层高、自动标高、平面来源和标准层来源列表。
- 第一版以现有模型结构标高为基准；建筑完成面若不同须另记录，不混用。
- 天正或楼梯项目中能验证同义的层高可预填，但由用户确认；对象名、楼层文字和几何 Z 仅作为提示。
- 一层可对应多个登记区域；一个源平面可作为多个标准层的模板，复用 `TemplateStoreyId`，避免为同一模板重复创建构件。
- 楼层列表显示“未登记 / 待核对 / 已登记 / 引用标准层”。标准层选择来源平面和具体引用楼层；引用层共享 XY 对齐和构件模板，使用各自计算出的标高、层高和经确认的逐层离地高度。现有模板不支持逐层洞口差异时，先转独立层，不能静默改全部楼层。
- 引用层已有独立构件时不覆盖；标准层的单层差异先转独立楼层再登记。任意局部覆盖属于后续模型能力，不在本轮假定已支持。
- 楼层变动显示受影响墙高、窗台、楼板及图纸；提交后重新校验，整笔可撤销。

## 6. 文件协议与导入事务

新增版本化 `CadPlanRegistrationDocument`，不要直接往现有简单 `import.json` 塞入未声明的建筑语义。旧 TQTZ 文件仍可读作底图，新格式有独立 SchemaVersion 与迁移规则。

建议契约（名称是计划，非现有类）：

| 数据 | 主要字段 |
| --- | --- |
| `PlanRegistration` | 登记 ID、项目/模型 ID、目标楼层、源 DWG 身份、选取方式/范围、时间、版本、坐标变换 |
| `SourceEntityRef` | 源文档身份、Handle、块/外参实例路径、对象类型、参数/几何摘要 |
| `NativeWallCandidate` | 原始基线、左右宽、墙高/墙底、归一化参数、每字段来源和读取状态 |
| `NativeOpeningCandidate` | 类别、位置、尺寸/窗台、编号/方向、源宿主、候选宿主和确认状态 |
| `FieldValue` | 原始值、归一化值、用户覆盖、单位、状态：原生读取/类型补充/几何推断/人工填写/缺失 |
| `ElementSourceMap` | 一个或多个源引用↔模型构件 ID、上次源参数、上次模型参数、用户覆盖、忽略/删除状态 |
| `ImportReceipt` | 登记批次、模型前后修订、墙门窗/轴网数量、跳过/失败原因及源→模型映射 |

Handle 只在源文档内有意义；DWG 路径和 Fingerprint 作为身份线索并配合登记 ID，另存/复制图纸遇到身份歧义时确认重新绑定。嵌套引用要有实例路径，同一个块定义在不同位置不能去重成一个对象。

来源映射与用户覆盖必须随模型原子保存、进入撤销快照；若分文件存储，需要同一批次提交机制，不能出现模型保存成功而映射丢失。

提交步骤：

1. 基于目标模型修订和登记快照创建候选；先生成墙，再绑定洞口和轴网。
2. 全量校验有效几何、尺寸、宿主、楼层及 ID；用户可排除异常项，重新确认最终数量。
3. 通过新批量导入命令一次提交，产生一笔 Ctrl+Z；失败/取消保持模型、映射和历史不变。
4. 生成几何并显示核对结果；成功落盘后写回执。后台结果提交前检查模型修订，模型已改则丢弃过期结果。

重复登记从第一批可用版本就按来源去重。后续完整更新采用“上次源值/当前源值/当前模型值”比较：源单改可预览更新，模型单改保留，两边都改必须选择；源删除也要预览，不能静默连带删除用户新增洞口。模型中人工删除的导入墙需保留忽略记录，下一次扫描不能自动复活。

## 7. 界面与效率

CAD 侧使用项目现有 WPF 窗口负责选图与只读核验；建筑模型侧继续 Avalonia，不能为了登记把独立编辑器绑到 Windows。

- 入口整合到 JZMX“CAD 平面登记”；TQTZ 保留原有底图导出行为。新命令别名实现时先检查冲突，不复用 LTTZ。
- CAD 登记窗口：楼层映射、选取范围、定位基准、扫描结果、异常列表与导入按钮；需要 CAD 点选时隐藏窗口，完成后返回原步骤。
- 模型导入窗口：左侧锁定底图和候选高亮，右侧参数表；支持勾选、类型/异常筛选、批量填墙高/窗台高、恢复原值。待处理与已通过数量明确显示。
- 模型操作不改变相机；导入后提供一次“查看导入范围”，不在每次改参数或删除后自动缩放。
- 复用现有图框登记、门窗类型/做法和楼层设置；只提示缺失值，不要求重填已有项目参数。

性能实现要求：

- CAD 对象读取留在允许的文档/事务上下文；按批读取、及时释放事务、进度和取消在合法执行边界处理，不把整栋扫描塞进持续持锁的模态事件。
- 范围预筛后才读取 COM；对象类型与属性能力按版本缓存，每个对象的值只读一次，不边刷新表格边重新扫描。
- 纯数据转换、宿主空间索引、校验和网格构建后台执行；检查取消、窗口关闭、项目切换及修订变化。
- 列表虚拟化，预览高亮不重建全模型；批量确认只生成一次网格。
- 使用固定样例记录 CAD 快照耗时、转换/校验耗时、首次预览耗时、UI 响应、内存；测试 100/1000/10000 构件。暂以取消响应与界面事件响应 P95≤200 ms 为目标，真实 CAD 调用长耗时另外记录，不把目标写成已达成结果。

实施顺序为 P0→P1→P2→P3→P4。P0 前可先完成协议与纯数据测试骨架，但没有真实字段证据不得启用对应自动转换。

P2 首个可测试版本必须含参数核对、来源去重和撤销，不先交付“能显示模型、但位置/尺寸无法核对”的半成品。P4 完成前只允许新增或重登无差异来源，已存在且发生变化的对象必须明确提示更新功能尚未开放，不能自动覆盖。

## 9. 验收矩阵

| 场景 | 必须核对 |
| --- | --- |
| 200 mm 居中墙、120 mm 左20/右100墙、反向墙、短门垛、斜墙 | 基线、左右面、长度、厚度；不能取包围框中线或丢短墙 |
| L/T 接、多墙接、异高墙、门窗贴墙角 | 平面和三维接缝无缺角/重面，洞口有效；移动删除后重新收口 |
| 同编号多樘窗、旋转门、镜像门、无宿主与多宿主洞口 | 实例独立、方向正确、宿主可确认；缺高/窗台不伪造原值 |
| 同 DWG 多层平铺、大坐标、旋转 UCS、非毫米源图 | 楼层间共用定位，已知尺寸与轴交点一致；逆变换回 CAD 不漂移 |
| B2/B1/1F/2F、层高变动、标准层引用 | 单基准标高推算、负标高、模板实例和来源映射一致 |
| 框边穿墙、穿洞口、重复选区、块/外参/代理对象 | 默认保留完整候选并提示跨界，不自动裁短墙/洞口；去重正确；不支持项可见 |
| 一批导入、取消、失败、撤销/重做、保存重开 | 模型和来源映射同进退，一次撤销恢复，ID 不变 |
| 重登不变、源单改、模型单改、两边改、源删/模型删 | 无重复和静默覆盖；冲突可预览，人工删除不复活 |
| 天正版本差异、未加载、属性异常 | 只降级有问题对象；不将整张图误报成功；报告环境及缺字段 |
| 100/1000/10000 构件、多次改参数和重复核验 | 记录分段耗时、响应和内存；不重复全图扫描，取消能响应 |

自动化验证用真实读取的纯数据样例加人工计算金样；CAD 2022 + 天正实机另验，不能用脱离 CAD 的测试宣称原生读取可用。识别前后比较源实体参数、数量及 DWG 修改状态，确认读取没有写源图。
