# 云同步数据保护修复记录

2026-09-05

## 本轮已实现

- 有基线且双方内容变化时保留冲突，不再由时间戳决定覆盖。
- 本地缺失不传播删除；百度缓存清理不删除云端文件。
- 已有且不同的本地文件不自动应用待下载副本，由正常同步重新比较。
- 系统包遇到不同的现有配置，保留本机与 `.cloud-conflict-*` 云端副本；这些副本不参与同步。
- 本机命名互斥锁覆盖网络准备、文件处理及上传整个工作流。
- 每次上传前重新读取云端条目，版本不同即停止上传。
- 百度内部缓存不再注册监视器；请求同步后保留五分钟周期补扫，覆盖同步期间忽略的外部保存事件。

## 验证

45 项隔离云同步测试通过，包括目录移走后云端保留、待应用期间再次保存、双方时间不同时仍保留冲突。
未对用户网盘执行真实同步，也未进行两台真实电脑并发验证。

## 尚未完成的安全设计

1. 云端复查与上传不是原子操作。需要版本化不可变文件和有并发控制的清单提交，才能彻底解决跨电脑竞争。
2. 系统包当前保守保留冲突，未实现逐文件共同基线、合并界面及整包事务恢复。
3. 首次连接没有共同基线时仍沿用初始同步策略及时间规则；需要进一步将不确定版本交给冲突处理。
4. 手动同步与百度缓存传输的统计仍需统一；引擎下载计数不能代表实际网络下载次数。
5. 失败回滚目前主要恢复状态记录，不构成整轮远端和本地文件事务。

本版本属于保护性修复，不代表云同步已经完成数据安全验收。云端自动删除现阶段关闭，历史文件会增加，后续需提供独立的显式清理流程。
