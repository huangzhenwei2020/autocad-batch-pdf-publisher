| 项目 | 现在的处理 |
| --- | --- |
| 跨电脑竞争 | 百度直连及通用同步目录均发布 SHA256 命名的不可变 ZIP。逐文件记录父版本，没有抢写共享 HEAD；同文件并发留下分支。 |

## 协议与边界

- 新云目录：`万落安全同步V2`。校验包 SHA256、文件哈希、父版本完整性后才应用。
- 同一内容地址代表相同包；不同提交使用不同路径。并发不同文件可合并，同文件保留全部分支。
- 显式解决冲突只涵盖当时看到的父版本；旧冲突列表过期时拒绝提交，后到分支仍保留冲突。
- 已打开 DWG 延后处理；旧待应用副本不能初始化另一范围的新文件，也不能覆盖不同内容的当前文件。
- 缓存按提供商及账号/目录身份隔离；本机缺失和缓存清理不传播云端删除。
- 旧云文件和 V2 历史包均不自动删除。事务备份位于本机 `.cloud-sync/transactions`；遇到后续保存产生 `需要人工核对.txt` 和恢复提示。
- 本机恢复是**可恢复事务**，不是多文件瞬间可见的数据库事务。若云端已提交但回执丢失，不删除已发布版本；下一轮重新核对。
- 原子替换失败不退回截断原文件复制。路径穿越、ADS 和目录链接不作为写入目标；损坏包或未到齐父版本失败关闭。

## 验证

58 项隔离测试通过，包括并发分支、不同文件合并、后到分支保留、缺失父版本、损坏包、路径越界、文件和状态回滚、日志重放、保留后续保存、首次连接不按时间覆盖。

两设备完整工作流测试验证了同步收敛、连续三轮无变化不生成新包、取消恢复后重试成功。百度提供商模拟 HTTP 测试验证损坏下载检测、网络计数及同包不重复下载。

正式 R24 构建另执行 LineVision 17 项、楼梯 86 项测试。
没有操作用户真实网盘，也没有宣称完成两台物理电脑和百度生产环境的联调验收。

## 升级与回退

1. 所有参与同步的电脑一起升级，保留各自项目备份。
2. 不与旧客户端混用：旧客户端不认识 V2，旧云目录后续修改不会成为 V2 新提交。
3. 首轮配置冲突需要选择保留内容，不能假定某电脑时间准确。
4. 出现恢复提示，先核对日志和事务备份，不手动清空缓存。
5. 程序可从 `975760d` 重新构建回退，但应先停用同步；旧版无法读取 V2，不能用旧同步回退数据。
6. 历史包及事务备份会增加空间占用。当前不自动清理不可变版本，以免破坏父版本链；正式使用前仍需在独立测试项目进行两台实际电脑验收。
